# MyGO 第一集：Grounding DINO 分辨率稳定性实验

状态：完成。2026-10-16 建档，2026-10-17 完成报告。六张原图 × 四档分辨率 × 三次测量，共 72 次正式推理，另有 2 次预热；全部使用本机 Apple GPU / MPS。

**结论：这六张样本中，480p、720p 的人物框与 1080p 高度一致；360p 的主要人物框也接近，但出现了重复框，不能保证原始输出集合完全相同。** 所有分辨率的模型输入均被默认处理器缩放到 1333×750，实测耗时接近，没有随着源图变小而显著下降。

## 2. 比较方法

以**本轮 1080p 模型预测**作为参考，不是真值标注。将框坐标除以对应图宽和图高，统一到 0–1 坐标系。同一原图、同一类别内，按 IoU 从大到小贪心一对一匹配，最低 IoU 为 0.5。未匹配参考框和额外输出框分别记录。

- IoU 是两个框的交集面积除以并集面积；1 表示完全重合。这是预测一致性指标，不是准确率。
- 中心偏移为 `100 × max(abs(Δx/W), abs(Δy/H))`，单位是画面宽或高的百分点；面积变化是相对 1080p 框面积的变化百分比。
- IoU、偏移、面积变化只统计成功匹配的框；额外框不能因此被忽略。
- 检测框用于比较的是每张图第一次正式推理输出；三次推理均用于计时。没有给这些图标注真实框，不报告标准 AP / precision / recall。
- 可见人数及重复框核对由助手目视完成，不是人工专家标注。

### 3.1 360p 的三个额外人物框

两位助手独立目视复核结果一致：

1. **06:30 教室**，图中 #18 与 #1 是右后方同一个长发背景人物的重复框。#18 分数 0.358474，框 `[453.38,44.00,503.09,164.20]`；#1 分数 0.504158，框 `[453.56,44.01,502.89,114.37]`。
2. **06:30 教室**，图中 #19 补检了中央偏上、被前景人物遮挡的棕发人物，分数 0.350763，框 `[292.61,38.98,321.95,100.52]`。1080p 没有输出此人的框。因此 360p 的 8 框对应 7 个可见人物和 1 个重复框，不能将所有额外框称为误检。
3. **11:00 单人近景**，图中 #1 和 #3 框住同一个主体：#1 更宽，包含更多右侧长发，分数 0.369475；#3 分数 0.362569。这里出现 2 框不代表有 2 人。

### 3.2 如果只取最高分人物框，差异会被放大

11:00 的 1080p 单框占画面 51.23%；360p 中与之最接近的框占 51.52%，但**最高分框**占 67.73%。若系统直接取每图最高分 `person`，360p 的人物框占比会相对增加约 32.20%，横向中心移动 7.8821 个百分点。

因此，上表“匹配框接近”不等于“下游无论怎样挑框都稳定”。本次保留了全部原始输出，没有试调 NMS 或阈值；是否增加去重，需要同时防止误删真实重叠人物。近景例子也说明变化不限于极小目标。

## 5. 性能解释与适用范围

本轮时延包含已加载 PIL 图片的预处理、设备传输、模型前向、GPU 同步和后处理；不包含模型加载、Python 导入、图片读取、视频解码和绘图保存。各档均 18 次正式测量，模型加载约 2.02 秒，预热约 1.54 秒和 0.45 秒。

**四档实际模型输入全部为 1333×750，所以计算量没有随源图像素数同比下降。** 低分辨率图被放大后，张量尺寸恢复了，但丢失的图像细节没有恢复。0.68–0.72 秒的差别不足以证明某档更快；这不是严谨的性能上限测量。若要降低推理成本，需要另测处理器目标尺寸，本次没有改变这个变量。

本轮支持的判断：480p / 720p 可以作为后续人物构图提取的候选输入规格；360p 的匹配框总体接近，但额外框会影响计数和选框策略。六张探索性样本不足以确定全库的最低可靠分辨率，也没有覆盖额外的压缩、噪声、模糊或裁剪。
