## 为什么 event merge 没有减少重算

### 1. 至少 9 轮会先被声纹来源校验拒绝

具体锚点为 chunk6、丰川祥子、405200–406500ms。16:50:23.332，中文翻译从“跟我没关系”改为“我没有什么要和你谈的。”，人物、时间、日语原文和原始音频未变。当前 `_voiceprint_event_fingerprint()` 把全部 `text_variants` 纳入身份，纯翻译修改也使这条声纹参考失效，有效参考由 25 条变为 24 条。

`compare_speaker` 将参与候选比较的全部参考纳入 `used_references`。提交时先检查这些参考是否仍有效，然后才进行 event merge。因此正在使用旧 25 条参考的窗口，即使 timeline 修改本身可以合并，也无法通过前面的声纹依赖检查。

对 54 个调用时间、32 条刷新日志、参考快照变化和代码执行顺序逐一对齐后，至少 9 轮、9 个窗口满足上述拒绝的充分条件。这 9 轮的生成跨度累计 2084.416 秒，是并行累计口径，并非可直接节省的墙钟。原始捕获异常原因没有记录，所以这里是持久化证据加执行顺序所得的分类，不是假称恢复了异常堆栈；修复声纹校验也不保证这些轮次随后不会遇到其他合并冲突。详见 [trace-evidence.json](trace-evidence.json)。

该声纹依赖检查原本已经存在，本次 event merge 没有新增它。v5 终态 25 条参考均有效；v7 的不同模型产出触发了这一过宽的失效条件。

### 2. 现实现按完整 event 合并，实际热点会重复改同一个 event

当前只自动保留不同 event 的独立修改。同一个 event 中“改 speaker”和“改中文翻译”仍按整条 event 判冲突；persons 整个列表也是原子值。双方发生时间、类型、顺序或拆分合并变化而无法可靠对齐时也会拒绝。

本轮可见热点为 chunk4 的 293800–296000ms 台词“長崎そよちゃんと…”。相邻 seq3、seq2、seq4 的执行时间重叠，成功提交分别修改了该 event 的 speaker/描述、中文翻译，以及描述/声音分数。说明实际修改确实集中在同一句，但未保存的丢弃草稿不能从成功产出反推，因此不能把其余 23 次刷新全部归为这个原因。

终态 22 个窗口审计中，可确认受益于放宽旧快照检查的只有 seq8、seq18 两例：别的窗口修改了其读取的 member，该窗口自己未修改该 member，故保留 Current 后成功提交。没有足够观测证据确认同一 chunk 内不同 event 真正发生三方合并。审计见 [merge-audit.json](3b9bb6d7-8f2c-4ce3-bb6f-2a2a0aa8228b/merge-audit.json)。这两例证明功能路径生效，但不构成本次整集提速的证据。

### 3. 重算数量未降，同时单轮 Agent 执行变长

Refine 中位跨度增加约 6.0%，累计跨度增加 696.436 秒，末尾窗口又集中发生多轮刷新。CAM++ 次数和累计推理时间反而下降，不能把这次增长归因于本地声纹向量计算。现有跨度无法进一步精确拆分模型推理、截音、看帧及工具往返等待，各轮 Agent 输出本身也不同。

## Trace 的可恢复范围与下一步建议

本轮 54 个 Refine 模型 trace 都只有 request/completed 元数据，没有 Canvas 工具参数、结果或完整 Proposed，亦无可靠的 native thread/rollout 映射。无法恢复丢弃的草稿；剩余 23 次刷新不能可靠细分为同字段冲突、结构变化或其他检查失败。未扫描无关的本地会话。`trace-latency-report.md` 是 17:18:03 时刻的中途分析；整轮最终数字以本 README 和 latency-comparison.json 为准。

建议先做两个小范围修复，再评估是否需要改变并发策略：

1. 将声纹身份校验限定在真实来源、时间、speaker、原语音身份等相关信息；纯翻译编辑不应使原声音锚失效。保留人物纠正、音频区间改变等真正失效的保护，并核对旧指纹兼容。
2. 在已有提交失败路径记录结构化原因及冲突 event/字段标识，避免下次仍只有通用 snapshot changed。无需保存整段音频或完整模型草稿。

之后根据实际剩余冲突选择同 event 内的字段合并，或限制共享写入 chunk 的 Refine 同时运行。单纯增加并发可能使重复修改更频繁，当前没有提速证据。此次只完成追踪与实验记录，没有继续修改生产逻辑、配置或再次启动解析。
