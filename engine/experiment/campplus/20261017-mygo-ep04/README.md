# CAM++：MyGO EP04 声纹可用性实验

日期：2026-10-17。状态：已完成真实 CPU 推理；本轮只新增本实验目录。

**结论：在本集固定的四人、24 段参考样本中，CAM++ 有实用的声音区分能力；B12 目标短句也与爽世参考最接近。混合长段会匹配占时长较多的发言人，单个余弦阈值不能可靠解决归属。** 这支持继续接入声音证据工具，尚不等于生产 VoiceprintAgent／Refine 已实现，也不是整部作品识别准确率的验收。

## 官方模型与最小推理路径

- checkpoint：`iic/speech_campplus_sv_zh-cn_16k-common`，revision `v1.0.0`，`campplus_cn_common.bin`，实际 **28,036,335 字节**（26.74 MiB），SHA-256 `3388cf5fd3493c9ac9c69851d8e7a8badcfb4f3dc631020c4961371646d5ada8`。
- 官方实现固定为 [3D-Speaker commit 065629c](https://github.com/modelscope/3D-Speaker/tree/065629c313eaf1a01c65c640c46d77e61e9607b4)。直接导入官方 `CAMPPlus(feat_dim=80, embedding_size=192)` 与 `FBank(80, sample_rate=16000, mean_nor=True)`；6,848,544 参数，严格加载权重成功，没有复制网络代码，没有训练。
- 模型结构、权重名称、192 维配置、特征及余弦口径依据 [官方 infer_sv.py](https://github.com/modelscope/3D-Speaker/blob/065629c313eaf1a01c65c640c46d77e61e9607b4/speakerlab/bin/infer_sv.py)；FBank 直接使用 [官方 processor.py](https://github.com/modelscope/3D-Speaker/blob/065629c313eaf1a01c65c640c46d77e61e9607b4/speakerlab/process/processor.py)。
- 实测环境：Python 3.12.13，macOS 26.4.1 ARM64，PyTorch／torchaudio 2.8.0，NumPy 2.2.6，SciPy 1.15.3，PyYAML 6.0.3。机器 Apple M5 Pro／48 GB 由用户环境及已有硬件记录提供；本轮未重新采集硬件信息。
- CPU／FP32／batch=1，intra-op=6、interop=1；没有测试 MPS，也没有使用 CUDA。
- 必需的直接 Python 包为 `torch, torchaudio, numpy, scipy, pyyaml`。SciPy／PyYAML 由官方 FBank 的模块导入链需要；不使用其训练增强功能。完整锁定版本见 [requirements.txt](./requirements.txt)。
- `modelscope` 仅为官方 CLI 的下载逻辑所需；本实验直接从官方 revision URL 下载并校验 checkpoint，不需要安装。已去掉初次试装但未使用的 `kaldiio`，再在独立进程完整复跑通过。也无需 soundfile、sklearn 或上游旧版 NumPy 约束。这里只确认本环境的最小可运行组合，不声称全版本兼容。

音频处理为 ffmpeg 8.1.1 精确 seek → 取原音轨首声道（与官方推理脚本选第一声道一致）→ 16 kHz PCM16 → 标准化到 [-1,1) → 官方 FBank、dither=0、逐频带减均值 → CAM++ → L2 归一化。没有 VAD、降噪、人声分离或时长补齐。多参考比较对归一化向量取均值后再次归一化，以 cosine 排序；完整结果同时保留每条参考的 pair 分数。

每段只在 TemporaryDirectory 中生成 WAV，读取后立即删除，异常退出也由上下文清理。未长期保存音频或临时 URI，仅保存时间、音频哈希、质量信息与向量。视频未上传外部服务。

## 声音区分结果

| 固定评测方式 | 参考 | 留出探针 | 正确匹配原标签 |
| --- | --- | ---: | ---: |
| 单参考 | 每人按时间最早 1 条 | 其余每人 5 条 | **20/20** |
| 双参考 | 每人按时间最早 2 条的质心 | 其余每人 4 条 | **16/16** |
| Leave-one-out | 每个探针仅用该人物另外 5 条；其他人物各 6 条 | 24 | **24/24** |

均为四个已知人物之间的 closed-set 排名，允许的候选始终包含正确人物，且没有拒识阈值。前两项是按时间固定的参考／探针拆分；第三项复用了样本做不同轮次的参考，不能当独立验证集。没有将同一个向量、重叠音频或重复记录当成自身参考，也没有把 target 的用户标签加入参考。这里的 100% 仅表示这些样本的排序结果，不能外推到未知人物、null 台词全集、其他集数或其他作品。

| 独立参考 pair | 数量 | 最小 cosine | 中位 cosine | 最大 cosine |
| --- | ---: | ---: | ---: | ---: |
| 同人 | 60 | 0.4199 | 0.6912 | 0.8555 |
| 异人 | 216 | 0.1131 | 0.3925 | 0.7209 |

探索性 pairwise AUC 为 **0.9726**；pair 共享原始片段且来自同一集，统计相关，不报告独立置信区间。对角线没有计入指标；[相似度矩阵](./cpu/similarity.svg) 中对角线仅用于展示，SVG 单元格 title 可查看分数。

**同人与异人分数显著重叠，没有可把这批 pair 完美分开的统一阈值。** 同人低分例为 `taki4/taki5=0.4199`；异人高分例为 `soyo1/anon1=0.7209`、`tomori5/taki6=0.6803`。这说明即便整体排名很好，单参考“超过 0.7 就确认身份”仍会误判。没有按这批测试结果反调生产阈值。

## B12 目标与边界实验

下表为每人参考质心的 cosine；差值为第一名减第二名。分数均不是概率。

| 参考策略 | 样本 | 第一候选 | 第二候选 | 差值 |
| --- | --- | --- | --- | ---: |
| 全部参考 | `target` | 长崎爽世 0.7849 | 高松灯 0.5364 | 0.2485 |
| 全部参考 | `boundary` | 长崎爽世 0.8047 | 高松灯 0.5509 | 0.2538 |
| 全部参考 | `mixed` | 千早爱音 0.9117 | 高松灯 0.6388 | 0.2729 |
| 仅 ≥5 分钟参考 | `target` | 长崎爽世 0.7472 | 高松灯 0.5419 | 0.2053 |
| 仅 ≥5 分钟参考 | `boundary` | 长崎爽世 0.7713 | 高松灯 0.5449 | 0.2264 |
| 仅 ≥5 分钟参考 | `mixed` | 千早爱音 0.9008 | 高松灯 0.6368 | 0.2640 |

目标使用全部参考时，各人物质心分数为：爽世 0.7849、灯 0.5364、爱音 0.4367、立希 0.4132。目标对六段爽世单参考的分数为 0.7826、0.7049、0.7312、0.7133、0.5439、0.6068；最强异人单参考为 `anon1=0.5808`。可见个别同人参考仍低于个别异人参考，多参考与候选差异有实际价值。

只使用 ≥300000 ms 的较远台词，排除了紧接目标且文字相近的 `soyo1`，也排除了开头其他人物的参考，爽世仍排名第一，差值 0.2053。该实验提供了与用户纠正一致的音色证据；不是系统已经通过 Refine 写回爽世的验收。

宽边界 `boundary` 仍匹配爽世，但这是同一语音的变体，不算额外正确识别一次。混合段 `mixed` 的第一名则为爱音 0.9117，爽世只有 0.5761，**第一／二候选差值更大也不能揭示该片段内有换人**。此现象说明应允许在授权来源内取准确的子时间段，不能对混合 ASR 长段取一个向量后，把整段内每句都归给最相近的人。

## 性能与复现验证

每个样本真实推理 3 次，首次样本另预热 1 次，共 82 次前向；27 个样本含 109.6 秒音频（压力测试有内容重叠）。计时包含从已在内存的波形生成 FBank、模型前向、取出 embedding，排除 ffmpeg、模型加载、导入和文件哈希。

| 指标 | 本轮实测 |
| --- | ---: |
| 24 条参考，72 次提取中位数 | **27.06 ms/段** |
| 24 条参考，提取范围 | 19.77–53.01 ms |
| 全 27 条，81 次正式提取中位数 | 26.71 ms/段 |
| 全 27 条，含 13.5 秒混合段的范围 | 19.44–76.46 ms |
| WAV 截取子进程中位数 | 62.23 ms/段 |
| 目标 1.7 秒短句提取中位数 | 19.66 ms |
| 24 条参考累计提取时间／累计音频时长 | 0.00765 |
| 模型构造与权重加载 | 0.196 秒 |
| 模块导入 | 首轮 37.30 秒，独立复核 2.29 秒 |
| 首段预热 | 44.04 ms |
| 进程峰值 RSS | 546,963,456 字节，约 521.62 MiB |

性能为当前桌面环境单进程测量，不是机器上限或整套解析的吞吐。首次导入开销显著，后续宿主宜按需加载并在进程内复用模型；不能只用热前向时间估计冷启动。

[validation.json](./validation.json) 记录以下检查：

- 27×192 向量全为有限值，L2 范数最大误差 1.2e-7；每个样本的 3 次前向向量完全一致。
- 去掉 `kaldiio` 后，独立 Python 进程再次处理全部 27 段：PCM 哈希、向量和全部评测／目标排名完全一致，embedding 最大绝对差为 0。
- 清单中的视频、checkpoint、上游 Git commit、全部源快照和原事件均已校验；上游工作树无修改。
- 临时音频目录无残留；相似度图 XML 合法；脚本通过 `python -m py_compile`。
- 验证记录含清单、脚本、依赖、结果、向量、图与日志的 SHA-256。

## 复现

在 AniVAG 根目录执行，网络只用于下载公开代码／依赖／权重。所有模型代码和 Python 依赖留在 `/tmp`，不修改项目主环境。下面复用已固定的输入文件；源视频与清单所指快照必须仍存在且哈希一致。上游源代码与权重不复制进本仓库。

```bash
EXP=engine/experiment/campplus/20261017-mygo-ep04
WORK=/tmp/anivag-campplus-reproduce
uv venv --python .venv/bin/python "$WORK/venv"
uv --cache-dir "$WORK/uv-cache" pip install --python "$WORK/venv/bin/python" -r "$EXP/requirements.txt"
git clone https://github.com/modelscope/3D-Speaker.git "$WORK/3D-Speaker"
git -C "$WORK/3D-Speaker" checkout 065629c313eaf1a01c65c640c46d77e61e9607b4
curl -fL 'https://www.modelscope.cn/models/iic/speech_campplus_sv_zh-cn_16k-common/resolve/v1.0.0/campplus_cn_common.bin' -o "$WORK/campplus_cn_common.bin"
"$WORK/venv/bin/python" "$EXP/run.py"   --upstream "$WORK/3D-Speaker"   --checkpoint "$WORK/campplus_cn_common.bin"   --output "$WORK/reproduced"
```

输出目录必须尚不存在，防止覆盖证据。首次实测使用 `/tmp/anivag-campplus-20261017`；复核输出保留在该临时目录的 `minimal-recheck`，其验证摘要已持久化到本目录。正式结果保存在 `cpu/`。
