## 1. 当前已确认的方向

1. **先定义用户希望匹配什么，再选择模型。** Query 同时涉及任务类型、特征维度、作用范围和时间结构，不能只按输入图片／视频来划分。
2. **构图检索当前以“构图类别相似”为主。** 两张图都属于对角、水平、居中、对称等构图即可具有较高相关性；人物具体位置、大小和线段位置可以参与排序，但默认权重较低。尚未确定具体数值权重。
3. **具体 Query 的显式条件仍要满足。** Q14 明确要求“人物在左、右侧留白”，Q15 明确要求“俯视、人物很小”时，不能把这些条件自动降为可忽略项。上述权重取向适用于一般的“构图类似”查询。
4. **PICD 是当前构图类别检索最直接的公开评测依据；没有随论文发布开箱即用的 PICD 24 类分类模型。** CADB 有配套的 SAMP-Net，但主要训练目标是构图质量评分。
5. **Grounding DINO 已在本机真实运行。** 它提供文字条件下的目标框，适合作为主体布局辅助；不直接输出摄影构图类别、主要线段、相机机位或场景分区。
6. **普通 VLM 能做构图解释和坐标估计，但稳定性需要评测。** 本轮助手的目视标注不能代表某个独立 VLM API 的批量效果；固定 JSON 也不能单独保证识别正确。
7. **当前没有完成构图检索效果评测或训练构图分类器。** 后续先用独立标注比较方案，再决定是否引入更多专用模型。

## 2. Query 的统一拆解

**Query = 任务类型＋特征条件＋作用 Scope＋时间结构，再附加模态、检索范围、允许变化项和排序条件。**

### 2.1 任务类型

| 任务类型 | 对应问题 | 成功标准 |
| --- | --- | --- |
| 找同源 | Q01–Q07、Q34 | 确认同一原始画面、连续片段或声音；视觉／语义相似只能召回候选 |
| 找同一实体 | Q08–Q10、Q32 | 确认同一角色、地点或物件，并满足服装、时间等附加条件 |
| 找特征相似 | Q11–Q25、Q28 | 匹配指定的构图、神态、姿态、动作、运镜、外观或表达 |
| 找事件与解释关联 | Q26、Q27、Q29–Q31 | 提供事件、关系变化、原因或呼应的上下文证据 |
| 找声音事件 | Q33、Q35 | 实际音频中存在相应发声、声音事件和变化顺序 |

“首次、全部、后来”是范围与排序条件；必须明确采用播放顺序还是故事时序。“找到一个合理候选”和“找全出现位置”需要不同的评测方式。

### 2.2 特征分类

| 特征类别 | 要表达什么 | 例子 |
| --- | --- | --- |
| 构图与视角 | 元素分布、主体占比、留白、前后景、遮挡、观察视角 | Q14 左人右留白；Q15 俯视小人物；Q16 隔窗拍两人 |
| 人物神态 | 脸、眼睛、嘴、头部等可见状态 | Q12 欲言又止；Q13 嫌弃脸；Q19 笑到哭 |
| 姿态与动作 | 身体姿势、运动方向、动作阶段与状态变化 | Q11 相似姿势；Q17 低头再抬眼；Q18 跳下 |
| 运镜 | 观察画面的方式随时间如何改变 | Q20 慢慢推近脸部 |
| 视觉外观 | 色彩、光线、纹理、服装、材质和画风 | Q10 服装；Q23 暖色逆光；Q25 色光衔接 |
| 内容语义 | 人物、物件、场景、事件、关系和含义 | Q24 雨夜霓虹；Q26 舍不得；Q27 和解；Q29 哭泣原因 |

这些特征允许叠加。Q16 同时包含“两个人和窗户”的语义与前后景、遮挡的构图条件；Q19 同时包含神态和连续变化。

神态与情绪需要分层：皱眉、含泪、嘴角下压是可见状态；犹豫、舍不得、孤独是结合动作、对白和上下文作出的解释。孤独可以由环境、光线或多人关系表达，不一定是一张悲伤的脸。

### 2.3 Scope 与时间结构

| Scope | 含义 | 例子 |
| --- | --- | --- |
| 主体 | 一个或多个角色、物件，或脸、手、服装等局部 | 姿势、神态、指定服装 |
| 背景／环境 | 房间、街道、天气、环境光线等 | 同一房间、雨夜 |
| 关系 | 主体之间、主体与背景之间的关系 | 隔窗、前后、遮挡、和解 |
| 整体画面 | 全局空间分布、色光和视觉效果 | 构图类别、留白、视觉衔接 |

主体由查询目标决定：找椅子时，椅子就是查询主体，即使它处在原镜头的背景里。主体裁剪图会丢失“人物相对整幅画面很小”等全局信息。

| 时间结构 | 需要保留的证据 |
| --- | --- |
| 单帧状态 | 某一刻的构图、神态、姿态、外观 |
| 单镜头连续变化 | 同一主体的动作阶段、状态变化、运动方向和先后顺序 |
| 相邻镜头组合 | 切镜边界、每个镜头内容、连续性、顺序与时长 |
| 跨场景／跨集关联 | 当前时间参照、历史出现、事件关系及上下文证据 |

静态俯视属于构图／视角；相机如何移动属于运镜；手部特写后切到脸部属于分镜组织。三者分别表示。

### 2.4 Q01–Q35 研究覆盖表

以下记录每条原始 Query 的重点，完整期望答案见[目标 Query Set](./multimodel-retrieve-trd.md)。本表不代表能力已实现。

| ID | 用户 Query | 解析与匹配重点 |
| --- | --- | --- |
| Q01 | 这个图片／表情包出自哪一集？ | 同源验证＋作品、集数、原视频时间索引 |
| Q02 | 只有某一集画面右下角这一小块，能找到完整原画面吗？ | 局部对应与几何核对，不能只看全图语义 |
| Q03 | 这张被裁剪、加字或贴了贴纸的表情包，原图是什么？ | 修改区域鲁棒性、局部原画面对齐 |
| Q04 | 这个画面最早出自哪一集？ | 同源匹配＋范围内首次排序；区分播放和故事时序 |
| Q05 | 这个画面在哪些集出现过，包括回忆和回顾？ | 穷尽范围内出现位置；重复使用与相似镜头分开 |
| Q06 | 这个 GIF 对应的完整连续片段在哪里？ | 多帧连续对齐、起止时间，不能只命中一帧 |
| Q07 | 这个混剪里的几个镜头分别来自哪里？ | 输入切镜、逐镜头同源定位，允许多个作品 |
| Q08 | 这张图里的角色还在哪些片段出现过？ | 角色实例身份，不能仅凭服装或发色 |
| Q09 | 这个房间／物件在其他集里出现过吗？ | 地点／物件实例一致，允许视角和光照变化 |
| Q10 | 找这个角色穿这套衣服的镜头。 | 身份与指定服装联合满足 |
| Q11 | 有没有其他角色也摆出这个姿势？ | 主体姿态相似，允许身份、服装、背景不同 |
| Q12 | 找类似这种欲言又止的表情。 | 可见神态；心理含义单独解释 |
| Q13 | 有没有同款嫌弃脸，换个人也可以？ | 神态与表达相似，弱化身份 |
| Q14 | 找人物站在画面左侧、右边大面积留白的镜头。 | 整图主体位置、尺度和留白 |
| Q15 | 有没有类似这种俯视、人物很小的画面？ | 静态机位＋主体相对整图占比 |
| Q16 | 找隔着窗户拍两个人的镜头。 | 人数、窗户、前后景、遮挡关系 |
| Q17 | 有没有先低头、再突然抬眼的片段？ | 同一主体、阶段变化、顺序和速度 |
| Q18 | 找类似这个从高处跳下来的动作。 | 动作阶段和方向；区分起跳、下落、落地 |
| Q19 | 有没有从笑逐渐变成哭的过程？ | 同一主体神态的连续演变 |
| Q20 | 有没有镜头慢慢推近人物脸部的片段？ | 相机运动与景别变化；排除只由主体靠近造成的变化 |
| Q21 | 找先拍握紧的手，再切到脸部特写的分镜。 | 两镜头内容、切换与相邻顺序 |
| Q22 | 有没有类似这种两人对话，最后切到空椅子的镜头组合？ | 完整连续镜头组合；不能拼接无关命中 |
| Q23 | 找类似这种暖色逆光的画面。 | 色调、光向、整体视觉效果 |
| Q24 | 有没有雨夜、霓虹灯倒映在地上的片段？ | 多语义条件＋照明与倒影证据 |
| Q25 | 找颜色和光线能跟这段接起来的镜头。 | 色光分布相近与剪辑衔接偏好 |
| Q26 | 有没有嘴上说不在乎，实际上舍不得的片段？ | 对白、行为、上下文与情绪推断 |
| Q27 | 找两个人终于和解的场景。 | 关系变化；同框或微笑不足以证明 |
| Q28 | 有没有同样表现孤独，但不一定是一个人站着的镜头？ | 情绪表达相似，允许不同人数、构图、情节 |
| Q29 | 她为什么在这里哭？ | 场景定位＋原因证据，不能仅看表情 |
| Q30 | 这张表情包前后发生了什么？ | 先同源定位，再扩读连续上下文 |
| Q31 | 这个镜头是不是在呼应前面某一集？ | 两处证据与关联理由，保留不确定性 |
| Q32 | 后来这个物件又出现了吗？ | 物件身份＋当前时间参照后的范围查询 |
| Q33 | 哪些片段角色“哈？”了一声？ | 实际音频、发声时间；字幕不能替代声音 |
| Q34 | 这个笑声出自哪里？ | 音频同源匹配与时间对齐 |
| Q35 | 有没有突然安静，然后爆发喊声的片段？ | 声音事件、能量变化、先后关系 |

TRD 中的 Q36–Q40 是组合用途：告别结尾、关门后的衔接、三秒无台词且右侧能放字、动作与构图同时相似、出处与表情原因。它们组合上述能力，不另设一个万能相似度。

## 3. 普通 VLM、embedding 与专项逻辑分别承担什么

不能把“当前模型尚未验证可靠”写成“普通 VLM 原理上做不了”。模型可以给语义、类别、候选位置；精确坐标、时间顺序、实例身份、范围穷尽和声音同源等目标仍需要明确表示、验证及查询逻辑。

| 能力 | 通用 VLM／embedding 可提供 | 额外需要验证或实现的部分 |
| --- | --- | --- |
| 粗构图类别 | 定向类别判断、图像特征、候选召回 | 固定标签体系、独立评测、跨内容和动漫泛化 |
| 精细布局 | 主体／关系描述、粗坐标 | 坐标规范、框或轮廓、几何计算、变长集合匹配 |
| 姿态与动作 | 姿势／动作描述、粗动作类别 | 关键点或时序特征的收益；主体跟踪、方向、阶段和顺序核验 |
| 运镜 | 视频描述和候选类别 | 排除主体运动；追踪／光流及运动解释的可靠性 |
| 外观 | 色彩、服装、光线、风格描述 | 颜色分布、区域属性及光向的专项评测，不预设全部需要新模型 |
| 同源／同一实体 | 相似候选召回 | 局部对应、身份核验、连续对齐、索引与去重 |
| 分镜与事件 | 单镜头内容、事件描述 | 切镜边界、相邻关系、时间约束、上下文证据 |
| 声音 | 带音频能力的模型可提供描述／识别 | 实际音频路径、事件检测、音频指纹、时间定位；视觉证据不足 |

“特殊逻辑”不一定是另一个神经网络。面积占比、时间先后、首次／全部查询和框匹配都可以由确定性代码完成；是否引入 pose、depth、flow、segmentation 等模型由漏例和评测决定。

## 4. VBench 能借鉴什么

VBench 主要评测生成视频的质量和指令遵循。可以借鉴“按维度选择组件、采样和聚合证据”的做法；其质量分数不能直接作为同源、身份或构图检索的相似度。

本地源码核查位置为 `../VBench`，Git HEAD 为 `fd18b3d055cb0fc6f066ca90fe2c3c8cbb698490`；本轮未修改或运行其模型。讨论中出现过的 `motor/VBench-EVAL` 没有在本次核查目录中找到，本文不把它当成已核验的当前路径。

### 4.1 原始 16 个维度及实现

| 维度 | 本地实现 | 与我们的任务的关系及限制 |
| --- | --- | --- |
| [subject_consistency](../../../VBench/vbench/subject_consistency.py) | 原始 DINO ViT-B/16 整帧特征；比较相邻帧及首帧的余弦相似度 | 时间稳定性；不等于同一角色身份，也不是人物框检测 |
| [background_consistency](../../../VBench/vbench/background_consistency.py) | CLIP 整帧特征；比较前帧和首帧 | 没有先分割背景；不证明是同一个房间 |
| [temporal_flickering](../../../VBench/vbench/temporal_flickering.py) | 相邻帧 RGB 绝对差均值，针对静态视频 | 像素闪烁；真实运动也会造成变化 |
| [motion_smoothness](../../../VBench/vbench/motion_smoothness.py) | AMT-S 用间隔帧预测中间帧，与真实中间帧比较误差 | 插帧可预测性／连续性；不输出动作类别或顺序 |
| [dynamic_degree](../../../VBench/vbench/dynamic_degree.py) | RAFT 光流；高运动幅值像素统计＋阈值 | 动态程度；不自动区分人物运动和运镜 |
| [aesthetic_quality](../../../VBench/vbench/aesthetic_quality.py) | CLIP ViT-L/14＋审美评分头，逐帧聚合 | 质量过滤；同分不代表构图相同 |
| [imaging_quality](../../../VBench/vbench/imaging_quality.py) | MUSIQ 的 SPAQ 权重，逐帧质量评分 | 画质过滤；不是摄影构图分类 |
| [object_class](../../../VBench/vbench/object_class.py) | GRiT 检测类别，统计目标出现的帧比例 | 类别存在；不确认实例身份 |
| [multiple_objects](../../../VBench/vbench/multiple_objects.py) | GRiT 类别集合是否同时包含目标类别 | 同时存在；不等于精确人数或人际关系 |
| [human_action](../../../VBench/vbench/human_action.py) | UMT ViT-L/16、Kinetics-400 动作类别；16 帧输入 | 粗动作类别；不保证 Q17–Q19 的细粒度过程 |
| [color](../../../VBench/vbench/color.py) | GRiT dense caption 的物体类别与颜色词匹配 | 物体颜色；不等于整体色光分布或逆光方向 |
| [spatial_relationship](../../../VBench/vbench/spatial_relationship.py) | GRiT 检测框＋中心距离／IoU 规则 | 可借用框和几何关系思路；没有摄影构图类别、留白或主线段 |
| [scene](../../../VBench/vbench/scene.py) | Tag2Text 描述与场景关键词匹配 | 场景语义；不证明地点实例相同 |
| [appearance_style](../../../VBench/vbench/appearance_style.py) | CLIP 图文匹配 | 粗风格语义；不是光照几何 |
| [temporal_style](../../../VBench/vbench/temporal_style.py) | ViCLIP 视频文本相似度 | 时序风格；不是严格事件顺序核验 |
| [overall_consistency](../../../VBench/vbench/overall_consistency.py) | ViCLIP 抽帧视频特征与整体 prompt 匹配 | 整体语义一致；不证明剧情因果或同源 |

源码补充：[组件选择与权重配置](../../../VBench/vbench/utils.py)、[原始维度清单](../../../VBench/README.md)。

需要保留的实现限制：当前本地 `spatial_relationship.py` 把 left/right、above/below 分组后使用绝对中心距离比较，没有用距离符号严格区分左右、上下。借鉴其思路时应重新验证方向规则，不能原样当成精确有向空间关系核验器。本轮只记录，没有修改上游。

### 4.2 与 Query 的映射

- **构图／机位：** 原始 16 维没有摄影构图分类；Q14–Q16 不能仅靠 `spatial_relationship` 覆盖。静态俯视不能用运镜类别替代。
- **同源与身份：** 一致性、物体类别和场景描述可作辅助，但 Q01–Q10 仍需要同源、实例身份与时间索引。
- **动作与变化：** UMT、RAFT、AMT 分别给动作类别、运动场、连续性信号；Q17–Q19 需要同一主体和阶段顺序。
- **外观：** CLIP、颜色词、MUSIQ 和审美头覆盖一部分特征；Q23–Q25 的光向与剪辑衔接仍需单独评价。
- **分镜／剧情：** 相邻镜头顺序、原因和呼应属于检索与证据组织，不能由整段一致性分数代替。
- **声音：** 原始 16 维不包含 Q33–Q35 所需的语音、笑声同源或声音事件顺序能力。

### 4.3 三条论文线

| 工作 | 研究重点 | 对本项目的帮助 |
| --- | --- | --- |
| [VBench，CVPR 2024](https://arxiv.org/abs/2311.17982) | 细粒度分层的视频生成质量评测 | 维度拆解、组件选择与聚合方法 |
| [VBench++](https://arxiv.org/abs/2411.13503) | I2V、长视频、Trustworthiness | 参考图一致性、长时间跨度与运镜等扩展 |
| [VBench-2.0](https://arxiv.org/abs/2503.21755) | Human Fidelity、Controllability、Creativity、Physics、Commonsense；18 个细维 | 动态属性、动作顺序等定向问答与验证设计 |

VBench++ 的 [camera_motion](../../../VBench/vbench2_beta_i2v/camera_motion.py) 使用 CoTracker 网格追踪，以边缘点的首尾位移作方向判断；它不等于完整 3D 相机恢复，也不能仅凭此可靠区分主体运动、真实推进和光学变焦。[长视频扩展](../../../VBench/vbench2_beta_long/README.md)先做场景切分，再处理片内和跨片的一致性。

**VBench-2.0 的 `Composition` 指创意概念／实体组合，不是摄影构图。** 例如“长有鹰翅膀的狮子”，通过视频 VLM 定向检查组合属性；不能把这一维度当成“对角、居中、水平”分类方案。证据：[任务数据](../../../VBench/VBench-2.0/vbench2/VBench2_full_info.json)、[实现](../../../VBench/VBench-2.0/vbench2/composition.py)。本轮核查上述方向和相关实现，没有完整审计／运行 2.0 的全部 18 个维度。

## 5. 视觉专项模型：输入、输出与职责

这些模型不都属于“小模型”，也不都属于多模态模型。许多只处理图像；其成本取决于具体权重、输入尺寸、中间特征、设备和实现。

| 模型／组件 | 输入 → 输出 | 学习目标／主要职责 | 对 AniVAG 的用途与边界 |
| --- | --- | --- | --- |
| [摄影构图 PCPNet 基线](https://www.sciencedirect.com/science/article/pii/S1047320318301147) | 图片 → 构图类别得分／标签 | 9 类摄影构图的多标签分类 | 任务最接近类别级构图检索；不是 PICD 发布的 24 类模型 |
| [SAMP-Net](https://github.com/bcmi/Image-Composition-Assessment-Dataset-CADB) | 图像与显著性信息 → 构图评分分布、平均分、辅助属性和模式权重 | 预测人工构图质量评价 | 可作质量排序或特征基线，模式权重不是构图类别概率 |
| [MUSIQ](https://github.com/google-research/google-research/tree/master/musiq) | 原图及多尺度表示 → 质量分数 | 技术画质／美学质量，由 checkpoint 决定 | 过滤或质量排序；不是直接的构图类别识别器 |
| [CLIP](https://github.com/openai/CLIP) | 图像／文本 → 可比较的特征向量 | 匹配图文对 | 语义召回与图搜图基线；不能默认对具体空间条件可靠 |
| [原始 DINO](https://arxiv.org/abs/2104.14294)／[DINOv2](https://github.com/facebookresearch/dinov2) | 图像 → 整图／patch 特征 | 自监督视觉表示 | 图像相似及下游任务特征；不会自动输出目标框或构图类别 |
| [Grounding DINO](https://github.com/IDEA-Research/GroundingDINO) | 图像＋文字 → 框、标签、匹配分数 | 开放词汇物体定位 | 人物／物件位置；不原生输出构图线段和语义分区 |
| [SAM 2](https://github.com/facebookresearch/sam2) | 图片／视频＋点、框、mask 提示 → 像素区域 | 提示式分割与视频分割传播 | 精细轮廓及区域面积；单有 mask 不证明遮挡因果或角色身份 |
| [RAFT](https://arxiv.org/abs/2003.12039) | 两帧 → 像素位移场 | 光流估计 | 运动方向／强度证据；不直接输出动作含义 |
| [AMT](https://arxiv.org/abs/2304.09790) | 前后帧 → 中间帧 | 视频插帧 | 补帧与连续性研究；不是动作识别模型 |

PICD 论文称为 PCPNet 的摄影方法，对应 Lee 等 2018 年的 *Photographic composition classification and dominant geometric element detection for outdoor scenes*；原论文分类器称为 FT_CNN，并另有按类别执行的几何元素检测过程。不要混同为一个端到端输出所有几何的网络，也不要与同名的点云 PCPNet 混淆。

许多模型可理解为“视觉编码器 → 中间特征 → 专门输出头”。分类头学习类别，评分头学习人工分数，检测／分割模块学习位置。相似的编码器架构可以接受不同监督，但换头后仍需相应训练。

把评分头之前的向量拿来检索，是在验证特征的可迁移性。最终质量分数相近，不等于构图类别相近；能够输出 embedding，也不表示该 embedding 的相似性已经按构图组织。PICD 正是在检验这件事。

MUSIQ 需要按 checkpoint 区分：AVA 是美学评价；KonIQ、PaQ-2-PiQ、SPAQ 是图像质量评价。自然图像主观画质也可能受光线、布局影响，不宜说成纯失真检测；不同权重的分数范围不能混用。[论文](https://arxiv.org/abs/2108.05997)、[Google 官方解释](https://research.google/blog/musiq-assessing-image-aesthetic-and-technical-quality-with-multi-scale-transformers/)。

# 构图理解

## 1. 目标与方案修正

用户最终确认：**第一层“构图类别相似”是主要目标，第二层具体布局可以包含一些权重但不多。**

| 层次 | 判断内容 | 当前地位 |
| --- | --- | --- |
| 构图类别 | 都是对角、水平、居中、对称、三分等组织方式 | 主要召回与排序依据 |
| 具体布局 | 人数、主体中心、大小、线段方向／位置／长度、遮挡等 | 一般相似查询中的辅助；显式 Query 条件除外 |
| 质量 | 清晰度、构图质量、美学偏好 | 独立过滤或排序信号，不能当作构图相似度 |

早期提出“Grounding DINO 主体框＋VLM 定向构图标签＋结构检索，需要精细轮廓时加 SAM 2”，现在作为可选组合保留。它没有完成检索评测，也不是必须组件清单。当前可以先验证类别识别，DINO／线段／SAM 2 是否加入由收益决定。

“构图”不是物件名称的集合。水族馆与走廊可以共享斜向构图；两个水族馆画面也可能分别属于水平和对角构图。不能通过总语义相似度默认解决构图相似。

## 2. 构图数据集与可借用标准

### 2.1 PICD：最贴近当前类别级检索目标

[Can Machines Understand Composition? Dataset and Benchmark for Photographic Image Composition Embedding and Understanding，CVPR 2025](https://openaccess.thecvf.com/content/CVPR2025/html/Zhao_Can_Machines_Understand_Composition_Dataset_and_Benchmark_for_Photographic_Image_CVPR_2025_paper.html)提出 PICD 和评测协议。

- 分类沿“点、线、形状”等元素类型与排列方式组织，形成 24 类。
- 论文版 36,857 张图片、355 种场景；截至本次核查，官方数据扩展到 49,123 张。复现时要锁定版本。
- 当前公开 CSV 的核心字段为 `img_id`、`category_id`、`category_abbre`、`category_full_name`。
- 官方列出 44,577 张可直接下载图片，其余 4,546 张通过原始来源映射获取。数据使用说明包含 CC BY-NC-SA 4.0 和专属条款；本轮核查了发布说明，没有下载全量数据。

来源：[官方仓库与下载说明](https://github.com/CV-xueba/PICD_ImageComposition)、[类别定义附录](https://openaccess.thecvf.com/content/CVPR2025/supplemental/Zhao_Can_Machines_Understand_CVPR_2025_supplemental.pdf)。

论文的构图检索实验从每类随机抽 50 张，共 1,200 张 query，其余为 gallery，用同构图类别定义相关性，报告 mAP@10／50／100。另有三图构图区分和语义干扰测试，检验模型是否把“内容相同但构图不同”误认为匹配。[评测协议](https://openaccess.thecvf.com/content/CVPR2025/papers/Zhao_Can_Machines_Understand_Composition_Dataset_and_Benchmark_for_Photographic_Image_CVPR_2025_paper.pdf)

这提供类别级标准；不提供每对图片细粒度构图相似分数，也不直接提供本轮自定义的“人物框＋主要线段”逐图真值。摄影数据能否迁移到动漫仍需验证。

对用户更粗的“对角构图”，可以研究将 PICD 的点元素对角排列、线／形状对角构图映射到共同父类。此映射是我们的候选产品标签方案，尚未确定，也不能把合并后的指标当作原始 24 类 benchmark 的成绩。

### 2.2 PICD 有没有训练好的模型

**没有随该工作提出并发布一个可直接加载的 PICD 24 类分类器或专用构图检索权重。** 当前官方仓库是数据、标签、映射和条款；论文主要评测已有预训练模型。

原论文将 PCPNet、SAMP-Net、MUSIQ 等 10 个既有构图分类、评分、美学、裁剪模型的中间特征拿来评测；补充材料另评 CLIP 与 DINOv2。使用评分头之前的特征，不代表把评分分布解释成构图类别概率。

| 基线 | 原任务 | PICD 中的用途 |
| --- | --- | --- |
| PCPNet | 摄影构图分类 | 提取特征，比较构图辨别与检索 |
| SAMP-Net | 构图质量评价 | 提取中间特征，检查构图类别信息 |
| MUSIQ 等 | 图像质量／美学评价 | 检查质量任务特征的迁移性 |
| 裁剪模型 | 预测裁剪区域质量 | 以整图为目标区域提取预测模块前的特征 |
| CLIP／DINOv2 | 通用视觉表示 | 在补充实验中评测构图信息 |

论文表 2 的三图辨别 CDA1 为 SAMP 0.334、PCP 0.388、MUSIQ 0.488；该任务随机水平约为 1/3。**这些不是 24 类分类准确率，也不是我们的动漫实测。** 结果提示现成特征未必能直接胜任构图检索，而非证明构图只能靠专用模型。[原论文](https://openaccess.thecvf.com/content/CVPR2025/papers/Zhao_Can_Machines_Understand_Composition_Dataset_and_Benchmark_for_Photographic_Image_CVPR_2025_paper.pdf)

“训练一个固定类别分类头／适配器”或“让 VLM 按固定类别输出”都是我们的候选实现，尚未实施。若使用 PICD 训练，必须另建并锁定训练／验证／测试划分，避免把训练见过的图片当成独立评测。

### 2.3 CADB 与 SAMP-Net

CADB 原始目标是构图质量评价：9,497 张图，每张由 5 位美术相关专业标注者给出 1～5 分。后续补充了 13 类构图标签与主要构图元素，类别包括居中、三分、黄金比例、三角、水平、垂直、对角、对称、曲线、放射、消失点、重复图案、充满画面，并允许无明显规则或多标签。[官方数据与元素标注说明](https://github.com/bcmi/Image-Composition-Assessment-Dataset-CADB)

配套 SAMP-Net 使用 ResNet-18 特征、显著性增强的多模式池化和属性融合，预测构图质量评分分布。官方提供约 180 MB 的预训练权重。模式权重表示这些模式对质量预测的重要性，不是 13 个构图类别的预测概率；模式与规则也不是严格一一对应。[SAMP-Net 论文](https://www.bmva-archive.org.uk/bmvc/2021/assets/papers/0378.pdf)、[权重与代码](https://github.com/bcmi/Image-Composition-Assessment-Dataset-CADB)

| 对比 | PICD | CADB |
| --- | --- | --- |
| 主要问题 | 是否理解构图类别、能否检索同类构图 | 构图质量好不好 |
| 核心监督 | 24 类构图标签 | 每图多人的质量评分；另有类别和元素标注 |
| 配套模型 | 评测已有模型；无该论文自有 PICD 分类器 | SAMP-Net，可下载权重 |
| 对当前任务的帮助 | 类别定义、语义干扰和检索评测 | 分类／元素标注补充，质量模型基线 |
| 不应作出的推断 | 数据集存在就已经有成熟识别模型 | 两张图都高分就构图相似 |

### 2.4 其他相关数据集

| 数据集／工作 | 实际标注与用途 | 对我们能提供什么 |
| --- | --- | --- |
| [ShotBench／ShotQA](https://vchitect.github.io/ShotBench-project/) | 电影画面与片段，八个影视语言维度；ShotBench 超过 3,500 个专家问答，ShotQA 约 70k 问答 | 景别、机位、构图、光线和运镜的理解评测；不是图对相似排序真值 |
| [Netflix Match Cutting](https://arxiv.org/abs/2210.05766) | 100 部电影；9,985 人物画面匹配对与 9,320 运动匹配对，多人判断 | 真正的成对剪辑匹配标准，但侧重人物／运动；[公开仓库](https://github.com/Netflix/matchcut)提供标注、时间和 embedding，未打包原电影素材 |
| [Color Composition Similarity](https://github.com/hamailan/Color-Composition-Similarity) | 31,248 图对，每对至少 20 人按 1～5 分评价颜色及其空间分布相似性 | 更接近 Q25 色彩衔接；不能当成忽略颜色的几何构图真值；官网有下载链接，本轮未下载 |

注意术语：Composed Image Retrieval 通常指“参考图＋文字修改”的组合查询；图像抠图中的 Composition-1k 指前景背景合成。它们不能仅凭名称归为摄影构图相似数据集。AVA／AADB 的审美评分也不能直接充当构图相似标签。

## 3. Grounding DINO 的模型与输出解释

### 3.1 模型是什么

Grounding DINO 是有可下载权重的开放词汇目标检测模型，不是一个逐层询问 VLM 的协议。图像编码器提取视觉特征，文本编码器处理目标描述，经跨模态融合与 Transformer 解码器输出目标框和词语匹配分数；这里的 decoder 不等于聊天模型逐 token 生成回答。

开源常见权重包括 Swin-T／Tiny 和 Swin-B／Base，本文只实测 `IDEA-Research/grounding-dino-tiny`。本地可走 CPU 或支持的 GPU 路径；不能把我们验证过的 Tiny 软件路径和成本直接套到其他版本。[官方实现](https://github.com/IDEA-Research/GroundingDINO)、[论文](https://arxiv.org/abs/2303.05499)、[Tiny 模型](https://huggingface.co/IDEA-Research/grounding-dino-tiny)

### 3.2 如何阅读输出

模型先预测候选框与输入词的匹配分数；官方后处理按 `box_threshold` 保留目标，按 `text_threshold` 解析标签。实验将框还原为原图像素坐标，并计算中心和面积：

```json
{
  "label": "person",
  "score": 0.407468,
  "box_xyxy": [1115.22, 558.60, 1403.75, 737.96],
  "center_xy_normalized": [0.655982, 0.600260],
  "box_area_ratio": 0.024957
}
```

此例来自已退役的本地六图实验，见[GroundingDINO 退役摘要](../../docs/dev/design-experiment-cleanup.md#groundingdino-检测)。

- `label`：与输入文字匹配的标签，不是模型自由生成的完整场景理解。
- `score`：匹配分数，不是“有 40.7% 概率识别正确”，也不是构图相似度。
- `box_xyxy`：左上角和右下角坐标；这是矩形，不是像素轮廓。
- `center_xy_normalized`：脚本按 `(x0+x1)/(2W)`、`(y0+y1)/(2H)` 计算。
- `box_area_ratio`：脚本按框面积除以画幅面积计算；框内含背景，不能称为人体实际像素面积。

归一化坐标方便跨分辨率比较。换分辨率后，像素框需要缩放；归一化框也只应预期近似稳定，不能要求完全一致。阈值附近的分数变化会影响框是否出现，重复框还会影响人数和最高分选框策略。

### 4.1 性能与本地可运行性

首次实验 MPS 前向中位 736.84 ms，完整检测流程中位 784.81 ms；CPU 为 1973.84／1999.66 ms。计时含预处理、传输、前向、同步和官方后处理，不含模型加载、Python 导入、读图、视频解码与绘图。

FP32 权重文件约 689 MB；MPS 驱动已分配内存观测最大值约 3.25 GiB、进程峰值 RSS 约 0.63 GiB；CPU 峰值 RSS 约 2.86 GiB。驱动分配与 RSS 不能简单相加，权重大小也不等于运行总内存。

“官方完全没有性能提示”的说法已修正：原实验引用论文 Table 20 的 Tiny 172M、464 GFLOPs、8.37 FPS，但公开表格的运行口径不足以直接推算本机耗时。本地实测更适合当前容量判断。[GroundingDINO 退役摘要](../../docs/dev/design-experiment-cleanup.md#groundingdino-检测)

## 5. 统一表示：先固定任务，再固定字段

### 5.1 当前类别级方向

统一输出需要固定标签体系与版本，保留类别、来源和分数语义。下列仅为设计示意，未写入生产合同，也不是某个模型的真实输出：

```json
{
  "schema_version": "composition-draft-v0",
  "label_scheme": "待确定：PICD原始类别或产品父类映射",
  "composition_labels": ["diagonal"],
  "source": "待确定的分类模型或VLM",
  "layout_features": null
}
```

如果模型提供类别得分，应记录它是 logits、概率还是未校准分数；不能给助手目视判断补造 0.9 一类置信度。真实画面可能同时体现多种构图，是否多标签需根据产品标签方案和数据评测确定。

初始流程为“统一类别识别 → 同类／相近类召回与排序 → 少量布局调整”。目前不固定类别与布局的数值权重，不把未验证的混合公式写成既定方案。

### 5.2 保留的几何表示草案

先前讨论的“主要线段＋人物框”可以作为布局补充。其最小约定为：

| 字段／规则 | 约定 |
| --- | --- |
| 公共元信息 | schema 版本、原图宽高、坐标空间、来源 |
| `subjects.items[]` | 固定类型与 `box_xyxy`，数量可变；人框口径明确是否包含随身物品 |
| `lines.items[]` | 固定角色枚举、两个端点；角色候选为区域分界、透视引导 |
| 线段分组 | 同一结构带上下两条边可共享 group，避免重复计为独立证据 |
| 坐标 | 左上角原点、x 向右、y 向下，归一化至 `[0,1]` |
| 缺失状态 | 区分未运行、不支持、未提取到可靠结果和已提取；空结果不证明画面不存在目标 |
| 提取来源 | DINO 可填框；不提供线段时标明不支持；不得从框对角线伪造线段 |

线段选取规则比字段名更重要：保留能解释主要区域划分和纵深的边界，不标所有细碎边缘；明确端点、遮挡延伸、曲线近似及主次规则。固定 JSON Schema 只能保证类型与格式，不能保证语义与坐标正确。

人物和线段按变长集合匹配，不能默认两图数组第一项互相对应。中心、面积、长度和角度由代码计算；角度使用 `(Δx×W, Δy×H)`，不能在不同画幅下直接用归一化坐标斜率当真实图像角度。裁剪、黑边和字幕区域的处理口径也需要固定。

## 6. 标准、评测与后续工作

公开数据使我们有了可借用的类别定义和标注依据。标准仍应对应产品任务，不能由某次模型输出反过来定义“正确答案”。本轮两个构图案例和六张分辨率样本属于探索实验，尚不是独立构图检索测试集。

| 下一步 | 验证什么 | 当前状态 |
| --- | --- | --- |
| 阅读并固定 PICD 类别及 CADB 元素规则 | 是否采用原始类别，或合并为产品父类 | 待执行；已找到原始资料 |
| 建立可复现的公开基线评测 | VLM 类别判断、既有 embedding、构图分类方法的差异 | 未运行 |
| 添加少量动漫留出集 | 摄影标准向动漫迁移是否可靠 | 未建立；不要把当前示例当作测试真值 |
| 比较类别主导与少量布局加权 | 布局是否带来真实排序收益 | 未确定公式和权重 |
| 根据失败例决定训练或工具组合 | 是否需要分类头、适配器、DINO、SAM 2 或线段提取 | 尚未技术定型 |

动漫评测的候选起点是若干参考图配多个候选（例如 50 张参考图、每张 10 张候选，仅为规模建议）。标注者先看原图和明确的查询要求，独立判断相关性，不看模型画线，以免循环自证。需要包含“语义不同但构图相同”“语义相同但构图不同”，排除只靠重复帧获高分，并按作品／镜头划分避免近重复泄漏。多人分歧应保留并复核，而不是强行假设绝对客观答案。

若采用原始 PICD 类别相关性，按其检索协议比较；若使用产品多标签、父类或等级相关性，应单独命名评测并记录标签规则。具体布局仅在默认查询里低权重，显式位置和机位要求仍需单独核验。

## 7. 需要持续保留的结论边界

| 容易产生的误解 | 本轮确认的表述 |
| --- | --- |
| 普通 VLM 无法做构图，必须先用 DINO | VLM 可解释和估计；类别识别要实测，DINO 是可选位置证据 |
| DINO 输出物体框就完成了构图理解 | 物体框只表达目标区域，类别、主线和整体关系还需其他表示 |
| 人物框 IoU 高说明检测准确率高 | 本轮 IoU 是模型间／分辨率间一致性，无专家 GT |
| 480p 与 1080p 一样，画质影响很小 | 六张样本匹配人框较接近；其他类别、阈值、重复框、压缩和小目标仍可能变化 |
| 官方没有性能资料，或者参数少就一定很快 | 有论文指标，但本机成本要按实际输入、实现和设备测量 |
| PICD 数据集带有现成的 24 类模型 | 该工作提供数据和评测，没有发布自有分类器权重 |
| SAMP-Net 模式权重就是构图类别概率 | 模式权重服务于质量评分，不能直接替代类别预测 |
| 固定 JSON 就能统一构图解析 | 还需固定标注口径、缺失语义和独立验证 |
| VBench 的同名 Composition 就是摄影构图 | VBench-2.0 该维度是概念组合；PICD 是摄影布局分类 |
| 首先必须完成精细线段、轮廓和遮挡才能检索 | 当前已确认类别级为主，精细几何只是可选补充 |

## 1. 当前卡点与实现边界

目标是可靠区分角色声音，特别是第四集“祥ちゃんも悪くない／也不是小祥的错”。用户确认人物为**长崎爽世**。用户试听认为该句是正常、清晰的人声，不能因为模型匹配失败就认定目标是坏样本，也不能继续只靠改阈值证明效果改善。

本轮 v11 的两个已确认登记错误如下；人物真值来自用户确认，不是模型多数投票：

| 原视频区间 | 台词 | v11 正式登记 | 用户确认人物 |
| --- | --- | --- | --- |
| 47.5–48.8 秒 | 祥ちゃんも悪くない | 高松灯 | 长崎爽世 |
| 293.5–296.0 秒 | 長崎そよちゃんと… | 丰川祥子 | 千早爱音 |

当前声纹是 `iic/speech_campplus_sv_zh-cn_16k-common`、revision `v1.0.0`、192 维、CPU。**192 维不足不是已证实根因**：官方 ERes2NetV2 common 和中英 advanced CAM++ 同样输出 192 维；网络结构、训练语料及声音状态的鲁棒性与输出维数是不同问题。[官方模型注册](https://github.com/modelscope/3D-Speaker/blob/main/speakerlab/bin/infer_sv.py)

同一角色可能轻声、夹声、压低、喊叫或改变发声方式。清晰度只是一项条件；更需要检验模型的跨状态表示和参考库的状态覆盖。电影演员变声导致现有声纹模型性能下降有直接研究先例，但尚未证明我们这句爽世的具体失败因素。[VoxMovies 原论文](https://arxiv.org/abs/2010.15716)

实现状态需区分：

- VoiceprintAgent 已能登记同人多条参考、替换／撤销未 ready 的参考、拒绝区间交叉，并由完成工具提交 ready；采集目标为每人 6 条，**没有硬上限**。
- 当前在 75% Understanding 提交后准备：24 个 chunk 的门槛为 18；第一轮来源池冻结当时全部已提交来源，并不保证是顺序上的前 18 个 chunk。原 90% 批次推进规则仍保留。
- 本轮工作区已将 finish 检查改为：同编码器同人物组至少 5 条参考时，逐条留一计算 `candidate_mean`，`<=0.50` 要求复核；已移除 core／gap 条件。相关 213 项测试通过，**此次改动之后未重启部署，不会追溯撤销已有 ready 成果**。
- 当前仍是 Refine 按需调用 `compare_speaker`，再用 Canvas 写 speaker。**ready 后程序遍历所有台词、自动识别并填写 speaker 尚未实现**；“算法先分簇”已有下述 WavLM K-means 离线实验，Agent 归名和生产调度尚未接入。
- 声纹只在本次 video/task 内使用，人物参考在 task detail 的 `voiceprint` 中；engine 提供 schema／通用能力，持久化由 server 负责。首版不自动跨视频共享，也不需要把这批小规模声纹送入 ES。

## 2. 已有实验如何读取，避免再次混用分数

`candidate_mean` 是目标与本人物组其他参考的逐条 cosine 均值；归一化质心分数是先平均参考向量，再对其方向计算 cosine。设单位向量的平均为 μ，后者等于前者除以 `||μ||`。两者不是同一数值口径，阈值不能直接共用；相似度也不是身份概率。

下表固定为 **v11 的同一个 47.5–48.8 秒目标和同一套参考**，排除目标自身：

| 候选人物 | 有效参考数 | 逐条 cosine 均值 | 归一化质心 cosine |
| --- | ---: | ---: | ---: |
| 丰川祥子 | 6 | 0.515009 | 0.696128 |
| 长崎爽世 | 6 | 0.418053 | 0.574727 |
| 高松灯 | 5 | 0.435419 | 0.534034 |

### 第四集全部 ASR 来源的 WavLM K-means 实验（2026-10-18）

入口：[聚类与选源退役摘要](../../docs/dev/design-experiment-cleanup.md#聚类与选源)。本轮没有切换生产模型或重解析。

固定输入为 V9 任务 `56498828-8926-4ad7-beb4-b8a22d2b0b49` 保存的 24 个 Understanding chunk／378 条完整 ASR cue；V11 快照没有保存 ASR，不能假装用其 timeline 代替全量 ASR。长 cue 等分为不超过 3 秒的非重叠短窗，共 436 窗，另复制 3 条历史 query；439 条均实际编码。短于 1.5 秒、已标 OP／ED、低 RMS、重叠或重复来源、留出台词相关 cue 不拟合，最终 226 窗拟合。原 cue 与切窗累计时长均 683.5 秒；没有丢掉 null speaker。已知两句及其全部重叠 cue 不用于选 K 或选代表源。

使用此前数值复核过的 Python 3.12 原生 ARM 兼容 WavLM，主环境未安装新依赖。439 条前向累计 52.290 秒、加载 4.793 秒、峰值 RSS 约 2.844GB；3 个历史 query 新旧向量逐元素完全相同。聚类使用 SciPy 1.15.3 `kmeans2`，对 L2 单位向量做普通欧氏 K-means，未做 spherical／whitening／降维。K=2～12，每 K 5 组、每组 10 starts，共 550 starts 均成功；组内按 SSE 取胜者，以五组 cosine silhouette 中位数选择 K，不读人物名或目标结果。数学计算约 6.394 秒。

自动选中 K=2，silhouette 中位数 0.237962，簇大小 157／69。两个大簇混有多个人物；爱音、爽世两句的全部 5 个边界条件落入同一簇，**自动几何指标不能直接充当人物簇数选择器**。主结果保留，未根据目标改 K。另将所有已计算 K 的代表源与目标落点完整展示，只作粒度探索、不另选“最好模型”。每簇最多 3 条代表源，按跨 seed 对齐稳定性、同簇至多 10 条独立 cue 近邻支持、欧氏距离差排序，优先跨 chunk；另展示一条边界例。这些指标不是身份概率。

K=8 的探索结果可作为下一轮试听入口：C01 的 68 个拟合窗中 63 个原标签为爱音；C03 的 20 个窗中 16 个为灯；C04 的 38 个窗中 35 个为爽世；C08 的 25 个窗中 19 个为立希。C05／C07 等弱标签仍混杂，弱标签本身也可能错；不能把这些比例写成纯度真值或识别准确率。同一人物可占多个簇，不要求一人一簇。

K=8 的经典爽世 47.5–48.8 秒目标落 C04，其 3 个代表源为 `897600–900000`、`626900–629100`、`561500–563850 ms`，均来自不同 chunk、原标签均为爽世。目标与三条的逐条 cosine 为 0.514304／0.560845／0.512320，均值 **0.529157**；本次其他簇代表源均值的最高为 C01 **0.311067**。爱音 293.5–296.0 秒目标与 C01 三代表源均值 **0.647584**，次为 C04 **0.548420**。这是另列的代表源均值诊断，不是 K-means 欧氏分配公式，也不是概率；没有用目标反选来源。

这个结果支持继续验证“扩大整集来源后先分组、再选参考”，尚不能把改善全归因于样本质量：本次候选池不同，乐奈与睦因所有来源过短而没有拟合窗，祥子只有 2 窗，稀少人物尚未各自分离。随后已补[聚类与选源退役摘要](../../docs/dev/design-experiment-cleanup.md#聚类与选源)：保留祥子、乐奈旧来源，只替换爱音、立希、爽世、灯四组。爽世目标的逐条均值 0.529157 仍低于乐奈 0.529823，排第 2；归一化质心分则为爽世 0.593479、乐奈 0.529823，爽世第 1。爱音目标在旧库本来已第 1，不能算新增修复。候选来源身份仍待试听核验，尚无独立泛化验收；没有全量人工真值，未计算 DER／整集准确率；已标音乐区间和 RMS 也不等于完整 VAD、伴奏或换人检测。

独立验证覆盖 439 份 WAV／PCM、378 cue 完整切分、226 个拟合资格、55 组中心与标签／SSE／silhouette／ARI／对齐、全部映射、11 个粒度视图的 231 条代表源、385 个代表源均值及独立复算的 1155 个 cosine，并重执行选定 seed。临时整集 PCM 已清理，实验试听 WAV 按本次报告保留。准备脚本仅针对固定输入；本次 ASR 与 query PCM 无交集。以后换输入复用时，应在扫描 ASR 前建立 query PCM 排除集合，不能只依赖最后追加 query 的去重顺序。

## 4. 算法先分组、Agent 辅助的研究方向

用户确认希望由算法先确定一批声音组，再由 Agent 辅助检查和归名。候选流程是：**原音频／ASR 时间参考 → 合适的短窗 embedding → video 内全局匿名聚类 → Agent 根据多个明确来源给簇命名 → 程序分配台词并保留未决项**。尚未接入当前 runtime。

- 允许同一角色对应多个声学簇／原型，覆盖夹声、压低等声音变化；匿名簇数量不等于人物数。不把同一人物所有状态强制平均成唯一质心，也不因为任意单条参考最高就自动定人。
- 多原型评分是待验证方案：分别比较各子簇，参考充分时检查多条独立来源的支持，再与其他人物子簇比较；不在本次交接中拍定新阈值或公式。
- 差异很大的簇是否属于同一角色，仍需要可靠的身份锚点，不能用当前错标姓名多数票循环自证。Agent 不直接判断 192 维数值，声学计算由工具提供证据。
- ASR 一条可能混两个人，整条提一个向量后，聚类不会自动把它拆回两个人；需要检查换人、分窗和混合段。`speaker1/2` 只在当前 chunk 有效，不能当作跨 chunk 的全局身份。V2 历史 `start_seconds/end_seconds` 实际是绝对整数毫秒，不能再次乘 1000。
- 当前 ASR 随 Understanding commit 才形成持久化来源。固定整集聚类可先读已完成第四集；接生产若要求全量来源，不能同时声称仍在 75% 时得到固定整集簇，增量语义需另行设计。

可复用的经典算法及论文：

| 路线 | 来源 | 对下一步的作用与边界 |
| --- | --- | --- |
| average-link AHC／谱聚类 | [3D-Speaker 聚类源码](https://github.com/modelscope/3D-Speaker/blob/main/speakerlab/process/cluster.py)、[官方 CAM++192＋spectral 配置](https://github.com/modelscope/3D-Speaker/blob/main/egs/3dspeaker/speaker-diarization/conf/diar.yaml) | 编码器对照之后，在同一 embedding 矩阵做两条聚类基线；不能照搬小簇强制归入大簇的默认策略 |

### 补充论文：参考质量之外的优化（2026-10-18）

目前不能归结为“维度太少／模型已经没有优化空间”，也不能归结为“挑干净参考就能全部解决”。参考身份、发声状态与音素覆盖、参考聚合、目标自身的信息量，以及分段／换人是不同因素。本小节记录文献和后续对照建议；没有据此训练模型、改阈值或写回 speaker。

**多参考如何聚合。** 以下论文研究的是已知同一说话人的多条登记；它们不会自行证明第一条参考的姓名，也不保证匿名聚类中的一簇就是一个真实人物。

1. [Attention Back-end for Automatic Speaker Verification with Multiple Enrollment Utterances，ICASSP 2022](https://arxiv.org/abs/2104.01541)。
   使用 scaled-dot self-attention（SDSA）学习登记向量之间的关系，再以 feed-forward self-attention（FFSA）形成参考表示；后端通过带说话人标签的样本训练。
   可借鉴“不同参考贡献不同”的机制，但不是现成的无训练平均公式。[官方实现](https://github.com/nii-yamagishilab/Attention_Backend_for_ASV)明确当前代码针对 TDNN x-vector；不能直接把其权重套到现有 WavLM 256 维向量。

2. [How to merge your embeddings: statistical vs attention-based speaker embedding aggregation for speaker verification with multiple enrollments，EUSIPCO 2025](https://eurasip.org/Proceedings/Eusipco/Eusipco2025/pdfs/0000026.pdf)。
   在每人五条登记的设置下比较逐坐标 mean／median／max，以及单独训练的 attention 聚合；统计聚合无需再训练，attention 后端需要训练。不同测试场景的收益不同。
   这里的 median／max 是每个 embedding 坐标取中位数／最大值，**不是**删除逐条 cosine 的最大最小值，也不是取最高参考分。论文不能为当前动画直接给出一种通用最优聚合方式。

3. [Parameter-Free Attentive Scoring for Speaker Verification，Odyssey 2022](https://www.isca-archive.org/odyssey_2022/pelecanos22_odyssey.html)（[原文](https://arxiv.org/abs/2203.05642)）。
   评分用 query／key 的 softmax 权重组合 value 相似度，支持多条登记；“parameter-free”指无需独立的参数化评分模型。
   原系统的 encoder 联合训练输出相应 Q／K／V，缩放／温度可联合学习或作为超参数指定；不能认为任意现成的 WavLM 单向量已具备这种表示。对当前向量做 softmax 加权只能标为受其启发的待验启发式，不能声称复现论文后端。

4. [Probabilistic Spherical Discriminant Analysis（PSDA），Interspeech 2022](https://www.isca-archive.org/interspeech_2022/brummer22_interspeech.pdf)（[作者代码](https://github.com/bsxfan/PSDA)）。
   在单位球上以 Von Mises-Fisher 分布建模说话人方向和离散程度，支持多条登记／测试；合向量的方向与长度共同参与推断，而不只保留一个单位质心。
   它能研究登记数和集中程度如何影响证据，但要用带说话人标签的观察做 EM 训练。已有 TDNN 后端参数不能因维度相近而直接用于 WavLM；它也不是自动消除错标参考的无监督门禁。

**质量校准与跨状态。** 以下两类信息可以补充“音频越长越好”的单一假设，但都需要在本项目条件下验证。

5. [The IDLAB VoxSRC-20 Submission: Large Margin Fine-Tuning and Quality-Aware Score Calibration in DNN Based Speaker Verification，ICASSP 2021](https://arxiv.org/abs/2010.11255)。
   其质量感知 logistic 校准用同人／异人试验学习分数、时长、净语音量及其他质量特征的组合；不等于直接设置 cosine≥0.6。
   对所有候选应用相同正斜率的单调变换不会改变 top1；若仅加入对各候选相同的查询质量项，也不会重新排序。候选侧质量不同或采用其他条件项时才可能改变排序，这是公式的推论，不是已有本地改善。
   单靠单位向量不能还原归一化前 norm；当前实验 JSON 已保存 `raw_norm`，但需确认提取位置与该论文的特征是否一致、是否真有预测价值，不能直接当成已校准质量。本轮未调查或变更生产 reference schema。

6. [Phonetic Richness for Improved Automatic Speaker Verification，EUSIPCO 2024](https://eurasip.org/Proceedings/Eusipco/Eusipco2024/pdfs/0000750.pdf)（[原文](https://arxiv.org/abs/2407.08017)）。
   除净语音时长外，研究不同音素覆盖对识别和校准的影响：重复同一个短词，时长增加也未增加同等的语音信息。
   原文采用英语 39 音素、ASR／G2P 和带标签拟合的音素权重／校准。可借鉴参考库覆盖不同台词内容的方向；不能将该音素表或权重照搬日语，也不能仅由文本长度声称音素覆盖充分。

7. [Playing a Part: Speaker Verification at the Movies，ICASSP 2021](https://arxiv.org/abs/2010.15716)（[作者 VoxMovies 实现](https://github.com/JaesungHuh/VoxMovies)）。
   直接研究演员主动改声、情绪、口音及背景条件造成的影视域差异，显示采访语音上的能力不等于电影语音能力；这是保留同人跨状态来源的依据。
   其轻量适配仅训练最后全连接层，但仍使用跨域同人标签；并非免费校正。VoxMovies 最短片段按设计为 2 秒，不证明 1.2 秒日语动画的表现，本项目也未执行该适配。

**目标音频和换人边界需要单独处理。** [MSDD，Interspeech 2022](https://www.isca-archive.org/interspeech_2022/park22d_interspeech.html)通过不同长度的窗口、动态尺度权重和序列解码，处理短窗时间分辨率与身份表示质量的取舍；完整路线需要相应训练模型。不能平均现有向量就声称获得真正的多尺度表示。

[Mitigating Non-Target Speaker Bias in Guided Speaker Embedding，Interspeech 2025](https://www.isca-archive.org/interspeech_2025/horiguchi25_interspeech.html)展示非目标说话人会污染全局统计，需结合目标活动信息改造并训练提取器。对一般混人 ASR cue，只换干净登记库不能保证从已池化向量中消除另一人的贡献；应回到音频、换人位置或活动段重新提取。

上述一般风险**不是经典爽世片段的失配诊断**：用户确认它是清晰正常人声，V9 的 `47600–48800 ms` 也已独立成句。短时信息量、台词内容、发声状态或参考覆盖差异只是待验证因素，不能凭分数认定该句混人。

**下一轮优先做的最小对照。** 下面是结合论文和本地结果的工程推论，不是论文保证有效的方案。

- 先试听核验候选参考的身份，保留同一角色跨场景、发声状态及不同台词的多个原型；一个人物允许对应多个声学簇。K-means 的几何最优、跨 seed 稳定和簇内多数姓名都不是身份真值。
- 复用现有 439 条向量，固定同一人物候选池、相同留出规则，分别比较逐条均值、归一化质心和多个原型的独立来源支持；登记数不同要显式报告，增加原型后取最大值还会增加偶然命中机会，不能无条件自动接受。
- 对单位查询 `q` 和单位参考 `e_i`，令 `m=mean(e_i)`：逐条均值为 `q·m`，质心分为 `q·m/||m||`。二者不是同一公式；前者同时受参考方向集中程度影响，后者重新归一化方向。当前同六人物对照已展示两者会改变爽世目标排名，尚不能据此反选公式并宣布泛化成功。
- 独立按 cue／chunk 留出，分时长和状态报告误认、候选差异及保留 null；两句经典目标及全部重叠 cue 不用于选 K、选源或调参。没有更多核验标签前，只报告几何诊断／弱标签一致性，不训练后端或发布准确率。
- 现有长 cue 的多个子窗可用于发现表示突变并安排试听；439 个固定向量不能定位一个未切分短句内部的换人点。若后续确需多尺度／换人实验，要对原音频重新分段编码，另列成本及协议。
- 完成以上对照后，再判断是否值得训练轻量质量校准、Attention／PSDA 后端；当前只有两句明确问题不足以拟合并验收这些后端。现阶段不提出训练整个 WavLM 大网。

| 对照所需数据 | 现有 439 条向量能做的部分 | 仍需补充的部分 |
| --- | --- | --- |
| 参考聚合／多原型 | 固定候选池做数学比较，回查每条来源 | 身份试听核验、独立留出，避免用目标挑公式 |
| 时长／跨状态分析 | 按已保存边界分层、找分歧来源 | 实际发声状态标签，不能以簇号自动代替情绪 |
| 多尺度／换人 | 检查现有同 cue 子窗的表示突变 | 真正不同窗长的重新截音与提向量，必要的换人模型 |
| 学习型后端／校准 | 可作为将来的输入特征 | 足够同人／异人标签、分离的训练与验收集合 |

本节论文未提供可直接用于本项目的通用接受阈值。首个可验收成果应是可追溯且身份已核验的候选库、冻结条件下的留出比较，以及证据不足时继续保留 null。

### 如何收集同人不同发声参考（2026-10-18）

用户提出的困难是实际选源：不知道哪里存在同一人物的其他发声状态。算法可以先找匿名声音组、挑代表和疑点，再通过少量身份确认让一个人物关联多个声音组；不能由“与现有参考距离远”直接证明它是同人的另一种声线。

相关主来源：

- [Active Selection with Label Propagation for Minimizing Human Effort in Speaker Annotation of TV Shows，SLAM 2014](https://www.isca-archive.org/slam_2014/budnik14_slam.pdf)：主动选择待标注语音，结合受约束的凝聚聚类传播标签，直接研究以较少标注构建人物声音语料，并检查纯度与时长。原系统使用 BIC、广播视频及可选人脸／字幕姓名；借鉴选样流程不等于已经在 WavLM／日语动画复现。
- [Active correction for speaker diarization with human in the loop，IberSPEECH 2021](https://www.isca-archive.org/iberspeech_2021/prokopalo21_iberspeech.pdf)：选择两个簇的代表音频，询问是否同人后合并／拆分，并限制交互预算。其数据上较长／近中心代表优于跨簇极值对；名字归属不在研究范围。初级簇冻结会保留内部错误，不能据一条代表的确认认证整个混合簇。
- [Active Learning for Convolutional Neural Networks: A Core-Set Approach，ICLR 2018](https://arxiv.org/abs/1708.00489)：提供 k-center greedy 多样性选样依据。原研究是图像主动学习；在现有声音向量上使用最远点覆盖是工程借鉴，不是该论文已验证的声音身份算法。

建议的最小离线流程，尚未执行：

1. **发现声学组。** 使用现有向量形成匿名小组，允许一人多组；混合大簇继续拆成有局部支持的小组，保留未分配来源。K 值、稳定度和原 timeline 的多数姓名都不能代替身份核验。
2. **程序提供试听候选。** 每组先选接近 medoid、邻域支持较好的真实片段作为典型；再在可听、非重叠、不同 cue／chunk 的来源中选择少量有邻域支持的多样性片。最远点选样可按“到已选集合的最小距离最大”逐条补充，避免只拿同一声态的近重复；孤立点和身份边界点单独待核，不能自动登记。
3. **确认跨组身份。** 对尚未映射的小组提供代表片及可能人物／分歧，确认“同人／不同人／不确定”；可靠确认可形成 must-link／cannot-link 或先只维护人物到多个组的映射。Agent 可查找身份依据，但其判断并非论文中的无误人工标签；静帧出现人物不是发声证明，低置信关系不能强制传播。
4. **建立多个原型。** 身份确认后，在该人物范围内保留各组代表和场景覆盖，用于后续独立留出比较；不要只按距单一质心最近筛源，也不要将差异大的已确认同人样本一律当异常。声学差异可能来自发声状态、台词、背景或其他人，簇号不直接等于情绪标签。

第四集已有探索性 K=8 中，C04 的弱标签偏爽世，可以先核验典型与多样性片；C05 已显示混合弱标签，必须局部核验，不能直接称为“爽世的另一种发声”。若同人的另一种声音在当前向量空间完全靠近其他人，纯声音距离未必能找对或连上它，仍需要可靠的独立身份依据。目标是让算法缩小核验范围，不承诺仅凭聚类完成跨声线身份证明。

本节仅记录选样方案与边界，没有执行新聚类、生成新的准确率、修改生产代码或写回 speaker；两句经典目标继续作为留出，不能参与选源或调参。

## 5. 次日实验顺序与验收

1. **冻结输入与真值。** 优先复用已保存音频及来源，保留正常干净难例、同人跨场景／发声状态和相似音色异人；身份由用户确认或另做独立核验，不能将全部非空 speaker／registry 当真值。固定目标精确区间与 PCM SHA，1.0 秒历史目标和 1.3 秒 v11 目标如均测试，分别报告。
2. **先做最小 CPU 冒烟。** 选择明确 checkpoint／dataset，固定官方代码 commit 和 SHA，用 CPU、FP32、小 batch、推理模式加载并跑真实短音频；先验证有限 embedding 和资源占用，再批量处理。依赖按需补齐，不照抄上游旧环境，也不引入新服务。
3. **比较 CAM++ 基线和三支候选。** 每个编码器重新提取整套参考与目标向量，按各自官方前处理；不同模型的向量不能混算，即使都 192 维。首轮固定参考集合与聚合方式，只改变 encoder；模型特有评分后端单独列实验条件。
4. **比较识别而非分数大小。** 报告正确人物排名、同人／异人分离、候选差异、误认与未知；按 `<1s / 1–2s / >=2s` 及发声状态分层。只有充分人工标注后再估计准确率／EER；在相同保留未知策略下看误认，不把“cosine 变大”当成功。
5. **资源分项计时。** 首次加载、热态提向量、聚类、Agent 归名分别记录；测进程峰值 RSS 和模型／缓存磁盘增量。MPS 作为后续独立兼容试验，不影响首个 CPU 结论。
6. **再做整集匿名聚类与多原型对照。** 复用同一批原音频，比较 AHC／谱聚类和角色多簇映射；检查短应答、混合段、NPC、小簇和跨场景。登记源、重复／重叠音频不得成为目标自身的验证证据。评测中保留未决来源，不按经典片段得分反复选段／调参。
