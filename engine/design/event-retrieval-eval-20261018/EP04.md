# 第 4 集原台词：Event 真实命中测试

日期：2026-10-18。本轮按用户澄清，使用已经完成 Event 发布的独立 EP04 speaker-review 素材。与此前未覆盖的正式 13 集实验分开记录。

## 结论

**Event 成功，目标单句排名第 1。** 自然 Chat 的 Query 自主选择 `search_video_events`，没有调用 Chunk `retrieve` 回退；最终正确回答 **第 4 集 09:08–09:09，椎名立希**。最终视频卡保留上下文 **09:00–09:13**。

**本例没有显示速度收益。** 原台词精确匹配时，Event 与 Chunk 的直接检索均稳定 Top 1。三次同权重比较，Event 中位数 0.699 秒，Chunk 0.596 秒；本轮完整 Chat 为 226.111 秒，主要耗时在命中后的精读、画面核验、草稿修订和多轮模型调用。本轮没有运行相同问题的 Chunk-only 完整 Chat，不能据此计算 Event 对端到端耗时的增减。

## 为什么整轮仍然慢

原问题只问片段和说话人。Supervisor 委派后，审核范围还包含前后对白与画面人物核对。第一次 Evaluator 已明确确认目标原句、说话人、时间及播放范围正确，但认为正文没有完整说明画面人物，返回 continue，要求补充视觉与对白标签的对应说明。第二轮 Query 修订后，Evaluator 返回 complete。

这一次 continue 的原因是**答案覆盖与证据表达**，不是 Event 没找到。Evaluator 的完整 advice 原文及两轮动作保留在 [review-events.json](ep04-chat/review-events.json)，不凭缺失的模型内部推理归因。

共 53 次工具调用：Query 25、Evaluator 16、Chat 6、Supervisor 6。成功抽帧 7 次（Query 4、Evaluator 3），均实际供应图片；其中复用已有缓存帧。完整原图、manifest、请求时间与 SHA 核验保存在 [帧证据目录索引](ep04-chat/frame-evidence/index.json)。该索引也保留失败的抽帧请求；本轮有其他可恢复 Canvas 操作错误，详见逐工具日志。没有因此修改生产代码或提示。

## 同句 Event / Chunk 直接对照

同一 EP04 scope、同一原句、同 top_k=10、同 lexical/semantic/visual=0.65/0.35/0；Event 额外使用其专属 DIALOGUE 筛选。每种各运行 3 次，顺序为 Event→Chunk。两边使用 production factory，正常执行查询 embedding、SQL 范围和回源；没有手动复用跨调用 query vector，未启用视觉召回。

| 方式 | 三次服务耗时（秒） | 中位数 | 目标 Chunk / Event |
|---|---|---:|---|
| Event | 0.806 / 0.699 / 0.699 | 0.699 | Chunk 1，Event 1，三次一致 |
| Chunk | 0.596 / 0.622 / 0.541 | 0.596 | Chunk 1，三次一致 |

两边都已能在第 1 名找到父 Chunk，所以本例不存在父 Chunk 排名提升的空间。Event 提供了额外的单句身份、精确时间和说话人，不能由此直接推导检索服务更快。Event 的额外 coverage 校验本次约 0.14–0.15 秒；只把它记录为延迟来源，没有为了测试删除一致性检查。这个小样本不代表其他问题、其他并发负载或全量 13 集的延迟。

自然 Chat 实际选取的权重为 0.9/0.1/0，上表用于控制两种检索方式的输入，并不是该次工具调用的重复时间。直接对比在 Chat 开始后不久运行，客户端请求独立，存在环境波动可能。各阶段与全部通道候选保存于 [逐次 benchmark JSON](ep04-retrieval/summary.json)。
