## P1

### O0. 已有功能达到好用、可验证的交付状态（当前优先）

- KR1：固定课程样例、问题和运行配置，真实执行“上传 → 解析 → 检索 → 播放 → Chat 答疑”主链路。每个样例记录操作步骤、预期与实际结果及通过 / 失败状态；发现的问题修复后重跑受影响步骤。
- KR2：检索与答疑结果能回到原视频核对。分别检查老师讲述、术语解释、公式 / PPT 画面与时间出处；当前视频证据和其他课程证据保留各自来源，证据不足明确说明。支持视觉与仅文字的 Supervisor 都需完成实测。
- KR3：实时理解按固定 `[chunk_i-1, chunk_i, chunk_i+1]` 窗口验收。验证已解析复用、解析中共享、只补缺失 Chunk、同 Chunk 相差一秒、跨 Chunk 重叠、片头 / 片尾、连续追问、部分失败及取消；基础结果可供后续正式解析复用并补齐 Refine / 索引。
- KR4：在当前界面确认上传、解析与答疑的等待状态、失败说明、重试、取消和视频时间跳转。切换视频或取消后，旧结果不能混入新消息。优先修复实测中影响使用的阻断与误导，再优化其他体验。
- KR5：分别测量冷解析、已有 Chunk 复用和派生缓存命中的首次有效解释延迟、完整回答延迟及模型用量；记录样本量、模型、配置、环境和并发，统计 P50 / P95。根据首轮基准确定可接受阈值，再按实际瓶颈优化；预热与增量输出按实测需要安排。
- KR6：保留可复现的验收记录，包括样例与视频位置、预期 / 实际结果、运行条件及必要日志。实现、离线回归和真实视频＋真实模型验收分别登记；全部适用样例达到已确定的质量与延迟标准、使用阻断已解决后，再进入后续扩展批次。

当前已知进度：本地 `realtime_understanding` 首版与 Supervisor 接入已实现，离线测试通过；真实视频＋真实模型答疑、前端操作闭环与性能基准待验收。其他现有功能按实际证据逐项登记，本条不预先认定已通过。

验收分工：本 Agent 负责实时理解、Supervisor 和必要 Server 接口；前端体验、全量解析 / 检索质量、身份与访问范围由对应模块负责。真实闭环中的依赖缺口交给所属模块处理，当前先完成验收与必要修复。

### O1. 未登录用户可以体验云端公开且已解析的资料

- KR1：平台维护明确的公开资料清单。只有已发布、解析完成、索引可用且媒体可播放的资料进入游客范围；处理完成状态本身不代表公开。第一批使用专门的公开 Workspace，暂不建设完整发布后台。
- KR2：未登录用户可以完成公开资料的浏览、搜索和播放。公开范围由 Server 确定；更换请求中的 Workspace 或资源 ID，也不能读取私有资料。
- KR3：云端游客不能上传、修改或删除资料，不能启动解析或修改平台配置。API 和媒体入口执行同一权限规则，前端按权限展示可用操作。
- KR4：先提供无需对话的公开搜索，复用已有检索能力；游客 Agent 问答在 P1 后续批次接入。沿用现有 Agent 页面时，每个游客有独立会话，不能读取其他游客的问题、回答或流式事件。
- KR5：公开搜索与游客问答遵守可配置的请求、并发和模型使用额度。超过额度后不继续发起模型调用；已有资料免去重复解析，但查询编码和问答仍计入用量。
- KR6：撤回公开资料后，游客列表、检索、证据和媒体入口均停止提供该资料；游客不能读取后台任务详情、平台配置及完整费用记录。

### O2. 登录用户可以使用自己的个人 Workspace

- KR1：先接入一种登录方式，完成用户身份验证、登录状态读取、退出和会话过期处理；每个用户有一个个人 Workspace，Workspace 只有一个所有者。
- KR2：所有者可以完成私有资料的上传、解析、搜索、播放和删除。用户 B 不能通过 API、媒体 URL、SSE 或用量查询读取、操作用户 A 的资料。
- KR3：Server 验证个人 Workspace 的所有者后，再向已有业务流程传递合法范围。Video、Chunk 和索引沿用现有归属关系，不重复添加全部用户和租户字段。
- KR4：前端支持本机游客、云端公开游客和云端登录用户。数据来源、登录状态和连接状态分别管理；切换账号或来源时，取消旧请求、关闭旧 SSE，并隔离缓存、播放进度及对话状态。
- KR5：本机无需登录，原有上传、解析、搜索和播放流程保持可用。使用云端模型仍需要网络；断网后的模型能力取决于是否配置本地模型。
- KR6：本机资料保留在本机。登录云端不会自动上传资料、改变旧资料归属或覆盖本机状态；旧本机 Workspace 与历史播放记录有明确的保留方案。

### P1 执行顺序：先验收现有功能，再扩展公开与个人使用

先完成 O0 的现有功能验收与必要修复，再按下列批次推进公开游客和个人 Workspace 的新增能力；已实现的部分按实际验收状态继续，不重复开发。

| 批次 | 开发范围 | 本批验收 |
|---|---|---|
| P1-A | 平台公开清单、游客资料列表和媒体播放入口 | 不登录可以浏览、播放公开资料；私有媒体无法访问，资料写操作被拒绝 |
| P1-B | 无需对话的公开搜索、范围校验及游客限额 | 游客完成浏览→搜索→播放；修改 ID 不能扩大范围；超额不再发起模型调用 |
| P1-C | 一种登录方式、个人 Workspace 所有者与私有流程 | 两个用户各自完成上传→解析→搜索→播放→删除，互相不能访问私有资料 |
| P1-D | 三种使用方式的完整切换、缓存隔离及游客 Agent 会话 | 本机与云端状态不混用；账号切换没有旧数据残留；游客对话互相隔离 |

## P2

### O3. 提供完整团队与租户协作能力

- KR1：明确 Tenant、团队 Workspace 和个人 Workspace 的关系，支持团队创建、资料归属、所有权转移及关闭；按实际需要支持一个租户下多个 Workspace，不预先重复所有归属字段。
- KR2：支持成员邀请、接受、退出和移除，定义管理员、编辑者、只读成员的操作权限，并提供团队管理页面。
- KR3：团队成员按角色访问共享资料。上传、解析、搜索、播放、删除、媒体、SSE 和后台任务使用一致的权限规则；团队之间及个人私有资料之间保持隔离。
- KR4：共享资料与私人对话分开授权。定义团队对话分享、成员私人记录和个人播放状态的可见范围，不把加入团队视为允许读取全部成员对话。
- KR5：成员被移除或角色改变后，已有会话、流式连接和延迟任务按明确规则重新检查权限；任务恢复、重试、删除和归档保留正确的团队归属。
- KR6：支持团队模型配置与凭据管理，区分平台配置和租户配置；成员按权限使用配置，只有授权管理员可以管理凭据。
- KR7：按团队管理存储容量、解析与模型额度、并发和队列使用，保留平台总量限制。管理员可查看团队及成员用量，单个团队不能耗尽全部共享资源。
- KR8：提供邀请、成员变更、资料发布／撤回、删除、配置变更和费用管理的审计记录。完成旧个人资料迁入团队、导出、团队关闭及数据保留方案，并验证跨团队权限。

团队阶段依赖 P1 的身份和 Workspace 归属基础；本期先记录完整范围，成员管理不进入 P1。

### O4. 本地 / YouTube 视频的按需理解与课程库联动

状态：本地实时理解首版已实现并通过离线测试，当前优先完成 O0 的真实使用验收；YouTube、课程库扩展与本机产物后置。后续承接九月份“实时识别的 sub-agent 开发，接入 chat supervisor”的规划，将 YouTube 媒体获取、当前区间理解与课程库检索集成到 AniVAG。页面脚本或侧边栏作为客户端提供播放上下文，复用同一套视频理解与召回能力。

- KR1：用户暂停本地视频并提问时，Chat Supervisor 调用实时识别 sub-agent。已有适用的解析结果时复用；没有时只解析暂停位置附近的指定区间，取得转录和关键帧并回答，无需等待整集下载、全量 Parse 或索引完成。
- KR2：接入 YouTube URL、视频标识与当前播放时间，优先取得提问区间的可解码音视频。媒体获取层适配本地文件和 YouTube 来源，为实时识别 sub-agent 提供统一的视频来源与时间区间；首版面向普通点播视频。
- KR3：Chat Supervisor 按问题组合当前区间理解与已解析资料检索。“刚才那张图是什么意思”走实时识别；“其他课程哪里讲过这个”走课程库检索；复合问题组合两类证据。当前区间小解析直接用于回答，历史检索沿用已有索引就绪规则。
- KR4：成果保留原视频时间位置和来源；保存区间成果与整集解析完成分别管理。当前首版持久化基础 Chunk 结果并复用，派生观察与上下文使用有界进程缓存；临时不保存等可配置模式留待后续扩展，尚未实现。
- KR5：用户选择完整收录课程时，支持后台下载与解析同时推进。下载器准备好可解码片段后交给解析任务，解析当前片段时继续获取后续内容；当前提问区间优先处理。下载和解析分别展示进度，并支持取消与重试。
- KR6：用户本机 Codex / Claude Code 可以取得当前区间理解结果和 AniVAG 课程库证据，在选定的本机学习目录生成笔记或代码。产物分别保留当前视频位置和课程库出处；本机文件操作由本机 Agent 执行，AniVAG 提供内容、证据和访问接口。
- KR7：验收“未全量解析的 YouTube 课程播放 → 暂停并问刚才那张图 → 取得区间转录和关键帧 → Agent 解释”，再验收“解释这张图，找到云端另一门课的相关讲解，整理到本机学习目录”。回答和笔记中的两类来源均可核对并定位回原视频。

执行顺序：先完成已有上传 / 解析 / 检索 / 播放 / Chat 主链路与本地实时理解的 O0 验收及必要修复，再接 YouTube 区间媒体获取与页面播放上下文，随后验证课程库联动和本机 Agent 产物，最后补齐完整收录时的下载 / 解析并行流程。

云端入口沿用 O1 / O2 的身份、Workspace 范围和用量控制：游客体验已发布且已解析的公开资料；新增导入和实时解析面向有权限的用户。本机继续支持无需登录的个人使用。




### 2. 实时识别的sub-agent开发，接入chat supervisor

状态（2026-10-10）：`realtime_understanding`、公共 Chunk 组件与 Supervisor 工具已实现，离线测试通过；当前进入真实视频＋真实模型的使用验收与性能基准阶段。实现记录见 [实时parse_trd.md](../../agent/chat/design/实时parse_trd.md)，产品验收按 O0 进行。

职责边界：本 Agent 负责实时区间理解 sub-agent、Chat Supervisor 的调用与结果整合，以及这条链路必需的 Server 适配。前端播放交互、全量 Parse / Refine / 索引算法、身份与 Workspace 体系、YouTube 下载和本机笔记生成由对应模块负责；本任务复用其接口，依赖缺口列 TODO。

目标：用户观看视频时，点击对话输入栏自动暂停；消息携带当前视频和暂停时间 `t`（整数毫秒）。用户立即问“现在老师讲的 xxx 是什么意思”，Agent 利用 `t` 所在 Chunk 与前后各一个 Chunk 的讲述和画面解释，并提供可核对的原视频时间出处。

- KR1：复用现有 `extraContext.playback` 传递视频标识与播放时间，每条提问固定本次暂停位置。当前 `positionSeconds` 名称沿用旧合同，但实际单位为毫秒；不在本任务中改名或重复乘 1000。Server 校验视频属于本次允许访问的范围、时间在媒体时长内，不能把前端上下文直接当作可信证据。
- KR2：定位 `t` 所在 `chunk_i`，固定窗口为 `[chunk_i-1, chunk_i, chunk_i+1]`，在片头、片尾裁到实际存在的 Chunk。已完成的直接读取，解析中的共享等待，缺失的才领取并补齐基础解析；未全量解析的视频无需等待整集 Parse、Refine 或索引就绪。
- KR3：目标 Chunk 基础识别与精确暂停帧观察并行，两路汇合后由同一个实时理解 Agent 综合文字和视觉证据。首版额外看图使用一张受管暂停帧；成功视觉观察的实际输入依赖一致时复用缓存。返回上下文、caption、精选文字证据、原图及缺失范围，实时阶段不执行 Refine / 索引。
- KR4：Chat Supervisor 为当前视频答疑调用 `understand_current_video`，为“其他课程哪里讲过”调用已有检索工具；复合问题组合两类结果。实时总结作为上下文由 Supervisor 组织最终解释，支持视觉时传递实际图片，文字模型使用 caption 与文字证据。保留视频标识、来源 Chunk 和绝对毫秒时间，`t` 之后的内容注明为后续补充。
- KR5：验收现有消息事件通道的等待反馈、取消、超时与消息归属；取消提问或切换视频后不把旧窗口结果写入新消息。识别失败或证据不足时说明缺口，首次有效解释以已有证据为准。增量解释与补充输出作为实测体验后的优化项，当前不登记为已实现。
- KR6：基础 Chunk 结果持久化复用，完整解析随后接续同一任务并补 Refine / 索引。额外视觉观察与问题相关上下文使用有界进程缓存，并合并相同计算；依赖包含访问范围、媒体 / 帧身份、任务与内容版本、问题及模型 / 提示词 / 配置，Refine 后旧版本不命中。单个等待者取消不取消共享基础解析。
- KR7：用固定课程样例分别验证“已有解析 / 缓存”“完全未解析”“部分窗口缺失”“片头 / 片尾”“连续追问 / 跳转 / 取消”场景。回答中的老师原话和画面描述能回到原视频核对，缓存命中不重复识别已有片段。
- KR8：分别记录已有结果复用、派生缓存命中与冷识别的首次有效解释延迟、窗口补齐时间、完整回答延迟和模型用量，统计 P50 / P95，并注明样本量、媒体长度、模型、运行环境和并发数。速度阈值在首版基准后确定；预热与增量输出按测得的瓶颈安排。

当前调用链：

```text
暂停时间快照 + 用户问题
  → Chat Supervisor
  → realtime_understanding：定位固定 Chunk 窗口
      ├─ 并行复用 / 补齐目标 Chunk 的基础解析
      └─ 并行读取精确暂停帧，取得或复用视觉观察
  → 汇合整理，返回上下文、caption、精选文字证据与原图
  → Supervisor 整合当前视频与所需课程库结果 → 消息事件 / 最终回答
```

实现遵守已有分层：Agent 编排问题驱动的理解；Engine 复用时间窗口、转录归一化和证据校验等领域能力；Server 提供已校验的媒体、已有解析读取、缓存和执行控制；Gateway 执行模型调用。ASR 的片段相对时间只加一次区间起点，转换成原视频绝对毫秒位置。

`source.timeline_indices` 与筛选后的 timeline 一一对应，示例事件来自原始 `timeline[4]`。历史字段名 `start_seconds/end_seconds` 的实际单位仍是源视频绝对整数毫秒，区间为 `[start,end)`；跨 Chunk 事件保留完整时间，只校验源视频总范围。导出不去重相邻 Chunk 里可能已有的重复观察，不将 Chunk 的来源边界视为片内时间原点。训练侧按来源与时间组织上下文，不把翻译当成新轮次；这些 ID 用于追溯，不是需要训练加载器解析的媒体 URI。
