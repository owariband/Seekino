# Seekino 全量 UI · 三方向共同 Design Spec

> 本文件是三套方向稿的唯一共同输入。三套稿使用相同产品事实、功能与真实内容，只改变视觉逻辑、布局骨架和交互节奏。

## 顾问式需求重述

Seekino 不是一个孤立搜索框，也不是对任何问题都泛泛作答的聊天机器人。它解决的是动画爱好者很具体、也很有情绪浓度的问题：用户记得一个梗、一句台词、一个人物关系转折或一种难以描述的情绪，却不记得它出自哪一集、哪一分钟。检索的主体是用户与 Agent 的连续对话；Agent 把模糊记忆转成若干可播放、可核对的时间候选，并逐条说明为什么召回、依据来自哪里、还有什么未确定。界面既要让用户感到 Agent 理解了问题，也必须让用户相信回答来自真实画面、对白和时间轴。上传与建库则是另一条长期任务：任何页面都能看到它是否还在进行，点开后可以分清“文件传完了”和“内容已经可检索”。设计需要在“内容的文艺感”“对话的陪伴感”和“证据的可信感”之间取得平衡。用户明确要求干净、简洁、文艺、清新，采用青绿色，并同时提供真正重新配色的日间与夜间模式。

## 产品与受众

- 产品：本地单用户、Anime-first 的事件级视频检索与时间证据定位 Web 产品。
- 第一受众：想快速找回动画名场面、台词、关系变化或情绪片段的动画爱好者。
- 第二受众：评估项目完整度的开源用户、技术同伴与作品集观众。
- 核心价值句：用一句模糊的记忆，找到可以核验与播放的那一刻。

## 输出格式与尺寸

- 三方向各输出一个纯 HTML/CSS/JS 的交互原型。
- 基准画布：桌面 Web，`1440×900`；支持 `1024px+` 桌面与平板横屏自适应。
- 每个方向必须同时实现独立设计的日间／夜间主题，可一键切换并持久化。
- 本轮截图包含 Agent 检索工作台的日／夜模式，以及上传面板和建库流水线，便于同时比较气质与关键流程。
- 方向选定后再将选中语言扩展为全量高保真、完整状态矩阵和窄屏适配。

## 完整功能地图

1. **开始与空状态**：欢迎页、首次导入引导、无动画、无搜索历史。
2. **动画库**：Series 列表、封面／代表帧、已导入集数、建库状态、最近搜索。
3. **导入与上传**：选择本地视频、逐文件字节进度、队列、暂停／恢复／取消、批量校验、剧集顺序确认、重复文件与路径异常。
4. **任务中心**：上传完成后的校验、媒体准备、视频解析、文本／视觉向量与索引同步；包含分集阶段、预计剩余、失败原因、重试与取消。
5. **Agent 对话检索**：Series Scope、连续对话、上下文追问、历史会话、进行中状态、无结果与歧义澄清。
6. **候选与解释**：Agent 按候选展示关键帧、集数、时间戳，以及可核验的选择依据、Text／Vision 证据、反向条件／不确定点和 fallback 信号。
7. **播放与定位**：视频预览、时间轴、跳至证据、前后文、候选切换、复制时间点。
8. **基础设置**：本地存储位置、模型与服务状态、索引状态、主题、诊断信息。
9. **系统状态**：加载、离线、服务启动失败、媒体丢失、索引未就绪、部分结果、权限不足和恢复操作。

## 方向稿共同展示内容

- 动画系列：`BanG Dream! It’s MyGO!!!!!`
- 本地素材事实：仓库存在 13 集视频；当前仅第 7 集具有完整解析与检索样例。
- 查询：`爽世为什么哭着质问大家要演奏春日影`
- 首要候选：第 7 集 `20:52–20:59`，核心对白发生在 `20:56–20:58.5`。
- 证据：长崎爽世看到灯、爱音与立希拥抱后情绪爆发，质问“为什么要弹《春日影》”。
- 明确标记结果为“候选证据”，不展示虚构的绝对置信度百分数。
- 交互状态样例：第 8、9、10 集以三条独立轨道并行上传，分别为 64%、42%、20%；第 11 集以后等待可用槽位。所有数字只用于评审布局，不代表当前系统有真实运行中的上传任务。

## 情感基调与视觉约束

- 关键词：干净、简洁、文艺、清新、安静可信、内容优先。
- 主色为低饱和青绿色；颜色只在动作与时间证据上集中出现。
- 日间模式不是纯白实验室，带微弱纸张与青瓷色温；夜间模式不是 GitHub 深蓝，采用墨绿黑与提高明度的青色。
- 避免卡片墙、过量圆角、全屏渐变、紫色霓虹、emoji 与装饰性图标。
- 图片是内容证据，不是背景装饰；关键帧不得被过强滤镜破坏可辨认性。

## Form 推导五问

1. **叙事角色**：方向稿主画面是“Agent 回答并给出候选依据后的对话工作台”，它必须同时承担追问、结果确认、解释、播放定位和产品价值展示，是整个产品的 hero screen。
2. **观众距离**：主要在约 1 米距离的 13–27 英寸桌面屏幕使用；信息层级应在 1440×900 一屏内可扫读，正文保持 14–17px，关键时间与查询在第一视线区。
3. **视觉温度**：冷静但不冷漠，清新但不幼稚，文艺但不牺牲操作清晰度；日间像雨后书页，夜间像安静放映室。
4. **容量估算**：一屏最多并列三层——导航／候选、主关键帧或播放器、证据详情；二级设置与任务通过视图切换或抽屉承载，避免五列仪表盘式拥挤。
5. **视觉母题**：内容独有的母题是“时间书签”——用户在一部长视频里夹住某个瞬间。青色细线、时间刻度、页签和关键帧共同表达“从记忆中定位一页”，它既属于动画检索，也支撑文艺气质。

## 三个方向的物理隔离锚点

- A · 秒数轮盘第 12 号：Warm Editorial，经用户指定青绿色重新推导为“青瓷札记”；骨架为左侧窄书脊导航 + Agent 对话与候选 + 右侧证据播放器。
- B · 现实参照：Cosmos 的安静策展、搜索与来源信息设计，迁移为“影像标本馆”；骨架为顶部双行对话 + 大图主画布 + 右侧 Agent 解释 + 底部候选胶片。
- C · 顶级定制：以原研哉“白、空与信息退隐”的设计哲学为方法，不复制具体作品；骨架为悬浮文字对话 + 不对称留白 + 纵向时间书签与解释抽屉。

## v3 共用交互原则

- Agent 的解释采用“命中事实 → 证据来源 → 仍需核验”的三层结构；展示的是可复核依据，不是私有思维链。
- 低排序候选也必须解释为什么留下，以及它相对首选缺了什么，不能只给一个模糊的相似度。
- 全局上传提示显示活跃会话数、并行槽位和三条微型进度轨道；进入上传面板后再展示每个视频的独立百分比、暂停／恢复、总体字节进度和阶段说明。
- 上传进度与建库进度使用不同语义。上传字节完成后进度进入新的阶段，而不是直接变成“100% 可检索”。
- 所有进度数值、速度与剩余时间在无法可靠计算时使用“计算中／稳定后显示”，不伪造精确 ETA。
- 并行上传不是“队列中同时选了三个文件”，而是三个独立的活跃上传会话。它们互不阻塞，单个完成后立即进入自己的后续流水线，并释放并行槽位。
- 轨道数量由活跃上传会话决定：两集并行时只显示两条，三集时显示三条；评审图采用三路满载状态检查最拥挤场景。
