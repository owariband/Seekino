## CoT 能查到什么

只读恢复原三轮会话的持久 checkpoint，按 Deep Agents 的 DeltaChannel 还原出 14 条消息；直接读 checkpoint 主字段会漏掉增量消息，因此以还原结果核对。该操作没有执行模型或修改会话。

| 记录 | 核对结果 | 可以支持的结论 |
| --- | --- | --- |
| 模型用量 | 有 input、output、reasoning tokens 和整次调用开始／结束 | 可以比较调用成本与完整耗时；reasoning 是 output 子集，不能重复相加 |
| 原会话 checkpoint | 14 条消息中有 6 条 AI 消息，均未保存 `reasoning_content` | 不能恢复完整 CoT；缺少存储不证明供应商从未返回该字段 |
| 原始 Chat 响应 trace | 未找到；现有 [capture_model_diagnostics](../../../gateway/model_diagnostics.py) 只为带 `video_parse_task_id` 的调用开启磁盘记录 | Parse 的 trace 不能替代 Chat 的响应证据；记录开关不是全链路覆盖证明 |
| 工具请求、反馈及已交付文字 | 能恢复，包括 Q03 的核对请求、实时结果、视频提交和错误反馈 | 可以核对模型实际选择了什么动作、此前已有何种证据，不必等完整 CoT 才排查多余工作 |

此外，[confirm_turn](../../../gateway/agent_model/deepagents.py) 确认最终回答时会用规范正文替换最后一条 AIMessage，因此最终消息本来就不能作为原始模型响应的完整副本。后续需要在模型调用边界记录可用响应字段、用量及时间；供应商确实返回可观察推理文本时再分析摘要。供应商未返回与应用未记录应分开标注。

## Q03 的重复取证有了更直接的证据

在 Q03 提问之前，Q01 已交付给模型的工具结果中包含 74,540–94,720 ms 的老师原话、树叶新闻示例描述、视频与 Chunk 标识。原图也已经进入同一原生会话历史；不只是数据库里有成果。

Q03 的实际动作及新增信息如下：

1. 模型要求重新核对老师原话，并区分课程目标概括与当场说法。这个核对目标合理。
2. 工具再次执行画面观察，耗时 78.411 秒，其中视觉模型为 77.126 秒。前后返回的 `chunks` 完全相同，传入原图的 data URL 内容及其哈希也相同；变化只有 `frames` 中的描述和 `visual_summary`。没有取得新的讲解片段或原图。
3. 模型选择原先已有的 74.54–94.72 秒范围提交视频卡，被 `VIDEO_EVIDENCE_UNAVAILABLE` 拒绝。当前没有正式检索范围，工具仍被提供；反馈又建议检索或调用 `query_video`，并没有直接说明这条观看路径应怎样交付。
4. 模型再经过一轮生成，用文字时间点完成回答。

当前观看提示词会优先引导“当前或刚才讲解”调用实时工具；实时理解取得基础 Chunk 后仍进入画面观察。这些是可以修改和对照的实际执行规则。下一项优先实验应验证：原话与位置已经在历史中时，能否直接给出来源和解释边界；必须看新画面的反例仍要补取证。不能只把“新画面描述不同”当成新增来源，也不能直接将 77.126 秒全部承诺为净节省。

这是 HTTP 问答验收，未新增浏览器点击／渲染检查。FTT 始终为空，未把任何客户端快照计时写成流式首字。两题工作量不同、各只有一个样本，不合并计算中位数。

两次实时工具的总耗时分别是 49.626／112.144 秒；表中模型调用不包含工具的其余工作。新增 2 次用户请求、6 条模型调用记录，共 30,743 tokens。没有新增模型选型或改变配置。

RT05 的主要等待落在画面观察，且该次生成含 2,215 个 reasoning tokens。这使视觉请求的必要性、任务复杂度与推理策略成为值得独立对照的因素；**现有记录没有推理阶段时间戳，不能说 110 秒都是在思考，也不能据此得出模型普遍速度结论。** Q03 复用问题和必须看新画面问题分别验收，不能为提速统一删除视觉能力。

后续可独立推进：换播放位置与证据新鲜度、缺证时的回答、播放定位、刷新／重放／取消，以及 READY 范围可用后的检索。真实流式 FTT 按专门 PRD 验收；这些业务 QA 不以它完成为前置条件。当前继续优先复验已有证据复用和不可成功的工具调用，同时保留确需新视觉证据的质量检查。
