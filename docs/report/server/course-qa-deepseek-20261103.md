## 视觉失败和回答质量

第一轮误用了历史视觉来源，Kimi 指向已经停用的本机代理，实际返回连接拒绝。核对原解析服务正在加载的配置后，只将 QA 的 `model_sources.kimi_coding` 改成现用官方直连来源，Chat 仍是 DeepSeek Flash，冻结配置未改。第二轮请求到达 Kimi，明确返回 **429 / 五小时使用额度耗尽**。系统转为使用已有对白，没有得到有效的暂停帧说明，因此两轮的看帧质量均不能通过。

Q01 能从现有对白识别树叶新闻示例，并将课程目标标为解释；但回复很长，夹带 `partial`、Chunk、`visual_summary` 等内部字段，还提到 02:00 的动作记录。它说明了缺口，却没有完成“核对当前画面并简短解释”的全部目标。已有原帧可确认 01:30 为 LearnGPT 树叶新闻页面，不能拿后面的动作记录补作当前画面的核验。

Q02 两轮均未严格遵守三句话：第一轮有前置解释、编号三点和附加说明；第二轮编号三点后仍增加一段说明。它区分了老师原话与学习解释，但速度通过某个探索阈值不能抵消长度约束失败。

Q03 的“概率系统、同一提示可给出多个回答”可在既有对白约 **47,640–61,180 ms** 核对；模型补充的矩阵乘法与课程目标解释单独列出。本次沿用已有转写与原帧核验，没有重新逐字听音或做词级声学对齐。

## 原片证据已在历史中，仍然重复提交和取证

这次 Chat trace 保存了供应商返回的 `reasoning_content`，已经能检查推理摘要与实际工具动作；完整原文仅留在本机忽略目录，不提交或展示完整 CoT。

第二轮 Q03 的可观察过程是：

1. 模型已识别到历史中有 47,640–61,180 ms 的原话，可直接回答来源问题。
2. 它仍调用 `submit_video_item`，收到 `VIDEO_EVIDENCE_UNAVAILABLE`。
3. 反馈建议重新取得证据，模型随后再次调用 `understand_current_video`；视觉服务仍因额度失败。
4. 它又调用一次 `submit_video_item`，再次失败，最后以文字时间码交付。

这不是缺少 CoT 导致的不可诊断问题。现有工具可用性和重试提示仍把观看证据引向正式检索卡片路径。守卫应保留；下一项对照应验证已有来源能否直接以可回看的时间码交付，并让当前不能成功的提交动作不再被反复尝试。不能把推理字符或 token 数换算成思考秒数。

## 回看、刷新与可靠性

第一轮正文使用“47.6–61.2 秒”，实际没有生成任何时间按钮；第二轮使用 `00:47.6–01:01.2`，实际生成可点击时间点。前端时间识别与 Supervisor 允许“秒或时间码”的输出合同不完全一致，来源交付仍受措辞影响。

对第二轮 Q03 另作无模型调用的浏览器核验：从对话记录打开准确会话，点击来源，将播放器从 **90 秒定位到 47.6 秒**；定位后仍暂停，明确点击“播放视频”后推进到约 48.08 秒。这里通过的是“定位后点击播放”，不能写成自动播放。两轮刷新后消息可恢复，pageerror 均为 0；第二轮持久消息正文与完成事件一致。

真实 HTTP 补测通过：完成请求重放 200 且消息不变；同 key 改 payload 和进行中重放均 409；实际收到 **63 字符可读正文**后取消，终态为 `FAILED/AGENT_CANCELLED`，前缀保留；同会话随后完成“收到”回复，约 1.840 秒。取消回执约 0.006 秒只表示接口确认，不冒充供应商完全停止时间。未 READY 课程的正式检索返回 409，未把缺索引伪装成召回结果。更早的一次取消只保存了 `##`，单独保留，不用于证明可读正文恢复。
