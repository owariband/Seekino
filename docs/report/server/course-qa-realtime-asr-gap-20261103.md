# 课程 QA：已有整片 ASR，观看工具仍称无法核对讲解

用户在 **42:53.152** 提问“现在老师在讲什么？”，页面约 7 秒完成，回答称语音转写没有解析成功，只能依据画面。实际查询证实：同一课程、同一任务已有完整 ASR，结构、结果哈希和媒体身份均校验通过；当前实时工具没有读取它。这是内容交付失败，不能因响应较快而通过。

## 已确认的调用与数据

- 用户会话 `cf7fa5a3-3649-4ce8-a2d1-43c8631e6602`，助手消息 `e67fc643-0df8-4fb3-aa13-38427fd64050`。
- `understand_current_video` 实际调用，耗时 **4.034 秒**。三个 Chunk 覆盖 **41:00–44:00**，都返回 `full Parse requires retry (PARSING_FAILED)`；`partial=true`、`visual_error=null`。这不是一次 Whisper 请求失败，也不是回答所说的前后约六分钟音频都失败。
- `video_parse_content.asr` 已有 **2,476 条转写**，媒体身份匹配，原 Schema 校验和已保存 SHA-256 一致。与播放点之前三分钟 **39:53.152–42:53.152** 重叠的转写有 **62 条**，包含 B/T/C 为 4/8/2 的讲解。
- `ensure_chunk()` 读取 Chunk 成果，父任务失败时直接返回缺证；既不直接读取独立 ASR，也没有只补当前音频窗口的入口。补 Chunk 的正常路径依赖基础 Understanding 任务，不能替代轻量语音取证。
- 当前 `query_hook.enabled=false`；即使启用，现有 Query Hook 遇到 `extra_context.playback` 也会跳过。此次失败不能归因于 Jev 的三类 action。

ASR 来源是现有 `whisper_cpp_local / large-v3-turbo-q5_0 / scope=video`。本次只读校验结果，不假定其所有转写字词都正确。62 条采用区间重叠计数，边界 cue 可能延伸到暂停点之后；正式工具应按实际覆盖裁剪或明确标注，不能把未来讲解当作用户已经听到的内容。

用户本次浏览器没有开启专项 FTT/TT 采证：FTT 未采集，TT 只保留用户贴出的界面约 7 秒，不伪装成毫秒级客户端实测。

## 设计讨论的依据与下一步

建议独立修复实时证据获取：优先读取同一媒体的有效 ASR 窗口；缺少窗口时才抽取播放点之前至多三分钟音频，通过已有 Whisper 适配器补算并缓存。临时证据获取不要求整课任务成功，不重置失败任务，也不将短窗口写成整课 ASR 已完成。原有 Chunk、画面观察仍可组合使用。

路由建议将“需要哪种证据”和“本轮如何处理”拆开：`action` 保留 `respond/retrieve/mixed`，证据来源允许当前播放内容与课程库组合，不增加与三者互斥的 `realtime`。当前观看问题可能同时要求跨课检索；普通解释上一轮回答则不应重新转写。一次决定可表达这些信息，无须先新增两轮串行模型路由。以上是待实施方案，Jev 在线接入及收益没有在本轮验证。

修复后的首个验收应复用本次真实失败位置：同一失败 Parse 状态下，读取已有 ASR 回答当前讲解，新增 Whisper 调用为 0；随后在独立缺证样本上验证局部 Whisper、绝对时间戳、缓存复用、取消与来源回看。问当前内容并要求寻找另一门课的相关片段，应同时完成两类取证。当前原服务保持运行，C28 尚未修复。
