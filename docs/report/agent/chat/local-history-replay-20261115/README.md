# 2026-11-15 本地冻结环境下的三条历史 Chat 回放

日期：2026-11-15（Asia/Singapore）。分支 `perf/chat-local-history-replay`，回放协议见[配置继承 TRD 的“2026-11-15：本地完整历史回放计划”](../../../../design/03-product-reassessment/chat-model-config-inheritance-trd.md)。本文只整理已有指标，不表示已经上线。

## 结论

三条有效用例均完成。服务端 TT 为 30.485／14.138／49.851 秒，正文 FTT 为 25.229826833／12.931963375／47.111925375 秒。完成只是执行终态，3／3 完成不能当作 100% 正确：核心验收仅 T01 的集数和桥上片段得到支持，T02 未对准目标播放位置，T03 没有取到精确目标帧。有效样本 3 条，每条 1 次，不能据此给出总体准确率、p95/p99 或稳定性结论。

环境上，SQL、ES 和视频使用本地冻结副本，共 13 个视频、312 个 chunk、8172 个 event，回放没有使用生产数据库；DeepSeek、JEV 官方 API 和同一云端 embedding 仍是远程模型服务，19 次 embedding 健康探针零失败。Supervisor 固定 Flash／high／8192，JEV only、改写器关闭、100 次模型与工具预算、300 秒观察上限，每 case 1 次、串行。三条各自恢复原请求前历史，互不串联；原生消息数为 26／49／60 条，均保留原 summary。另有 5 条环境无效生成保留在记录中，其中 3 条因索引名与发布凭据不一致，2 条因隧道中断；还有 2 个零生成准备失败，一个缺本地 checkpoint schema，一个缺历史授权记录。它们只用于保留失败样本，不进入有效轮汇总。

数据导出首次退出码为 137，随后改为每页 8 条 ES 文档、gzip NDJSON 流式落盘后完成；这不是 Chat 样本，不计入 Chat TT 或生成用量。

## 时间、token 与角色

有效轮合计 37 次调用、1,151,422 total token（input 1,141,377、output 10,045）。T03 的“其他”是一条 RealtimeVisualObservation。Supervisor 分别为 7／5／12 次，正文首次落在第 5／4／11 次调用；T03 的 `understand_current_video` 工具耗时 9.455 秒。Query 生成均为 0 次。客户端 TT 与服务端 TT 分别记录，不能混为同一口径。三条的 provider 调用都返回 completed，T01 没有工具错误，T02、T03 的错误只有 UNKNOWN_ITEM。reasoning 与 cached input 有部分调用未回报，按缺失保留，不补零。[metrics.json](metrics.json) 给出逐 case 明细；[usage.jsonl](usage.jsonl) 有 97 行逐调用记录，其中包含上述无效轮，合计值不能与有效轮混用。

## 质量核对

T01 能支持核心集数和桥上片段，说明回答至少在这两个关键点上有据可查；但附带提到其他集数的部分，以及每句台词，没有做全面人工验收。因此它算核心验收通过，不是整条回答逐句正确。

T02 的目标播放位置是 1058310ms。实际卡片为 1028500–1039833ms，成功取帧为 1029500／1032500／1035500／1038500ms，卡片和帧都没有覆盖目标，判为播放位置锚定失败。T02 另有 2 次 UNKNOWN_ITEM。

T03 的目标时刻是 1056000ms。成功取帧为 1055062／1056187／1057312／1058437ms，没有目标帧，最近一帧 1056187ms，偏 187ms；实时观察帧为 1056558ms。原片可以回看，但现有证据不能概括为“已经看过精确目标帧”。T03 另有 3 次 UNKNOWN_ITEM。T03 从开始到首正文约 47.1 秒，占服务端 TT 的绝大部分；整轮有 12 次 Supervisor 调用、3 次取帧调用和 1 次实时观察，首正文出现在第 11 次 Supervisor 调用内。这些是同时发生的观测，不能据此认定某一项单独造成慢。这些时间对齐问题说明证据不足，不等于已经证明画面内容错误；现有记录也不含独立画面盲评。三条合计核心验收为 1／3，这只是这三条用例的验收结果，不代表总体准确率。

## 解释边界

本轮 Query 生成均为 0 次，T01 的实际检索由 Supervisor 直接调用工具完成。父子装配参数仍是 1048576 上下文、891289 自动压缩触发、24000 尾部目标；但有效轮没有走 Query，不能把 T01 的成功归因于 Query 压缩修复，也不能说原来的 Query 循环问题已经好了。

三条用例前后 native 摘要事件哈希均未变，支持本轮没有产生新的 Supervisor 摘要。ContextWindowController 正常压缩时不打印日志，所以“没有日志”不能推断“压缩次数为零”。

high 没有做 A/B，不能把 FTT 或 TT 的变化归因于 high，也不能宣称降低 high 一定会更快；T03 的实时观察和工具调用同样没有单独消融。

与旧记录比较也要克制：历史原请求服务端 TT 为 75.659／47.880／88.877 秒；上一轮云端 T01 在 196.567 秒失败，T02 为 17.176 秒（FTT 14.817），T03 为 19.562 秒（FTT 17.577）。本轮 T02 的 14.138 秒、T03 的 49.851 秒只能作描述性比较，不能证明代码导致加速或回退：当前代码、云端库快照、本地 SQL／ES、网络和 cache 均有差异；本地 HTTP FTT 也不等同公网云 FTT。这不是严格单变量 A/B。

被测运行源码来自 `76d20fe6`，包含配置继承修复 `30680fe4`；真实回放在 TRD 首提交 `5182fa76` 后执行。报告集成时 dev 已新增 message feedback，新增反馈接口不在本轮运行覆盖内。五条环境无效结果加上有效轮共有 97 条业务 provider 记录、reported total token 2,565,799；这只统计 Chat 回放，不含元数据 GET、健康检查和独立 Flash 取证／文档 worker。模型与数据原件保存在本机私有目录，没有提交 Git。
