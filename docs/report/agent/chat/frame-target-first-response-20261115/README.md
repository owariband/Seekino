# 2026-11-15：Chat 取帧目标、工具合同与较早回应

本报告关联 [PR #178](https://github.com/owariband/Seekino/pull/178)、[TRD](../../../../design/03-product-reassessment/chat-frame-target-and-first-response-trd.md) 与[工作台](../../../../dev/workbench.html) `CHAT-FRAME-FIRST-01`。失败核查来自既有三条有效历史回放；本次已保留三组各三条完整真实回放；最后一项播放锚点修正被官方402挡住，不能把较早候选的数字标为最终代码或线上效果。

## 完整失败口径

原业务工具完成日志为 24 次／5 次错误；读取完整原生 checkpoint 后，另发现一次执行前参数校验失败，共 **25 次尝试／6 次错误（24%）**。T01 为 9／0，T02 为 5／2，T03 为 11／4；其中抽帧 5 次／3 次错误（60%）。这是三条单次回放的观测，不代表全量服务错误率。实际用户原文、图片、ID、完整历史和 checkpoint 只在本机私有目录；公开材料仅使用场景和匿名片段 C。

| 失败 | 可见调用选择 | 直接原因 | 合同或上下文问题 |
| --- | --- | --- | --- |
| T02-E1 | 直接读历史片段 C | C 尚未在本轮检索注册，UNKNOWN_ITEM | 历史消息仍保留成功证据，本轮宿主注册表却已重建 |
| T02-E2 | 同一模型回复同时发出 C 的区间抽帧 | 同样未注册，尚未执行媒体读取 | 与 E1 共用前提；不能解释为模型看到第一次错误后仍重试 |
| T03-E1 | 沿用历史 C，抽目标附近区间 | C 未注册，UNKNOWN_ITEM | 可见历史证据与本轮工具可用状态不同 |
| T03-E2 | 实时工具已返回 C、available=true 后再次抽帧 | 实时证据不会写入检索注册表，仍 UNKNOWN_ITEM | 跨工具可用性未衔接 |
| T03-E3 | 转向 retrieve 恢复 | 无 cursor 时至少缺失一个必要搜索字段 | JSON schema 未表达运行时条件必填；失败参数在 Gateway 被替换为占位，无法确认原始字段 |
| T03-E4 | 有效 retrieve 返回四个其他片段后仍读 C | C 仍未注册，UNKNOWN_ITEM | 状态错位，也有模型未遵守“实际返回目标 ID”的约束 |

完整对应关系、源码入口和未确定项见 [diagnostics-before.json](diagnostics-before.json)。`UNKNOWN_ITEM` 是当前注册表检查，不代表原视频不存在；随后真正检索返回 C 后，同一 C 抽帧成功。参数失败的 checkpoint 中 `{}` 是归一化占位，不是原始参数的证据。Gateway 在执行前返回该反馈，绕过业务工具 handler 与日志，因此不能仅数业务完成日志。

## 工具成功后的业务缺口

T02 本轮播放位置为 1058310ms，但成功取帧仍在 1029500–1038500ms，最终卡片没有覆盖目标。历史位置为 1037256ms，模型选择旧段与历史锚定相符，但其内部动机没有独立证明。结论可能碰巧正确，取证错位仍不能验收。

T03 工具入参明确指向 17:36，实时执行仍冻结到 1056558ms。视觉摘要又生成“与用户所指相符”的时间判断，宿主没有数值核验；这个判断已作为工具结果回到 Supervisor。后续区间采样是 1055062／1056187／1057312／1058437ms，未请求 1056000ms，却声称精确核验。

区间事件、较早手部事件及稀疏静帧被组合成单帧结论和从17:08持续牵手的说法，还提出未经测量的播放器时间轴偏移。这些属于证据范围扩大或无依据解释；工具已有静帧不能证明连续动作的限制，不能全部归为 prompt 冲突，也不能据时间错位认定所有画面描述均虚假。

Query Skill 的历史 ID 歧义、原生 task 额外入口、submit 的先 read 恢复提示均有问题，但本轮没有进入 Query、没有调用 task、没有触发该 submit 错误分支，不作为上述六次错误的直接原因。

## 实现与验证范围

保留JEV-only和独立改写器关闭。应用模板追加当前轮处理方式，Supervisor沿用分类；简单目标使用最小工具，复杂独立目标或具体缺口才计划和按需Query。同一Agent循环先给一句真实目标确认，再实际取证并接续结论；严格限句或只要最终答案时可省确认。没有新增确认API或固定多Agent流水线。

单点get_video_frame接收绝对整数毫秒，默认当前视频，按授权Series与原片来源直接取一帧，不先检索Chunk；Server校验上传状态、时长、来源身份和缓存指纹。复用媒体与Artifact，不启动Parse／Refine／索引。实际解码PTS未知时为null。区间工具保留并明确均匀中点采样限制。understand_current_video删除不生效的query参数，位置固定为冻结播放点，不再暗示可按任意query选时刻。

条件检索schema表达首次query／top_k／channel_weights必填与cursor续读互斥，沿用原运行时校验。原生task的profile以实际模型注册名匹配，业务query_video保留；既有失败轮未用task，不能把它作为已证明的延迟原因。最新补丁把可信video_id／timestamp_ms作为本轮应用数据放在用户消息旁，不改写原文，不添加模型调用。

本地原片实帧预检：请求1056000ms，返回1张JPEG，人物闭眼微笑的近景与实际图片一致；跨范围拒绝，Parse任务数不变，Chat生成0次。最终组合回归 **808 passed／1 skipped，37.23s**，一条既有Starlette弃用警告。它覆盖Agent、Server接线、来源／权限／缓存、schema和Gateway工具关闭；241／357及早期807的子集或旧版本结果不累加。

## 冻结版本与实验条件

基线a5084c26、初候选cb1e7eb0、收紧提示ab18d93d各恢复T01–T03原始prestate，每条一次、串行，共9条完成请求。相同隔离MySQL／ES／Redis、13集媒体、312 Chunk、8172 Event；各组messages／files／summary源哈希一致，9条摘要事件均未变化。监督模型DeepSeek Flash/high/8192，JEV-only，无独立改写。模型为真实远端调用，不把缓存和网络波动忽略为受控因素。

最后冻结9b03b7ee，T01的JEV成功，DeepSeek生成返回HTTP402 Payment Required，零可见正文、零工具执行，TT2.387s；立即停止，T02／T03未执行。DeepSeek未返回用量，记unknown，不把失败轮纳入完成耗时均值，也不将其视为最终代码效果。准备阶段缺agent_message_feedback表的HTTP500发生在模型生成0次时，仅本地补空表；一项回放启动脚本语法失败也没有生成。所有失败证据保留，没有覆盖旧结果。

FTT是HTTP发出至首条非空正文，可能只是确认。取证后正文FTT按原生非空AI消息与SSE模型完成边界标注，排除确认及重复进度；它衡量开始实质回答，不代表回答内容已经通过正确性验收。TT用服务端totalDurationMs，客户端终止另列。token包括JEV、全部生成和embedding，reasoning已包含在output中，不重复累加。全量用量见[usage.jsonl](usage.jsonl)，未提交私有query、响应、ID、原生checkpoint或凭据。
