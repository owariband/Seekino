## 从命中区间找到完整动作

回看 #77 已发布的 MyGO EP04 v3 原片。事件 `42e49fad645abae8…` 覆盖 15:39.166–15:43.166，爱音举起双臂、把拳头收回脸边、张嘴咬牙再转头。事件 `5aff963dfddc1d28…` 覆盖 15:43.166–15:44.500 的正面反应。在原生帧上，镜头实际于 15:42.900 切到正面，15:43.901 开始叠化。剪辑使用连续的 15:39.188–15:43.901，右端不含。原始帧率为 24000/1001 fps，前 89 帧是中景，后 24 帧是咬牙特写。原片中明显的动作主要发生在中景，特写里嘴形基本保持。

在本机复用上轮 `anime-seg` ONNX 权重。中景里的发光爱音叠在餐桌前，直接给整帧做分割会把背景人物一并保留。这次手动选定画面左侧的 1100 × 900 区域，利用这个镜头特有的明暗差限制蒙版，保留与人物相连的软边，原片底部硬字幕留在选区外。切到正面近景时重置选区，直接分割整帧。两种构图都保留原画布坐标、原帧 RGB 和显示时间戳。头发及手臂的原片白光在个别帧仍会留下浅边。

## 时序、合成与验收

本机输出 113 张全画布 RGBA、113 张灰度蒙版、一条带透明通道的 ProRes 4444 MOV，以及「原片／红底人物」同步对照。在 02 工程的独立副本里把中景人物放到课程卡和旋涡上，再让正面特写接在原来的红底切点。取原成片时间线的 3.20–9.40 秒导出 6.20 秒试剪，配乐取同一时间位置。人物按原始 PTS 播放，最后一帧按原来的沙发切点多保留约 0.07 秒。

每一帧都回到整集原片核对人物可见部分的 RGB 和灰度蒙版。从 MOV 解码透明通道，与 PNG 蒙版逐帧对齐，8 位色阶上的最大误差为 1。对主体区域平均 RGB 变化小于半个色阶的 85 对相邻原帧，人物区域透明度的帧间平均绝对变化中位数为 0.00065，最大为 0.00988（透明度范围 0–1）。这项测量用于检查原画停留时的蒙版稳定性。用浏览器检查导出工程的 186 个画面时刻，记录 Canvas 实际绘制的 PNG，源帧编号 0–112 均按顺序出现。主工作区的 `outputs/verification/ep04-motion-cutout-20261109/` 保存成片、透明素材、原生时间戳、选区、渲染脚本和核验回执。这段 6.20 秒的试剪在投票之后另存。[逐帧和导出核验回执](motion-verification.json)

## 产品边界

Seekino 提供原片、带时间范围的事件及来源证据。角色名可帮助检索，例如用「爱音举起双手再收拳」找镜头。取回片段后，由剪辑 Agent 在自己的机器上选用素材或抠像。上文的框选和亮度约束只记录本次试剪的具体做法。11 月 9 日另在 #77 的工作树试过把选片提示写进 MCP 握手。抠像与合成都在剪辑机上完成。

下一次导演委托可以用下面这段选片提示替换原先的「挑一张带背景的爱音原帧」。

> 当手势或表情变化承载剧情时，回看命中片段和相邻镜头，找到动作从起势到收势的范围。可以直接用这段原片。构图需要单独叠人物时，用你本地的工具保留这一段连续表演。需要强调某一拍时可以定格。

这次样片验证了连续取材和合成可行。本机对比 #77 工作树修改前后的 MCP 握手，只有 `initialize` 返回的 `instructions` 有差异，四个工具的描述和输入输出 Schema 完全相同。MCP 接入与传输测试共 31 项通过。新提示能否让一个没看过目标时间码的剪辑会话自主选用动态表演，仍待单独验证。
