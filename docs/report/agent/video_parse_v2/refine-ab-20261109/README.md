## 首次调用与完成复跑

新加坡时间 12:11，官方 DeepSeek 接口因余额不足返回 HTTP 402。两次 Refine 和随后 18 次 A 组选片都被拒绝，未生成风格卡或首答。这一轮没有质量和费用测量值。之后调整了本地实验脚本，收到第一条 402 就保存回执并停止。[失败轮次](run-deepseek-01/result.json)

12:17–12:21，官方 DeepSeek Flash 完成 2 次制卡和 36 次选片，38 个不同的供应商完成 ID 均有对应的请求摘要。下面列的是看片前定好的评分。两组都找到指定片段或正确放弃，失分主要发生在原片范围和镜头运动的判断上。[逐题结果](run-deepseek-02/score.json) · [调用与用量核对](run-deepseek-02/audit.json)

两道题指出了差异。比较两次角色登场时，有卡组两次都认出了护目镜的逐级硬切，无卡组两次都当成镜内运动。单问字幕出字时，两组都找到了 14.333 秒，有卡组却两次把原片起点从 13.500 秒挪到了出字时刻。两种呈现顺序下，有卡组在双方均答对的题上分别快 22.1% 和 4.8%，未达到两种顺序都快 15% 的门槛。

8 段卡的 16 个引证都落在合法测量点上。卡片指出了 34.333 秒切到护目镜脸部，整理后的运动字段却仍写 `camera:PULL`，最后一个片段也分错了块。3 段版把 3 个输入 ID 扩成 7 条观察，并把卡放在 `members[0].style_card`。补测从原始响应中取出该卡，原样交给 B 组。该组 6 次请求都排在 A 组之后，补测耗时缺少交错顺序对照。[8 段制卡原始响应](run-deepseek-02/calls/E3-refine.json) · [3 段卡的实际位置和取回记录](run-deepseek-02/as-returned.json)

另用已选 ID 回填宿主保存的原片起止，保留模型的切点、排序和运动判断。这样复算后，主实验可用首答变为 A 10/12、B 11/12，补测两组都是 6/6。回填解决了原片边界被改写的问题。上表保留首答原分。[逐题回填](run-deepseek-02/host-range-replay.json)
