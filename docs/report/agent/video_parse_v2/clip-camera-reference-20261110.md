# 从剪辑素材读出镜头，再用代码回放

2026-11-10，分支 `feat/clip-camera-reference`，基线 `2139cbaf`。验证按剪辑素材策略解析后，编辑者能否搜到一次运镜，并用同一条来源事件里的代码和参数重画它。[设计](../../../design/03-product-reassessment/clip-camera-reference-trd.md) · [试点数据](clip-camera-reference-20261110.json)

## 模型怎样描述镜头

四段控制样例由代码绘制，方向、速度、固定机位及切点有已知答案。每段取 12 张图，间隔约 333 毫秒。用正式剪辑 Understanding 提示及 Schema 调用 DeepSeek Flash，推理档位 `none`。每段一次模型调用。宿主把可测量的背景位移作为证据，同一输入上同时记录模型回答与程序核对后的结果。

| 输入 | 模型原始判断 | 核对后的解析 | 模型用时 |
| --- | --- | --- | --- |
| 灯塔向港口，横移一屏 | 向右、缓入缓出 | 向右、缓入缓出，测得 0.994 屏 | 3.15 秒 |
| 反向用同一张画，从港口回灯塔 | 向右、缓入缓出 | 向左、缓入缓出，测得 0.994 屏 | 3.62 秒 |
| 固定机位，仅小船行驶 | 固定 | 固定，未检出全画面横移 | 2.16 秒 |
| 两处固定构图在第 2 秒硬切 | 两段固定 | 分段点在第 2 秒，未检出横移 | 3.07 秒 |

真实样例中，模型写出“镜头持续向右平移，灯塔逐渐移出画面，右侧的栈桥和一艘插着红旗的小船依次进入视野”。遮罩划过、无纹理背景上有物体移动另由确定性反例覆盖。以上样例数不足以估算一般素材的准确率。

## 10 秒灯塔动画的盲测

输入是之前用代码绘制、以 motion-showreel 导出的 1080×1080、60 fps MP4。宿主从编码后的视频抽取 30 张图，仅提供带时间的采样和生产提示。绘图函数和已知横移起止只用于评分。模型认出了先推入邮票，再从左侧灯塔移到右侧港口。Understanding 用时 6.28 秒，却把横移拆成 4.333–5.333 秒和 5.333–6.333 秒两次。分别运行两次缓动会在中间多一次减速和起步。

多处固定背景在 3.667–7.667 秒持续向左移，共一屏。两段描述方向相同且相接，覆盖了完整观测的一半。解析保留了灯塔亮起和船入画的细节，并为整段生成一条向右横移、缓入缓出的运镜参考。一次真实的文本 Refine 用时 4.14 秒，保留了 2.333–3.000 秒的推入和 3.667–7.667 秒的横移。

| 横移指标 | 原片依据 | 回放实测 |
| --- | --- | --- |
| 起止 | 绘图设定为 3.800–7.600 秒 | 比真值早 133 毫秒开始、晚 67 毫秒结束 |
| 行程 | 解码图像测得 1079.999 像素 | 1080 像素 |
| 帧位置 | 独立比对原 MP4 中静止地标，取原运动区间第 228–456 帧 | 229 帧的均方根误差 3.80 像素，最大误差 8.96 像素；取景窗始终向右 |

对照时另外提供真值起止，只检验插值。把区间内首末采样时间拉伸到两端的均方根误差为 41.59 像素。改成在采样时刻经过原位置，边界取邻近帧之间的插值，误差降到 4.70 像素。该对照与自动定位的 3.80 像素使用不同的输入边界。对本片单次本机运行，30 张缩小帧解码用时约 0.41 秒，背景配准约 0.06 秒。没有测整库吞吐或 token 成本。

## 正式读取入口与复核

- 普通视觉 Understanding 和 Refine 的提示会要求描述、保留可见运镜。剪辑事件还给出结构化观测，普通搜索/片段读取接口将其投影成中文 `cameraDescription`。片段详情直接展示时间范围相交的运镜描述，另有字幕和画面概要的素材也能看到。
- 在隔离的 SQLite 数据库里运行实际 Consumer、Understanding、Refine、内容版本发布和证据回源。模型及 ES 边界使用测试替身。外部剪辑工具经 `browse_events → read_evidence` 取得该发布事件的真实采样和模板。另一条测试经检索入口校验词法和语义投影，并由 Node 直接执行工具响应中的 ES 模块，同时覆盖失效引用。
- 证据记录包括源 MP4 摘要、模型原始判断、解析后的中文观测、原片时间和归一化轨迹。用项目模型配置执行 `python -m evals.clip_camera_reference --output /tmp/seekino-camera-pilot` 可重跑四个原创控制样例，这会调用四次已配置的官方模型。纯本地配准、回放、Refine 及读取回归见[领域测试](../../../../tests/engine/parsev2/test_camera_evidence.py)、[Worker 测试](../../../../tests/server/test_video_parse_worker.py)和 [MCP 测试](../../../../tests/server/test_mcp_retrieval.py)。
- 本次定量证据覆盖二维横移。推入、上移等的方向可以记录，倍率或行程使用创作默认值。真实相机的三维姿态、原生帧间的精确曲线、手持和较大视差均未经此试点评定。生产 MySQL/ES 联调、部署及历史库重解析另行验收。

本机通过 814 项相关后端用例、627 项前端用例及生产构建。离线回放页使用原作品的绘图和解析出的横移，在 Chromium 检查了播放、拖动以及取景从左半幅到右半幅。记录到项目工作台时修齐两张旧卡缺失的标签和资料链接格式，页面内置校验通过。
