# 豆包 2.1 Pro non-thinking：单 Chunk 业务质量复核

复核日期：2026-10-29（Asia/Shanghai）。复核已有两轮结果，没有新增模型调用。模型均为 `doubao-seed-2-1-pro-260628`、`thinking.type=disabled`，八次 usage 的 reasoning tokens 均为 0。关联 [首轮报告](parse-protocol-20261029.md)、[精简合同报告](parse-compact-shot-20261029.md)、[解析性能主 TRD](../../../design/03-product-reassessment/video-parse-performance-trd.md)、[B12 已知身份目标](../../../dev/problems.md#b12asr-匿名说话人分组不准refine-看帧后仍未纠正目标归属)。

**结论：本次配置的输出存在会直接影响人物检索、剧情引用和剪辑入出点的业务错误；合同合法、耗时短不足以证明结果可直接交付。** 最明显的是已知画外音的错误归属、跨说话人合并及其时间错位，另有立场误归纳、构图人数错误和画面文字遗漏。

这些证据不证明豆包整体不可用，不证明关闭 thinking 导致错误，也不证明并行调度可以自动纠正内容。它们支持“不把该配置的最快结果作为满足质量要求的通用性能基线”。用户的产品取舍仍为精简 JSON、质量优先、保留既有并行策略，见主 TRD；本报告不重开协议选型。

**归因修正（同日，用户指出）：47 秒目标是共享输入证据不足条件下的确认错误。** 本轮没有音频、转写没有说话人身份，K3 也在同一目标上失败。因此它可用于评估当前输入链路的缺口与错误猜人行为，不能单独用来证明豆包相对 K3 更差或 non-thinking 造成质量下降。下文身份、跨人合并、时间和立场问题可能属于同一错误链，不作为四组独立因果证据叠加。

可靠身份补证可以发生在前置观察或后置 Refine；重复读取同一批帧/无身份文本不等于获得新证据。音色分组提供匿名声源关系，具名角色仍需可信参考或已确认的声音—人物对应；不预设某个声纹补丁必然有效。用户进一步指出，对方的串行 workflow 会将前文上下文传给后块，可以在前向解析中维持人物/剧情信息，不应默认需要独立 Refine。此前独立请求顺序执行不等于这种串行方案；该 case 既不证明并行质量更好，也不证明这种串行方案必须增加音频或 Refine 才能满足其业务。

后续扩展评测按[主 TRD §4.7](../../../design/03-product-reassessment/video-parse-performance-trd.md#47-多片段质量验证计划分开模型能力身份补证与调度)，先建立更长连续序列和多元场景的金标，不以证明某个模型较差为预设目标。

## 明确的业务问题与后果

### 1. 已确认的画外音没有被正确归属

八份均未将目标短句归给爽世。R2 的四份即使每条对白都带姓名，仍全部标为千早爱音。47 秒画面是爱音，目标句却是爽世的画外音；用户确认是身份判据，图像说明画面人物与实际说话人不同，但不能据此确定模型内部的错误机制。

后果是按人物查询台词、引用“某人说过什么”、角色观点总结和人物剪辑均会取得错误证据。例如“找爽世替祥子辩解的那一句”可能漏召回，“爱音替祥子辩解”反而可能被错误支持。这些是错误数据的直接业务风险，本次未向生产索引提交或实际执行检索。

### 2. 跨人合并：人物接话变成一个人的连续陈述

最快的 R2 JSON-2 原文包含：

```json
{
  "start": 43000,
  "end": 46333,
  "type": "dialogue",
  "speaker": "千早爱音",
  "text": "因此让你们伤了心… 也不是小祥的错"
}
```

前半是爱音，后半是已确认的爽世。一个 Event 已经混入两个人，后续只改 speaker 仍无法同时表示两段事实，需要重新拆分与定位。

四次混合区间分别为 R1 XML-1 的 34.333–48.333 s、R1 XML-2 的 34.666–48.000 s、R1 JSON-2 的 38.000–48.333 s、R2 JSON-2 的 43.000–46.333 s。它们会抹掉叙事中的“另一人插话/反驳”关系，影响按说话轮次剪辑。相邻同一人的几句合并不一概算错，本项只统计跨越已确认说话人切换的情况。

### 3. 时间与内容错位：通过范围检查，仍可能剪不到目标句

R2 JSON-2 的混合对白在 **46.333 秒结束**，但目标属于用户确认的约 **47–49 秒**；[47 秒输入帧](../../../../outputs/verification/parse-protocol-compact-shot-20261029/frames/0142.jpg)仍显示目标字幕。

这条 Event 完全满足 `[0,60000)`、整数毫秒和 end > start，仍不能作为可靠剪辑区间。若直接按该 Event 截取，存在漏掉目标句的明确风险。这里不以字幕帧替代声学对齐，不报告精确起止误差或整段时间准确率。

### 4. 身份错误扩散到人物立场与剧情解释

R1 JSON-1 的 34.667–48.333 s 描述写：

> 千早爱音安慰高松灯，认为不是高松灯和丰川祥子的错

紧接着它记录的爱音原句却是“突然退出的人才有问题吧”，而替祥子辩解的短句实际来自爽世。模型将不同角色的立场汇总到同一角色，产生错误剧情解释。

这是第 1 项身份错误的下游扩散，不单独虚构一个统计分母。它说明长摘要/剧本看似流畅也可能改变人物关系；该样本耗时 131.33 秒，错误并不只出现在最快调用中。

### 5. 镜头构图人数错误

R2 JSON-2 在 55.667–59.667 s 写：

> 双人中景，长崎爽世走到台阶前……千早爱音和高松灯看向她

文字已经列出三个人；[58 秒原帧](../../../../outputs/verification/parse-protocol-compact-shot-20261029/frames/0175.jpg)也清楚显示三人同框。把这一整段称为“双人中景”不准确。

这会影响按构图人数找素材或匹配参考镜头。它是明确的局部画面描述错误，不足以宣称三位可见人物的身份普遍认错；本轮更稳定出现的是“谁在说话”判断错误。

### 6. 非对白文字覆盖不稳定

[50 秒帧](../../../../outputs/verification/parse-protocol-compact-shot-20261029/frames/0151.jpg)的购物袋可见 SUNWAY，[58 秒帧](../../../../outputs/verification/parse-protocol-compact-shot-20261029/frames/0175.jpg)的乐器包可见 ESP。两轮 Prompt 均要求保留非对白画面文字，R2 明确提供 screen-text 类型。

- 全部八份原文：SUNWAY 保留 4/8、ESP 保留 2/8，独立画面文字事件 0/8。
- 仅精简轮四份：SUNWAY 保留 3/4、ESP 保留 1/4。
- 仅五份合同通过结果：SUNWAY 保留 2/5、ESP 保留 0/5。

保留在 SHOT/其他正文中仍算事实保留，不能因为没有专门类型就一律判为遗漏。但完全没写出的词会失去对应文本检索线索；只出现在描述中的文字也不便单独按类型过滤。上述是输出覆盖统计，不是实际检索召回率，亦未证明单独 OCR 的增益。

## 已改善的问题和不能夸大的问题

**整批 speaker 缺失已经改善。** R1 XML-1 的 10/10 条对白无 speaker；R1 XML-2 有 2/10 条缺失。R2 四份共 61/61 条对白都有姓名。因此可以说新合同改善了具名覆盖，不能继续用旧轮的整批缺失描述当前精简合同；非空也没有解决目标身份错误。

**动作事实与动作分类分开。** 精简轮仍保留闭眼、低头、手部以及爽世到来/坐下等事实，不能说删字段后全丢动作。但两份没有独立 ACTION，另两份各一条，许多动作混在 SHOT。若下游按事件类型消费动作，这种不稳定会影响使用；纯全文检索不一定完全漏掉这些事实。

**31 秒存在额外身份疑点，尚未纳入确认错误统计。** R1 JSON-1 把“CRYCHIC才解散了”及相关动作主体写为爱音，其他精简输出归给灯；此前场景理解也将其视作灯的自责延续。但同伴输出一致和手部画面不能替代声音真值，本次未新增独立听音标注，保留为待核验，不用它扩大错误数。

**三个合同失败独立记录。** R1 JSON-2 的 speaker 不在 participants 中、R1 XML-2 的同 event 含 action 和 dialogue、R2 JSON-1 的三条 SHOT 多出 description，都会阻止严格接入交付，但不等同于这几段内容全部错误。删除名单后不再把该名单缺失当成新合同质量失败，也没有悄悄修补原文来提高通过率。

## 对产品和架构决策的含义

这批具体错误支持：Seekino 需要把人物归属、轮次/时间定位、可检索画面事实作为质量验收，不能用某供应商的一次短 TT 代替这些标准；选择适合不同用户模型的调度与交付方式具有工程理由。

这批实验没有比较同一豆包模型的 thinking 开关，没有比较质量等价的串行/并行完整链路，K3 也未通过同一个画外音目标。因此不能写成“non-thinking 必然不可用”“并行天然提高语义质量”或“已经证明所有额外架构复杂度都是必要的”。并行的预期收益必须与“实际传递前文、无强制后置 Refine”的串行 workflow 比较。串行前向上下文和并行后的 Refine 是不同的策略组成，不能强制两者相同，再宣布架构公平对照。应统计各自完整质量、墙钟、模型调用、记忆/纠错及维护成本；本报告没有完成这项比较。
