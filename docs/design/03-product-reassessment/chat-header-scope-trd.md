# 1. 问题与现状

分支 `fix/chat-header-scope`，基于已经集成[聊天侧栏 #67](https://github.com/owariband/Seekino/pull/67) 与[设置 #76](https://github.com/owariband/Seekino/pull/76) 的 `dev`。2026-11-08，游客看到“请选择要检索的公开系列”，真正说明没有可用系列的文字却在输入区下方另起一条红色警报。顶栏在 Seekino 字标旁重复展示 Kino，并占用 76px 桌面高度。CPU 截图还出现旧版独立聊天历史浮层，需核对该站实际提供的构建。

# 2. 影响因素与验收口径

| 场景 | 现有行为 | 验收 |
| --- | --- | --- |
| 公开范围暂无可检索系列 | 引导选择，原因在输入区下方 | 状态与范围控件相邻，只显示一次，发送继续受真实范围约束 |
| 顶栏与首页 | 大屏 76px、窄容器 64px，字标带图形 | 目标 64px、56px，字标可返回观看首页，聊天欢迎区中的 Kino 可交互 |
| 独立聊天历史 | 已合入左侧栏，截图仍显示旧入口 | 从 CPU 公网地址新开游客会话，宽屏核对左侧历史，手机核对左侧抽屉 |

# 3. 改造方案

沿用 AppShell 的高度变量和原有导航链接。聊天页根据当前资料来源、目录加载结果及 READY 状态，在系列选择器边上显示空目录状态。已选范围失效和真实读取失败仍提供相应反馈。模型配置、会话创建和选集权限沿用现有接口。

# 4. 对照办法

在当前公开站点记录构建指纹和独立聊天实际布局。在同尺寸浏览器和隔离游客响应中检查修改后的页头、范围提示和发送状态，覆盖公开空目录、未完成解析、可检索和加载失败四种情况。

# 5. 试点

用桌面与 390px、320px 视口检查页头高度、手机按钮尺寸、窄屏换行及侧栏开关。验收不需要付费模型或创建业务会话。
