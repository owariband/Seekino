# 1. 问题与现状

2026-11-09，观看首页切换白天与黑夜时，顶栏和画布立即换色，大片推荐画面和系列缩略图仍维持原亮度，亮度变化集中在画面边缘。复现入口是观看首页的主题按钮，设置页也能切换同一个偏好。[主题入口](../../../web/src/app/theme.tsx) · [观看首页](../../../web/src/features/player/WatchHomePage.tsx) · [封面样式](../../../web/src/features/player/watch.module.css)

工作分支 `fix/theme-transition`，目标分支 `dev`。沿用原有媒体、观看进度和浏览器偏好。[PR #80](https://github.com/owariband/Seekino/pull/80)

## 2. 影响因素、假设与评价指标

假设让页面换色与封面明暗调整同时发生，可以减轻切换时封面边缘的跳变。夜间适度收暗画面，需保留封面细节与推荐区白字的可读性。

| 观察对象 | 当前基线 | 验收方法 |
| --- | --- | --- |
| 顶栏、画布、首页大图及系列封面 | 页面主色直接替换，封面主体亮度固定 | 同一画面双向切换，采样到端点之间的中间值，短动画结束时到达目标主题 |
| 交互与偏好 | 顶栏、移动导航及设置共用主题，刷新读取偏好 | 连点以最后一次输入为准。刷新和减弱动态效果模式直接应用目标外观 |
| 媒体 | 推荐图和上次观看帧均由 PlaybackFrame 提供 | 主题切换前后封面源与 DOM 节点一致，播放页原片色彩保持原样 |

## 3. 改造方案与建模

首页在首屏绘制前读取已存主题，首次使用时跟随系统。之后，顶栏、移动导航和设置沿用 ThemeProvider 切换偏好。根元素的 CSS 属性 `--night-mix` 在 360 ms 内从 0% 过渡到 100%，页面色板、推荐区底部渐变和封面亮度共用这个进度。再次点击直接从当前进度折返。减弱动态效果时直接换色。

首页的 `.heroFrame` 和 `.seriesFrame` 仅包裹海报或预览帧，亮度从 100% 变为 84%。标题和操作按钮单独绘制。实际播放器继续使用原片。[共享色板](../../../web/src/styles/global.css) · [首页封面层](../../../web/src/features/player/watch.module.css)

| 明暗双向切换 | 原版本（每个方向） | 修复后（每个方向） |
| --- | --- | --- |
| 画布、顶栏的中间色数 | 各 0 | 各 20 |
| 推荐及系列封面的中间亮度数 | 各 0 | 各 21 |
| 封面日间 / 夜间亮度系数 | 1.00 / 1.00 | 1.00 / 0.84 |

同一浏览器将视口改为 390 × 844 后，移动导航也触发中间亮度。设置页单选、渐变中反向切换及刷新恢复均通过。开启减弱动态效果后，画布、顶栏与封面的中间值数量均为 0。取样明细和原始截图保存在本机 `outputs/verification/theme-transition-20261109/`。[浏览器回归用例](../../../web/tests/mobile-navigation.spec.ts)

## 5. 试点验证与方案取舍

本机预览使用实际 API 和素材库副本，包含 3 个系列、10 个视频。验证从首页进入正片并切换主题，同一个视频节点继续使用，视频及祖先元素无亮度滤镜。试点只涉及显示，没有触发解析任务。公开游客目录会变化，因此固定素材的前后对照取自本机。
