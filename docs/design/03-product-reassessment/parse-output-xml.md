# Parse 模型输出：无缩进 XML

状态：2026-10-26 协议设计稿。确定采用无缩进、标签与正文分行的表达方向；本文的字段默认规则与转换边界尚未接入生产解析链路。

目标是降低模型生成解析结果的负担，同时保留完整人名、对白原文/译文、动作、参与人物与可见人物等实际信息。模型输出经过解码、确定性整理和领域校验后，转换为现有 `VideoParseResult`，供后续处理使用。

**推荐表达**

只输出 `<timeline>` 根节点；每个事件的开始标签、正文、结束标签分别换行，全部顶格写，属性保持在开始标签同一行。对白正文保持“姓名：台词”，原文等补充子节点另起一行，不增加包装层级。换行用于阅读与流式观察，解析仍以 XML 标签为准。

以下仅演示格式，不是本轮模型实测输出。示例任务默认“主台词为中文译文，原文为日语”；时间统一为原视频绝对整数毫秒。

```xml
<timeline>
<scene start="0" end="60000" participants="高松灯,千早爱音,长崎爽世" visible="高松灯,千早爱音,长崎爽世">
夜晚的户外台阶旁，两人交谈，随后长崎爽世来到并坐下。
</scene>
<dialogue start="0" end="4200" participants="千早爱音,高松灯" visible="高松灯">
千早爱音：你其实很想组乐队吧
<original>本当はバンドやりたいんじゃないの？</original>
</dialogue>
<action start="22200" end="27400" participants="高松灯" visible="高松灯">
高松灯闭上眼睛，低下头。
</action>
<emotion start="22200" end="27400" participants="高松灯" visible="高松灯">
高松灯说“都怪我”，表现出自责。
</emotion>
<screen-text start="50166" end="50501" lang="en" visible="长崎爽世">
SUNWAY SUNWAY
</screen-text>
</timeline>
```

没有译文证据时保留原文，不能为了满足默认显示语言而编造翻译。以日语原文为主文本时，显式覆盖任务默认值：

```xml
<timeline>
<dialogue start="59880" end="60000" lang="ja" role="original">
未知说话人：はい
</dialogue>
</timeline>
```

**常用规则**

1. 每个事件必填 `start`、`end` 和正文；类型由标签决定。保留 `scene`、`dialogue`、`action`、`emotion`、`relation-change`、`screen-text`、`other` 七类，不要求每段都出现全部类型。
2. `dialogue` 正文固定为“完整姓名：完整台词”，按第一个中文冒号分隔。无法确认说话人时使用“未知说话人”。不使用 P0/P1 等人物代号，也不另外重复 speaker 字段。
3. `participants` 和 `visible` 使用英文逗号分隔完整姓名。participants 列出事件已确认的完整语义参与者；对白应包含已确认的说话人和交谈对象，不能省略说话人后依赖程序补入。台词里提到某人或某人出现在画面中，并不自动证明其参与该事件。visible 独立列出该事件期间实际可见的人物，不能根据 speaker 或 participants 自动补齐。人物归属完全无法确认时可省略对应名单；如果正文已给出明确的 speaker，participants 必须包含该人，并通过现有领域校验。
4. `<original>`、`<translation>` 直接声明文本角色，不再给这些子节点重复 role 属性。常见双语对白只需正文与一个另起一行的 `<original>`。需要保留额外语言版本时使用带 lang 的子节点，各自顶格另起一行；有额外的语气、打断等上下文才使用可选 `<note>`。
5. 主台词语言、主台词角色、原文语言由任务上下文提供一次，解码器和提示词必须使用同一配置。EP04 示例为 `zh-Hans / translation / ja`。事件上的 lang、role 仅用于覆盖例外；original 的默认语言来自原文语言配置，额外 translation 子节点必须明确 lang。未知原文语言允许 und；不能凭字符集、是否出现 original 节点来猜测语言角色。
6. 非对白正文直接是事件描述；screen-text 正文直接是可见文字。screen-text 的 lang 可省略，内部表示为未知，而不是让模型猜测。已知语言可以填写。
7. 保留结构换行，取消缩进。解码时忽略标签之间仅用于排版的空白，并移除正文边界的排版换行；正文内部的空格和换行仍需保留。按标准 XML 转义 `&`、`<` 和属性中的引号；根节点和事件必须闭合。截断或缺失正文不能通过补闭合标签伪装成完整结果。

**从模型输出移交给程序的工作**

| 内容 | 处理规则 |
|---|---|
| event_type | 由事件标签映射，不重复生成枚举字段 |
| speaker | 从对白正文的人名读取；“未知说话人”映射为 null |
| participants | 使用模型明确给出的完整参与人物，校验已确认的 speaker 在其中；不把这个字段解释为“其他参与者” |
| persons | 汇总明确的 speaker、participants、visible，去重；不从正文中的所有姓名盲目推断 |
| description | 非对白使用正文；对白使用 note，缺少 note 时使用“姓名：台词”；不要求模型再复述一遍 |
| text_variants | 根据任务默认值、显式例外及 original/translation 标签构造 |
| speaker_source | 由实际执行链路记录，模型不输出 |
| 时间单位 | 合同固定为绝对整数毫秒，不再逐结果重复 unit |
| 时间排序 | 程序稳定排序，模型不承担精确排序；每条时间边界仍须由证据确定并通过范围校验 |
| 空列表与名单去重 | 缺省名单映射为空列表，按明确字段去重；空列表不等于证明“画面无人” |

主要收益来自省去重复内容、派生字段和反复判断的元数据。缩进只是可以省略的排版，不能承诺仅删除缩进就显著加速。

**提示词与验收**

提示词只描述当前 XML 协议、任务默认值和观察职责，提供与解码器一致的样例；不附加旧 JSON Schema 或要求模型解释内部对象映射。输入 ASR/OCR 的数据格式与模型输出协议分别说明，避免把输入字段误当作输出字段。

语法检查、解码和现有领域校验都通过后才能作为解析结果使用。人物归属无法确认时允许空名单或未知 speaker；正文已确认 speaker 时，participants 不得遗漏该人。仍需单独检查人物归属与覆盖率，不能靠少写人物、少写对白来宣称加速。原文/译文的重复 language+role、缺失台词、越界时间及无依据内容仍属于错误。

接入时，提示词、模型调用的输出格式约束、XML 解码器必须同步调整。当前生产 Understanding 使用 Canvas 写入与完成工具，不能只换最终回答 prompt 就声称完成迁移；需在调用边界完成 XML 到领域对象的适配，再对 Refine、Prefix 和下游做兼容验证。本文不改变现有生产调用链，也不表示既有 JSON 工具参数已切换。

范围边界：这份设计针对视频解析的模型表达协议。原始模型文本、解码结果与校验错误应分别留存，内部对象继续承担存储、检索和版本一致性的职责。复测应同时报告首正文时间、正文输出时间、推理/正文 token、完整率和内容覆盖，不能只比较文件大小或一次总耗时。
