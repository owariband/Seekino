# 2. 影响因素、假设与评价指标

决定性因素是按钮外额外渲染的 `small.deleteHint`，而非删除状态错误。既有原生 `title` 已承载同样含义，假设移除重复节点即可满足目标。按钮禁用样式只有透明度与光标规则，未设置 `pointer-events: none`；浏览器悬停行为需结合浏览器验证，DOM 测试仅能验证属性。

| 指标 | 基线 | 目标 | 验证方法 |
| --- | --- | --- | --- |
| 回答中常驻说明节点数 | 源码与截图为 1 | 0 | 现有 App 测试与隔离浏览器页面 |
| 垃圾桶悬停说明 | 已有原生 title | 保留“当前回答进行中，完成后才能删除” | 属性断言、浏览器悬停核对 |
| 回答中删除保护 | disabled | 保持禁用，不能打开删除确认 | 现有交互测试 |
| 回答完成后删除 | 恢复可用 | 恢复可用，title 为“删除对话” | 同一测试完成回答后断言 |

# 3. 改造方案与建模

复用原生 `title`，移除常驻的 `small` 及其专用 CSS。沿用项目既有按钮结构，不新增 Tooltip 组件、状态、事件或依赖。更新现有“回答中不可删除”回归用例，使其断言不存在常驻说明，同时覆盖禁用期间点击和回答完成后的恢复。

展示顺序为：回答开始 → 禁用当前垃圾桶 → 未悬停无常驻说明 → 悬停由浏览器展示既有 title → 回答结束恢复删除按钮与普通 title。删除确认和服务端请求链路保持原有合同。

先在基线上运行更新后的目标断言复现失败，再移除节点和样式；最后运行对话相关测试、类型检查与生产构建。浏览器使用隔离测试响应，不创建真实对话，不触发模型调用。无数据迁移或兼容性变化。
