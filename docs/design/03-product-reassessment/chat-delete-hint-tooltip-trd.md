- 需求：回答进行中的删除说明仅在鼠标悬停垃圾桶时显示。
- 日期：2026-11-13。
- 分支：`fix/chat-delete-hint-tooltip`；目标分支：`dev`；PR：[ #147](https://github.com/owariband/Seekino/pull/147)。
- 当前执行状态统一记录于[工作台](../../dev/workbench.html) `CHAT-DELETE-HINT-01`。
- 上游：[独立对话页布局](chat-sidebar-layout-trd.md)与既有对话管理已在 `dev`，无需等待其他 PR；本次基于 `3d095593`。

当前 `SearchPage.tsx` 的同一套历史列表供独立侧栏和观看页历史弹层使用。当前对话回答进行中，`cannotDelete = current && searching` 禁用删除按钮；按钮已有 `title="当前回答进行中，完成后才能删除"`，但还在列表项下方额外渲染“回答完成后可删除”。截图和源码均能确认这行提示常驻并额外占高，增加了历史列表的视觉干扰。

期望鼠标停在垃圾桶时才提示原因，列表不额外展示这行说明。本次只调整前端展示；保留删除禁用、其他对话删除、删除确认、焦点恢复及请求行为，不涉及后端、模型、配置或数据变更。

# 2. 影响因素、假设与评价指标

决定性因素是按钮外额外渲染的 `small.deleteHint`，而非删除状态错误。既有原生 `title` 已承载同样含义，假设移除重复节点即可满足目标。按钮禁用样式只有透明度与光标规则，未设置 `pointer-events: none`；浏览器悬停行为需结合浏览器验证，DOM 测试仅能验证属性。

| 指标 | 基线 | 目标 | 验证方法 |
| --- | --- | --- | --- |
| 回答中常驻说明节点数 | 源码与截图为 1 | 0 | 现有 App 测试与隔离浏览器页面 |
| 垃圾桶悬停说明 | 已有原生 title | 保留“当前回答进行中，完成后才能删除” | 属性断言、浏览器悬停核对 |
| 回答中删除保护 | disabled | 保持禁用，不能打开删除确认 | 现有交互测试 |
| 回答完成后删除 | 恢复可用 | 恢复可用，title 为“删除对话” | 同一测试完成回答后断言 |

# 3. 改造方案与建模

复用原生 `title`，移除常驻的 `small` 及其专用 CSS。沿用项目既有按钮结构，不新增 Tooltip 组件、状态、事件或依赖。更新现有“回答中不可删除”回归用例，使其断言不存在常驻说明，同时覆盖禁用期间点击和回答完成后的恢复。

展示顺序为：回答开始 → 禁用当前垃圾桶 → 未悬停无常驻说明 → 悬停由浏览器展示既有 title → 回答结束恢复删除按钮与普通 title。删除确认和服务端请求链路保持原有合同。

先在基线上运行更新后的目标断言复现失败，再移除节点和样式；最后运行对话相关测试、类型检查与生产构建。浏览器使用隔离测试响应，不创建真实对话，不触发模型调用。无数据迁移或兼容性变化。

# 5. 试点验证与方案取舍

这是局部、低风险的重复提示移除，代表性的现有集成测试和隔离浏览器检查可替代独立线上试点。检查独立侧栏及共享历史菜单不再有额外说明，悬停目标仍是垃圾桶按钮。收益为减少常驻提示与列表高度；原生 tooltip 的延迟与外观由浏览器控制。

隔离生产构建在本机临时端口 4179 验证，全部 API 由测试响应接管，不创建真实对话或调用真实模型。Chromium 153.0.8010.12 的 1440×1000 桌面及 390×844 手机布局均为 0 个常驻说明；鼠标命中垃圾桶，`:hover=true`、`pointer-events=auto`，title 为“当前回答进行中，完成后才能删除”。禁用点击发出的删除请求为 0，回答完成后按钮启用且 title 恢复“删除对话”，页面 JS 异常为 0，手机页面宽度为 390px。

原生 title 浮层由浏览器控制，本次验证鼠标命中与属性、截图复核常驻说明消失，不声称页面截图捕捉了浏览器原生浮层。未逐浏览器核验浮层外观；未发布到现有开发服务或线上。

# 6. 结果验收与闭环

采用移除重复节点的方案。常驻说明消失、垃圾桶原生 title 保留、运行中删除保护与完成后恢复均取得本地证据，54 项对话测试和生产构建通过。无新增组件、状态、配置、请求或数据迁移。该结论仅覆盖本分支本地实现与隔离验收；`dev` 集成及正式发布通过 PR 跟进，不能据此声称截图中的既有服务已经更新。
