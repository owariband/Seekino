# 1. 问题与现状

2026-11-24，0.2.17 的 macOS 播放器中，320 点宽的 Kino 陪看框分两排放工具，中央展示未配置模型的提示，输入框上方重复整段片名。用户在同一窗口按 ⌘W 未能关闭。[PR #190](https://github.com/owariband/Seekino/pull/190) 的工作分支为 `fix/desktop-companion-window-close`，依赖 [PR #189](https://github.com/owariband/Seekino/pull/189)，先合并上游。

# 2. 影响因素、假设与评价指标

工具栏占用、字号层级、重复文字和浮窗遮住的画面面积会影响观看。用同一段视频、同一窗口尺寸、相同的模型配置截前后画面，量取空状态的尺寸并检查操作能否找到。用聚焦的主窗口和独立帮助窗口分别验证标准关闭命令，检查设置弹层和输入焦点的影响。

# 3. 改造方案与建模

沿用 Seekino 现有文字、颜色、Kino 形象和原生控件。重新安排面板导航、空状态、配置入口和输入区；保留拖动、自动淡化、选集、历史、停靠、附件和问答。检查 macOS 菜单的标准关闭项，通过当前窗口既有关闭路径处理。Windows 继续用自己的窗口约定。

# 4. 对照实验与结果分析

基线为本机安装的 0.2.17。用隔离资料库复现用户截图中的播放器，分别保存修改前后的渲染图。对快捷键使用 Cocoa 窗口和标准按键事件，区分关闭窗口、关闭弹层和退出应用；记录实际命中的窗口与持久状态。

# 5. 试点验证与方案取舍

对候选包检查浅色和深色、宽窄窗口、有无模型与回答、全屏下打开设置、输入和菜单焦点。替换安装前检查当前资料库和任务，保留旧包备份。

在隔离资料库中，签名包完成了未配置模型的配置入口、已有模型的流式问答、选集与键盘切换。打开已有对话时沿用完整阅读高度。对话收到一张原片帧的离线响应后可以继续输入。窗口变窄时沿用既有底部布局。观看设置仍在工具栏上单击可达。

# 6. 结果验收与闭环

83 项桌面与宿主回归通过，另以 Cocoa 运行新增的 macOS 快捷键专项回归，1 项通过。已在本机安装 0.2.18，并核对启动后持有原示例资料库的锁。同片、同时间、同坐标的两版截图用于视觉验收，最终外观由实际使用者判断。

签名归档的原生菜单接受了 AppKit 的 Command-W。聚焦设置中的连接名称时只关闭设置；帮助窗口是活动窗口时只关闭帮助。在普通剧集内定位到 6006 ms，聚焦 Kino 输入框，再按同一快捷键，主窗口关闭。读取测试资料库里的观看记录，视频 ID 和 6006 ms 均一致。系统附件选择框取得焦点时，主窗口的关闭命令被禁用。

macOS arm64 归档完成签名复核，固定响应的导入、解析、检索、回看及问答通过。Windows x64 归档已核对源文件、运行时和 CRC，尚未在 Windows 真机评价此次面板外观。
