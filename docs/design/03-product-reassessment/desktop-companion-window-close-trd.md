# 1. 问题与现状

2026-11-24，0.2.17 的 macOS 播放器中，320 点宽的 Kino 陪看框分两排放工具，中央展示未配置模型的提示，输入框上方重复整段片名。用户在同一窗口按 ⌘W 未能关闭。[PR #190](https://github.com/owariband/Seekino/pull/190) 的工作分支为 `fix/desktop-companion-window-close`，依赖 [PR #189](https://github.com/owariband/Seekino/pull/189)，先合并上游。

0.2.18 把首次连接时的陪看面板缩成短卡片，把聊天和选集合成一个切换按钮。这样虽少挡住一部分视频，却改变了 Web 的布局，两个入口也不能同时看见。本次恢复原来的对话高度、常驻页签和居中 Kino，精简重复片名与表头。另发现一次旧版快捷键验收在写出成功结果后，仍持有测试资料库的锁。

# 2. 影响因素、假设与评价指标

工具栏占用、字号层级、重复文字和浮窗遮住的画面面积会影响观看。用同一段视频、同一窗口尺寸、相同的模型配置截前后画面，量取空状态的尺寸并检查操作能否找到。用聚焦的主窗口和独立帮助窗口分别验证标准关闭命令，检查设置弹层和输入焦点的影响。

布局以同一原片下前后版本的浮窗宽高、两枚页签的可见性和输入区位置衡量。Web 按播放器可用高度计算浮窗，桌面窗口另有原生标题栏。进程验收要观察正常返回、超时和中途取消后的进程组及资料库锁。

# 3. 改造方案与建模

沿用 Seekino 现有文字、颜色、Kino 形象和原生控件。重新安排面板导航、空状态、配置入口和输入区；保留拖动、自动淡化、选集、历史、停靠、附件和问答。检查 macOS 菜单的标准关闭项，通过当前窗口既有关闭路径处理。Windows 继续用自己的窗口约定。

对照 [Web 播放器](../../../web/src/features/player/WatchPage.tsx)，在同一栏保留聊天、选集和播放器操作，给聊天记录和输入框留出固定空间。桌面验收由独立的运行器控制测试时限、终止测试自己创建的进程组并等待退出。

# 4. 对照实验与结果分析

以下先保留 0.2.17 与 0.2.18 的历史对照。基线为当时安装的 0.2.17。用隔离资料库复现用户截图中的播放器，分别保存修改前后的渲染图。对快捷键使用 Cocoa 窗口和标准按键事件，区分关闭窗口、关闭弹层和退出应用；记录实际命中的窗口与持久状态。

| 1080 × 700 点窗口，Micrograd 0:36 | 0.2.17 | 0.2.18 |
| --- | --- | --- |
| 未配置模型的浮窗 | 320 × 408 点 | 320 × 181 点，遮住的面积减少 55.6% |
| 常驻工具栏 | 两行，包括标题、聊天与选集页签 | 一行，包括可拖动的标题、选集、历史、观看设置、停靠和关闭 |
| 普通播放中的提问上下文 | 再显示完整文件名和时间 | 输入区显示时间，悬停可看完整片名 |
| 活动主窗口收到 ⌘W | 原生菜单没有对应项，窗口继续显示 | 「文件 → 关闭窗口」调用已有关闭流程 |

同一原片的同一位置，分别用深浅色和窄窗复核；展开对话和选集仍有完整阅读空间。当时使用的短浮窗默认顶边与展开后的对话对齐，播放画面右下角的讲者恢复可见。后续验收否决了短卡片布局。打开旧包的 Cocoa 窗口后在自己的原生菜单中分发 Command-W，系统菜单返回未处理。对同一设置输入框、帮助和主窗口重复该操作，确认关闭作用于当时的窗口。

旧版的一个独立测试脚本在 18:02 写出快捷键结果，随后在 Qt 隐藏窗口时等待渲染线程。现场等待栈为 `QWindow::hide → QQuickWindow::event → QWaitCondition::wait`。其父进程为 Codex，PID 64069 持有临时资料库锁，采样时物理内存占用 374.5 MB，峰值 561.2 MB。核对命令行后只向该 PID 发出 SIGTERM，并确认退出。

# 5. 试点验证与方案取舍

对候选包检查浅色和深色、宽窄窗口、有无模型与回答、全屏下打开设置、输入和菜单焦点。替换安装前检查当前资料库和任务，保留旧包备份。

在 0.2.18 的隔离资料库中，签名包完成了未配置模型的配置入口、已有模型的流式问答、选集与键盘切换。打开已有对话时沿用完整阅读高度。对话收到一张原片帧的离线响应后可以继续输入。窗口变窄时沿用既有底部布局。观看设置仍在工具栏上单击可达。

在 0.2.19 的同片对照中，1080 × 700 点的原生窗口仍有 42 点标题栏。窗内浮层宽 320 点，高 408 点；同尺寸 Web 独立播放器的浮层高 434 点。两者按各自播放器可用高度的 62% 展开，聊天和选集同时可见。桌面居中显示 Kino；未配置模型时保留一个配置按钮，普通播放的上下文为「第 1 集 · 0:36」。800 × 800 全屏的长片名测试一度将时间挤到 x=1495。给时间预留空间后，片名末尾省略，时间显示在 x=750.5 至 785，距窗口右缘 15 点。

# 6. 结果验收与闭环

0.2.18 的 83 项桌面与宿主回归通过，另以 Cocoa 运行新增的 macOS 快捷键专项回归，1 项通过。已在本机安装 0.2.18，并核对启动后持有原示例资料库的锁。同片、同时间、同坐标的两版截图用于视觉验收，最终外观由实际使用者判断。

签名归档的原生菜单接受了 AppKit 的 Command-W。聚焦设置中的连接名称时只关闭设置；帮助窗口是活动窗口时只关闭帮助。在普通剧集内定位到 6006 ms，聚焦 Kino 输入框，再按同一快捷键，主窗口关闭。读取测试资料库里的观看记录，视频 ID 和 6006 ms 均一致。系统附件选择框取得焦点时，主窗口的关闭命令被禁用。

macOS arm64 归档完成签名复核，固定响应的导入、解析、检索、回看及问答通过。Windows x64 归档已核对源文件、运行时和 CRC，尚未在 Windows 真机评价此次面板外观。

0.2.19 在本机通过 83 项桌面与宿主回归、1 项原生 ⌘W 检查和 3 项验收进程回收测试。让测试工作进程拒绝 TERM 后，分别触发超时、取消和父进程提前退出，三次均确认对应进程组消失。打包应用使用默认 Cocoa/Metal 渲染，两次打开同一隔离库，系统正常退出请求发出后分别在 0.613 秒、0.348 秒返回 0，均释放库锁。此处的退出时间只代表本机这两次试验。

签名归档已在本机安装，原示例资料库正常打开。原生窗口实测拖动、选集、停靠、自动淡化与恢复、浅深色以及窄窗；带原片帧的流式问答使用本地固定响应。签名包另通过固定响应的导入、解析、两种搜索及回看，系统观察器在回看期间未观察到 fork 或 exec。原 ⌘K 测试删除了无用的逐帧回调，在关闭资料库和清理窗口后才写验收结果，回放原测试时正常退出。19:43 复查，只查到一个已安装的 Seekino 进程，持有原示例资料库锁，没有直接子进程，也没有查到上述验收进程。Windows x64 ZIP 已校验，真机外观和操作待验。
