# 1. 问题与现状

需求：按《让创意更有黏性》（hypnos 的笔记 `宣传与粘性.md`，SUCCESs 检查表）重写 Cloud 的欢迎卡片与站内文档，并拆出快速开始等多页文档。提出日期：2026-11-10（Asia/Shanghai）。分支：`feat/sticky-docs-quickstart`；PR：[#92](https://github.com/owariband/Seekino/pull/92)。上游：[Cloud 使用文档 TRD](cloud-user-docs-trd.md)（#89，已合并）。

**背景。** Cloud 推广的目标是让首次访客真的试用，比赛需要真实用户。#89 交付的欢迎卡片和 `/docs` 内容准确，但按 SUCCESs 检查表核对，第一印象抓不住人：

| 原则 | 现状（#89） | 影响 |
| --- | --- | --- |
| 简单：一个核心 | 欢迎卡片同时讲“找回那一刻”“边看边问”和文档链接；`/docs` 第一节是 Cloud / 本地版对比表 | 访客还不知道产品有什么价值，就先读到版本差异 |
| 意外：打开缺口 | 没有反常识的点 | 读起来和其他“AI 视频搜索”没有区别 |
| 具体 | “精确时间范围”“素材库”等抽象词 | 记不住 |
| 可信：可自己验证 | 只有断言 | 不信 |
| 情感 / 故事 | 功能清单 | 不在乎、不行动 |
| 知识的诅咒 | MCP、解析、索引等术语出现在首屏附近 | 新手看不懂 |

核心信息沿用 hypnos 已批准的宣传脚本《Weekend Study》（PR #50）：**“41 小时的课，你要的只是其中一段。”** 41.5 小时为实测（Karpathy *Zero to Hero* 14.6 h + Stanford CS336 26.9 h，ffprobe）。脚本中的“40 秒”仍是占位，文档不写这个数字。

**本次边界。** 只改欢迎卡片文案和 `/docs` 的内容与结构，`/docs` 拆为多页：快速开始、两个版本、部署本地版、接入 Agent、未来计划与交流。不改检索、后端与欢迎卡片的显示规则。交流群链接仍为 `[xxx]` 占位。

# 2. 影响因素、假设与评价指标

假设：首屏只给一个核心、一个可立即验证的动作，访客更可能开始第一次搜索。

| 指标 | 类型 | 标准 | 方式 |
| --- | --- | --- | --- |
| 一个核心 | 结果 | 欢迎卡片只有一个核心句和一个主动作 | 文案评审 |
| SUCCESs 检查 | 结果 | 每页首段都能指出对应的原则落点 | 本 TRD 第 3 节对照表 |
| 事实可验证 | 护栏 | 页面中的数字都有实测来源；没有来源的不写 | 第 3 节事实表 |
| 既有行为 | 护栏 | 前端测试、构建通过；`/docs` 旧链接仍可访问 | vitest、build、路由测试 |
| 首次搜索转化 | 诊断 | 上线后观察；本 PR 不承诺 | 无统计 |

# 3. 改造方案与建模

**页面结构（倒金字塔）：**

| 页面 | 首句（核心） | 主要原则 |
| --- | --- | --- |
| `/docs` 快速开始 | 41 小时的课，你要的只是其中一段 | 简单、意外（倍速也要近 40 分钟）、具体（1.3 秒实例）、可信（问访客自己的经历）、三步故事 |
| `/docs/versions` 两个版本 | Cloud 用来试，本地版用来装你自己的视频 | 简单 |
| `/docs/self-host` 部署本地版 | 一条命令，在自己电脑上跑起完整的 Seekino | 具体 |
| `/docs/agents` 接入 Agent | 测试中，Claude Code 通过 Seekino 在第 4 集里找出 Anon 咬牙切齿的 1.3 秒 | 故事、可信 |
| `/docs/roadmap` 未来计划与交流 | 说出一个名字，列出 TA 出场的每一秒（参考索尼“口袋收音机”：具体、可检验的愿景） | 意外、具体、情感 |

**事实表：**

| 页面中的说法 | 来源 |
| --- | --- |
| 41 小时的课 | 41.5 h 实测（《Weekend Study》事实表）；Cloud 上须两套课程都发布后才成立 |
| 116 分钟的课，3 倍速近 40 分钟 | README 示例课程时长；116 ÷ 3 ≈ 38.7 分钟 |
| 快速开始的召回截图 | 2026-11-10 以 Cloud 游客身份实问“self-attention 是在哪一集哪一分钟讲的”，截取真实回答（`web/public/docs/recall-self-attention.png`）；替换原先的 MyGO 1.3 秒文字记录，因为 MyGO 尚未上 Cloud，访客无法复现 |
| 第 4 集 15:43，1.3 秒（仅“接入 Agent”页） | EP04 `[943166, 944500)` ms，editing TRD E4 实测 |
| 不需要显卡 | 默认 Docker 部署只调用 API 模型（[本地配置指南](../../../deploy/local-setup.md)） |

**欢迎卡片：** 标题即核心句；一句说明（“说出你想找的那一段，我直接带你到原片里的那一秒”）；主按钮“试一句”，次链接“怎么用”指向快速开始。

**实现：** `/docs/:page?` 路由，侧栏（窄屏为顶部横向标签）在页面间切换，切换时滚动回顶部并沿用页面进入动画；内容以按语言的数据块描述。

# 4. 对照实验与结果分析

2026-11-10 用同一份 mock 数据（Cloud 游客身份、两套课程）截图：欢迎卡片（1440px、390px），五个文档页（1440px），快速开始英文深色版与 390px 版。

| 检查 | 结果 |
| --- | --- |
| 欢迎卡片 | 一个核心句、一句说明、一个主按钮（“试一句”）和一个次链接（“怎么用”） |
| 页面结构 | 每页标题即核心句，随后只有一段导语；每页底部给出下一步 |
| 中文标题换行 | 最初在“记得”“列出”中间断行；改为 `word-break: keep-all` 后只在逗号或空格处换行 |
| 示例问法 | 最初画成胶囊按钮，但点击没有反应；改为引语列表，并与检索页已有示例保持一致 |
| Cloud 实测 | “attention 到底在算什么”只给出概念讲解、没有片段，已移除；改为“在哪一集讲的”式问法。召回截图中片段缩略图为灰色占位，回答约 35 秒才出现，一次长问法在 90 秒后中断；录制宣传视频前需先处理 |
| 旧链接 | `/docs` 仍是快速开始；未知页面重定向回 `/docs` |

# 5. 试点验证与方案取舍

低风险的文案与静态页面，以截图评审代替试点；上线后观察首次搜索是否增加需要统计能力（#89 中已决定暂不做）。
