# 2. 影响因素、假设与评价指标

主要因素是供应商依赖、编码输入模态、模型空间身份、视觉缺失时的完成判断，以及
本机推理资源。关闭视觉向量不等于关闭视频理解；只出现在画面中且没有进入文字事实的
内容会失去直接视觉召回能力。

| 指标 | 基线 | 实验验收/观察标准 | 测量方式 |
| --- | --- | --- | --- |
| 本地模型可用性 | 未安装运行栈 | 实际返回有限、非零、归一化的 1024 维向量 | 固定模型版本，真实请求与原始结果 |
| 视觉编码次数 | Chunk 视频及 Event 图片必需 | text 模式严格为 0；不伪造视觉向量 | 抛错型视觉替身及调用记录 |
| 索引与恢复 | 多模态完整性检查 | 文本模式可发布并恢复；多模态缺失视觉仍拒绝 | Engine、Coordinator、真实 ES 定向验证 |
| 中英课程召回 | 未取得同数据对照 | 保存预期片段、实际排名与错误；探索性样本不设泛化门槛 | 实际课程文本和可核对原片时间 |
| 推理延迟与资源 | 本机未测 | 记录冷/热请求、输入长度、模型驻留及失败 | Ollama 请求计时及进程观测；小样本不报可靠 p95 |
| 兼容性 | 旧多模态索引/任务存在 | 默认合同不变，异模型/异模态显式隔离 | 旧测试回归及错误合同拒绝测试 |

# 3. 改造方案与建模

Gateway 新增 `ollama_embedding` 来源，用本地 `/api/embed` 编码文本，不承担课程语义。
随后按用户决定新增 `llama_cpp_embedding`，通过 `/v1/embeddings` 直接连接原生
llama.cpp。`scripts/run_local_embedding.py` 仅启动独立 GGUF 文本推理，固定 last-token
pooling；程序和权重放在独立目录，无需运行 Ollama。保留原适配器供已有配置使用。
模型绑定增加 `input_mode: multimodal | text`（默认 multimodal）和可选
`query_instruction`。文档原文直接编码；查询按模型要求增加检索指令；指令与编码协议
进入 encoder revision。拒绝截断、非法输出和不支持的图片/视频调用。

Server 将模式和指令保存进任务配置。`text` 模式构造没有视觉 encoder、capture 和
visual input 的索引合同；Chunk 与 Event 仅要求词法/语义表示，跳过索引专用抽帧和
图片/视频编码。检索仅启用词法与文本通道；关闭视觉不会影响 OCR、VLM 的解析配置。

```text
课程原片 → 既有 ASR / OCR / VLM → 正式 Timeline（视频、时间、版本）
         → 文本投影 → 本地 Qwen → 文本向量与词法索引
中文问题 → 同模型查询编码 → 召回 → 同版事实核对 → 原片时间范围
```

视觉开关是编码/索引合同的一部分：活动物理索引模式固定，上传不能绕过配置校验随意
切换某个任务。已有任务冻结原模式；换模式或 encoder 使用新物理索引并显式重建，
不能只换查询端。实验保留原业务索引，避免影响已有多模态素材的检索。

失败路径保持现有租约、版本与重试边界：本地服务不可用明确失败，不能标记为空索引
成功；完整性判断按冻结的模式要求全部必需表示；回源与授权不因 text 模式放宽。

# 5. 试点验证与方案取舍

范围是本机小规模课程样本和独立实验索引，不批量提交全部 Karpathy 课程。
样本保留原视频路径、时间区间和转写/投影来源；检查语义命中、时间范围、来源一致性。
若本地输出不稳定、检索合同混用或旧行为退化，先修复对应边界，再扩样。
若视觉细节问题无法从文本召回，则保留该失败，后续比较启用视觉的同样本方案。

本地推理降低远程向量服务依赖，但增加本机服务的安装、驻留和启动维护；视频解析中
ASR/VLM 的成本和耗时不会因此自动消失。
