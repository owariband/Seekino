# 1. 问题与现状

- 需求：独立对话页的左侧历史、居中草稿与简洁输入栏。
- 分支：`feat/chat-sidebar-layout`；PR：[ #67](https://github.com/owariband/Seekino/pull/67)。
- 日期：2026-11-07；当前执行状态见[工作台](../../dev/workbench.html) `CHAT-LAYOUT-01`。

当前 `/search` 通过 `SearchPage.tsx` 展示右上角历史弹层，欢迎区占据剩余高度，输入框固定底部且宽达 880px。用户截图中历史列表遮挡正文，初次提问的欢迎语和输入框相距很远，输入框背景与留白偏重。目标是参考用户提供的 Claude 截图的层级、比例和紧凑度，保留 Seekino 品牌与真实数据。

边界：只改独立对话页的布局与相关可访问性，历史加载、切换、删除确认、流式回复、证据回看均复用现有机制。观看页 embedded 陪看浮窗维持现有交互。既有空对话不删除、不隐藏。

依赖：PR [#66](https://github.com/owariband/Seekino/pull/66) 已合入 dev，继续保持延迟创建合同；本需求基于 `db180245`，不依赖未提交的 Kino 浮窗实现。完成后将本分支代码同步到当前 Kino 预览工作区进行联合验收，Kino 需求仍单独交付。

# 2. 影响因素、假设与评价指标

| 因素 | 现状与假设 | 验收口径 |
| --- | --- | --- |
| 历史入口 | 右上弹层遮挡正文；常驻窄左栏更适合连续对话 | 桌面左栏约 248px，列表独立滚动，正文不被遮挡；窄屏可打开关闭 |
| 空态焦点 | 欢迎区与输入框上下分离 | 欢迎语紧邻居中输入框，首屏直接可输入 |
| 正文可读性 | 880px 正文与输入框偏宽 | 桌面正文及输入框最大约 760px，宽屏也不无限拉长 |
| 发送过渡 | 不能重挂载或导航造成状态丢失 | 首次发送后同一个 textarea 留在 DOM，转为底部输入区；输入失败仍可重试 |
| 可靠性护栏 | 刚修复无操作创建空会话 | 挂载/新建仅草稿；模拟首次发送创建 1 次，重复新建创建 0 次 |

比例来自参考截图的窄侧栏、适中阅读宽度及大留白，不把黄金比例作为固定算法。实际像素、主题效果与移动端溢出在浏览器验收时记录，初稿均待测。

# 3. 改造方案与建模

- SearchPage 保留一套历史列表渲染与处理函数，独立模式置于左侧栏，embedded 模式保留弹层。
- 独立页的居中欢迎区复用 Seekino 原版互动 Kino、像素地面、场景检索引导语及三个示例问题。Kino 位于消息容器内，沿用注视、轻点和闲置 45 秒入睡的互动。
- 独立模式用草稿/对话两种视觉状态：无消息且未发送时居中，发送进行中或已有消息时显示可滚动正文与底部输入区。复用同一个 composer，保留附件、来源选择、取消和键盘操作。
- 输入栏降低边框、阴影与工具视觉重量，独立对话回复输入缩为一行基础高度，多行文字可增高；空态输入区稍宽裕。
- 桌面左栏可折叠，窄屏使用可关闭的覆盖层，并处理 Escape、焦点返回及隐藏内容的键盘访问。
- 按项目 CSS token 支持亮暗主题，减少动效偏好下取消过渡。无新增服务端接口、配置或数据迁移。
