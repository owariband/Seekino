# 1. 问题与现状

分支 `feat/personal-model-connections`，依赖 [#72](https://github.com/owariband/Seekino/pull/72) 的模型设置页和 [#68](https://github.com/owariband/Seekino/pull/68) 的会话选择。当前 PR [#74](https://github.com/owariband/Seekino/pull/74)。管理工作台编号 CHAT-PERSONAL-MODELS-01。

现有设置只列出管理员 YAML 开放的模型。普通用户打开设置无法添加自己的 API 服务，也不能决定请求使用哪种协议、目标地址和模型 ID。目标是从设置完成个人连接配置，在聊天中真正由指定的模型回答。

# 2. 影响因素、假设与评价指标

| 用户操作 | 原状 | 验收依据 |
| --- | --- | --- |
| 配自己的中转或模型服务 | 只能看到服务端名单 | 选择协议、填写任意模型 ID 和自定义 Base URL、保存、编辑、测试及删除 |
| 把个人选择带进聊天 | 会话只有配置文件中的引用 | 新聊天使用个人默认，旧聊天保留选择，服务端按当前用户解析个人引用，直接切模型不创建空聊天 |
| 跨用户、改地址或并发写入 | 尚无个人配置合同 | 归属隔离，密钥不回显，改变凭据目的地需重新指定凭据，冲突保留用户输入 |
| 验证协议 | 看见模型名无法确认调用 | 对可见协议分别核对实际 HTTP 路径、认证、载荷、工具及回复，在集成环境从正常产品入口联调 |

# 3. 改造方案与建模

每个用户可保存多个连接，每个连接可以有多个自定义模型 ID。协议支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 和 Gemini。选择协议提供可编辑的地址示例，保存后立即进入个人候选。设置中的新聊天默认与具体会话的模型分开。

个人配置与当前身份绑定，服务端加密持久化凭据。客户端仅接收连接元数据和是否已有密钥。已有聊天使用稳定个人引用，服务端为本轮解析实际模型、冻结连接参数，复用 Supervisor 的工具和会话历史。局域或本地模型由本机模式访问，云端自定义地址通过受限的出站连接。素材解析和 Query 使用部署配置。用户的聊天入口只展示已保存连接中的模型，空账号提供「配置模型」。草稿没有有效选项时保留输入，发送和上传均等待选模。新对话按个人默认、当前身份和资料来源下最近有效的选择依次解析。历史会话保留消息和绑定，旧平台绑定再次发送前需要由用户改选。

# 4. 对照实验与结果分析

原行为由上游模型页与消息选项可复核。用受控 HTTP 供应商逐协议断言请求，用隔离数据库检验两位用户、重试和编辑冲突。四种协议都从本机生产入口完成 HTTP 回环，逐协议的工具结果回传通过。浏览器对两个模型单独验证连接测试和实际发送，见[验收记录](../../report/web/personal-model-connections-20261107.md)。

# 5. 试点验证与方案取舍

在本机模型设置页手动或浏览器自动化录入一个独立测试服务，核对刷新、选模、请求及返回，清理验收创建的临时记录。保留现有播放器工作树和 API 运行环境。

# 6. 结果验收与闭环

本机 5188 已加载新设置，19641 API 已验证四种协议的探测、真实请求和会话归属。测试记录已清理。验证使用受控 HTTP 供应商，各厂商付费账号未测。集成顺序为 #67、#68、#72、#74，状态见[管理工作台](../../dev/workbench.html)。
