# 1. 问题与现状

分支 `feat/personal-model-connections`，依赖 [#72](https://github.com/owariband/Seekino/pull/72) 的模型设置页和 [#68](https://github.com/owariband/Seekino/pull/68) 的会话选择。当前 PR [#74](https://github.com/owariband/Seekino/pull/74)。管理工作台编号 CHAT-PERSONAL-MODELS-01。

最初的聊天框列出了硬编码的模型。11 月 7 日的试点支持自定义协议并读出了本机 YAML，但网页写入另存 MySQL，已有 YAML 来源无法在页面编辑。cloud 游客也可以请求模型管理接口。目标是让可配置身份从网页直接编辑生效的部署 YAML，同时保留按对话选模和游客问答。

# 2. 影响因素、假设与评价指标

| 用户操作 | 原状 | 验收依据 |
| --- | --- | --- |
| 修改已有或新增的模型连接 | 网页保存与实际文件脱节 | 检查写入后的文件，独立重载后核对模型、来源与默认引用 |
| 旋转密钥或更改地址 | 界面掩码无法证明磁盘与网络的保密性 | 响应无密钥，磁盘无明文，下一次发送使用新密钥 |
| 游客直达接口、历史与流 | 仅判断是否有身份 | 菜单发起零次配置请求，绕过页面直达受限操作得到 403，游客仍能完成问答 |
| 并发修改和旧会话 | 两个后端各自维护状态 | 拒绝过期修订，保留原有 YAML 引用，已完成的消息可重复读取 |

# 3. 改造方案与建模

模型设置由 Server 的 `ModelSettings` 读取 `SEEKINO_MODEL_CONFIG` 指向的文件，按 Gateway 解析后的连接投影到设置页。编辑经过权限检查、文件修订校验和完整配置校验，再更新 `model_sources`、`models` 与 `chat_default_model`。模型与 Agent 参数共用文件锁和原子替换。本机环境变量引用在编辑时可保留，新密钥写为绑定到目的地的 AES-GCM 密文。配置页仅接收密钥是否存在的布尔值。[模型配置](../../model-config.md)

会话保存其模型引用，每轮开始时读取对应的配置快照。命名预设沿用原推理和回退参数，四类自定义 HTTP 协议使用已有的聊天适配器。配置管理按管理员授权，cloud 浏览者可使用服务默认回答，JSON、SSE 和公开接口说明均限制模型信息。旧 SQL 表仅用于历史会话的所有者兼容读取。

# 4. 对照实验与结果分析

原行为由上游模型页与消息选项可复核。用受控 HTTP 供应商逐协议断言请求，用隔离数据库检验两位用户、重试和编辑冲突。四种协议都从本机生产入口完成 HTTP 回环，逐协议的工具结果回传通过。浏览器对两个模型单独验证连接测试和实际发送，见[验收记录](../../report/web/personal-model-connections-20261107.md)。

# 5. 试点验证与方案取舍

在本机模型设置页手动或浏览器自动化录入一个独立测试服务，核对刷新、选模、请求及返回，清理验收创建的临时记录。保留现有播放器工作树和 API 运行环境。

# 6. 结果验收与闭环

2026-11-07 试点核实了四种 HTTP 协议的调用和三个本机 YAML 来源的识别与掩码。当时网页编辑仍写入个人数据库。2026-11-08 改为直接写生效文件，复验覆盖保存与独立重载、旧会话、凭据轮换、访客权限和公开回答。生产 cloud 上线由发布流程验收。集成顺序为 #67、#68、#72、#74。[本次验收](../../report/web/personal-model-connections-20261107.md#yaml-写回与-cloud-权限) · [管理工作台](../../dev/workbench.html)
