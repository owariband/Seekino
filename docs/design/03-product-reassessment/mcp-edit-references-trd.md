# 1. 问题与现状

找到正片表演后，编辑仍得翻参考片才能知道某种手法是否值得借用。#84 的代表片段、风格卡与来源属于同一解析版本；现有 retrieve、browse_events、read_evidence 提供正片事件。编辑需要直接用自己的话寻找参考，并播放返回的原片区间。

分支 `feat/mcp-edit-references`，依赖[参考片解析 #84](https://github.com/owariband/Seekino/pull/84)、[档案 #83](https://github.com/owariband/Seekino/pull/83)。依次合入。沿用[双召回主设计 #50](https://github.com/owariband/Seekino/pull/50)。正片自选区间取片由 [#81](https://github.com/owariband/Seekino/pull/81) 提供，试点集成工作树组合两条链路。

# 2. 影响因素、假设与评价指标

手法说明要有可检索的语义、清楚的原片边界与可看的证据。逐级拉远很容易被误写成镜头内推拉。验收统计固定问题里的首个可用结果、逐帧可指认的切点、来源版本及媒体播放。不同租户、未发布与已替代版本的结果必须为零。

# 3. 改造方案与建模

复用本机 MCP 的身份、访问限制和媒体端点。先限定当前可查参考任务，再在独立 ES 中按自然语言召回；当前 MySQL 观察核实候选后输出景别、切换、区间与直接播放地址。整片卡保留段号供逐段回看。只提供读取，本次的编辑决定和人物分离均在编辑机上完成。

# 4. 对照实验与结果分析

用同一问句在正式 MCP 请求里检索，下载被选中原片并核对每次跃变。检查整片起点、首个切点和每个动作停留区间。测试伪造或过时的 ES 候选以及时间、租户和查无结果的行为。初始结果待测。

# 5. 试点验证与方案取舍

本机隔离实例先验 P5R。单片通过后检查 #81 的实际发现、请求、媒体解码和编辑机上的红底质量，再扩库、启动只拿剧本与工具的新编辑会话。记录用片、耗时、返工，保留片主评分入口。

# 6. 结果验收与闭环

该分支验收标准是编辑能通过正式工具发现一段有来源的手法并逐切回看。端到端结果与未完成的实片、独立编辑和片主盲评分别记录。
