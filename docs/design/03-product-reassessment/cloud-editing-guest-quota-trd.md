# 1. 问题与现状

需求：Cloud 剪辑取片的游客额度。日期：2026-11-12（UTC+8）。分支：`fix/cloud-editing-guest-quota`。PR：[#142](https://github.com/owariband/Seekino/pull/142)。当前状态统一见[工作台](../../dev/workbench.html)。

Claude 正在制作宣传片，取得 3 段素材后下载收到 `QUERY_LIMITED`，另外 9 个镜头已有来源但无法继续取片。用户要求立即放宽限制，恢复剪辑。

源码中 `server/api/media.py:get_video_clip` 与 MCP `retrieve` 都通过 `server/service/access.py:model_query` 预留次数；游客按 IP 共享每日预算，换 Cookie 无法增加额度。报错也可能代表并发占满，不能仅凭错误文案判断日次数已耗尽。`AuthConfig` 默认游客 20 次/日、并发 1，部署样例为 10 次/日、并发 1。

本次只调整已有鉴权环境变量及其部署样例，保留身份签名、CSRF、资料授权、证据版本、60 秒片段上限、Redis 持久计数和全局并发控制。没有媒体、数据库或索引迁移。

# 2. 影响因素、假设与评价指标

关键假设：已有凭据有效，阻塞来自低请求预算或身份/IP 并发；沿用原计数并提高阈值即可接纳旧额度之外的请求。现网具体失败计数尚待核对，不把“下载 3 段”解释为独立的 3 段上限。

| 指标 | 基线 | 目标及验证 |
| --- | --- | --- |
| 游客日请求阈值 | Server 默认 20、部署样例 10 | 部署样例 10,000；核对环境装配 |
| 游客身份/IP 并发阈值 | 1 | 4；保留服务全局容量限制 |
| 已达旧阈值的游客 | 待测 | 同一计数在新阈值下可准入，不删除现网计数 |
| 公网取片 | 用户报告 `QUERY_LIMITED` | 原生 MCP 游客凭据签发、读证据、下载真实短 MP4 成功 |
| 兼容护栏 | 现有鉴权、计数和并发算法 | 仅修改既有游客环境变量，登录用户设置和其他合同保持原值 |

# 3. 改造方案与建模

复用 `AuthConfig.from_environment`，部署样例设置 `SEEKINO_AUTH_QUERY_LIMIT_GUEST=10000`、`SEEKINO_AUTH_CONCURRENT_QUERIES_GUEST=4`。登录用户配置保持原值。无需修改限流算法或用无效的 0 表达无限。

先备份私有环境文件，读取运行容器的完整 Compose 文件列表，核对渲染结果与实际 API 镜像、环境一致。仅重建 API，使用 `--no-deps --no-build --pull never`，保留数据库、索引、Redis、Web 和媒体卷；发现非本次差异则停止并核对。身份验证链及计数键不变，旧会话可直接受益。回退时恢复环境文件并以相同方式重建 API。

# 4. 对照实验与结果分析

采用不涉及算法变更的最小验证：用无网络、无持久卷的临时 Redis 执行现有 `_ADMIT_QUERY`，核对旧阈值拒绝、新阈值接纳及并发拒绝不扣额。运行既有配置回归，并核对部署样例经环境装配得到预期值。未运行完整 Redis 回归，不据此扩大结论。

公开 MCP 验证通过游客身份、协议握手、读取证据和无 Cookie 下载器连续 4 次下载。每次均 HTTP 200，文件为 1920×1080 H.264/AAC、时长 1.001 秒、700,776 字节。令牌、Cookie、签名链接与私有配置原文不进入记录。[验证报告](../../report/server/cloud-editing-guest-quota-20261112.md)记录方法及边界。

| 对照 | 修改前 | 修改后 | 判断 |
| --- | --- | --- | --- |
| 同一隔离计数 20 | 阈值 20 拒绝，重试提示 86,400 秒 | 阈值 10,000 接纳，计数递增到 21 | 已达旧阈值不必重置计数即可继续 |
| 并发护栏 | 游客配置为 1 | 4 个租约准入，第 5 个拒绝，计数不增加 | 保留并发保护 |

# 5. 试点验证与方案取舍

本次为低风险现有配置调整，以真实短片链路和旧阈值准入对照作为试点。提高阈值会扩大可用请求次数；本次游客并发上限为 4，原有全局容量和任务超时继续约束资源。用户已明确批准游客数值及一次 API 重建。没有实测的吞吐、长期成本和完整宣传片制作效果均不作结论。

# 6. 结果验收与闭环

既有环境参数调整及 API 重建已完成，实际加载值和健康已经核对；公开 MCP 4 次真实短片下载通过，隔离对照验证旧计数可在新阈值下继续准入。采用此方案，保留原鉴权和资料权限。完整 9 镜头续剪由原剪辑任务验证，长期负载和成本尚未测量。部署快照、私有备份及运行文件列表仅保留在本机忽略的验收目录与服务器，不进入公开 PR；公开报告只包含配置合同和功能验证。当前状态和下一步仅在工作台维护。
