# 1. 问题与现状

2026-11-23，macOS 原生桌面交付。用户希望从 Finder 打开 Seekino，导入自己的视频，查找想看的台词或画面，再从证据时间跳回原片。Web 版提供了这些主流程的操作参照。PR 1 已在 `dev` 交付可搬移的嵌入宿主，固定模型响应下测过 Python、SQLite 和 FFmpeg 同进程调用。宿主是命令行验证入口，产品还需要原生窗口、连续音画播放和一份可安装的包。 [上游 PR #183](https://github.com/owariband/Seekino/pull/183) · [后端 TRD](macos-desktop-backend-trd.md) · [包内回放](../../report/server/desktop-backend/embedded-host.md)

工作分支为 `feat/macos-desktop-app`，目标分支为 `dev`，依赖已合入的 #183。[桌面交付 PR #184](https://github.com/owariband/Seekino/pull/184)，进度和验收放在工作台。首版覆盖系列与视频、导入、任务、关键词和描述搜索、原片播放与模型配置。桌面 Chat、外部 Agent、云同步和历史 MySQL 库迁入沿用上游约定的后续范围。

# 2. 影响因素、假设与评价指标

应用能加载后端只证明启动可行。桌面体验还取决于导入时窗口能否响应、状态能否在重开后恢复、点击结果能否听见和看见正确的原片位置，以及签名后所有扩展能否继续加载。Web 的资料库、任务状态、时间码和搜索快捷键是操作对照，首轮对照使用同一输入和搜索词。

| 指标 | 基线 | 目标 | 验证 |
| --- | --- | --- | --- |
| 用户闭环 | 嵌入宿主可解出原片帧和音轨 | Finder 启动后能完成配置、导入、解析、搜索、回看 | 空库验收，短片检查画面和音轨，多窗口任务检查恢复 |
| 时间与响应 | Web 结果附整数毫秒区间 | 点击结果直接定位原片，播放和拖动有效，后台解析时窗口可操作 | 带标记短片和 VFR 样片，核对首帧和声音，记录开始播放和拖动时间 |
| 单进程 | #183 固定回复回放观察为 0 个子进程 | 一个 Seekino PID，0 个子进程，0 个业务监听端口 | 用系统观察器跟踪实际 App 的验证路径并检查包内动态库 |
| 安装与升级 | 后端 ad-hoc 验证包 | 发布包独立安装，替换版本后资料库仍可读 | 移动 App、清理开发环境，签名公证后用目标 Mac 验收 |

# 3. 改造方案与建模

macOS 和 Windows 共用 Qt Quick 窗口、交互状态和 PyAV 播放器。窗口从桌面线程直接调用既有 Python 服务。系列、任务和版本仍由后端维护。Mac 用 Application Support 和钥匙串，Windows 用 LocalAppData 和凭据管理器。关闭时等待后台任务释放资料库。

窗口内容以 Seekino Web 的青瓷色、品牌素材、搜索输入区、视频封面与动效为对照。Typora 提供 macOS 布局参考，窗口左上保留系统按钮，标题栏容纳高频操作，可收起的资料树直接展开系列和视频。验收同时看空库、有素材的首页、搜索命中，以及开启系统“减少动态效果”后的切换。 [Web 主题](../../../web/src/styles/global.css) · [Web 首页](../../../web/src/features/player/WatchHomePage.tsx) · [Typora 资料树](https://support.typora.io/File-Management/)

点击结果时 `open_result` 复核来源版本，PyAV 从受管原片的整数毫秒区间解码，Qt 输出图像和 PCM。macOS 使用自建媒体 wheel，Windows 预览使用锁定的 x64 wheel。Windows 编码合同标明 libx264，Mac 库继续识别已有的 VideoToolbox 合同。

# 4. 对照实验与结果分析

使用已知起止的合成片在包内复跑 #183 的固定模型回放和重开搜索。核对同一命中在 PyAV 抽帧路径和原生连续播放器中的时间，保存音画、处理阶段和系统进程证据。随后用配置的模型导入短片和多窗口片，确认真实解析结果和搜索命中。固定模型回放和原生渲染验证已完成。首次试验在 CoreVideo 创建带自定义 IOSurface 属性的视频缓冲区时崩溃，改用默认属性后重新通过。App 从 300 ms 交出画面和 PCM，播放时钟推进后可暂停跳转。实测与边界见 [安装候选报告](../../report/desktop/native/2026-11-23-acceptance.md)。

# 5. 试点验证与方案取舍

先在 Apple Silicon 开发机从独立临时库启动，再把安装候选交给用户在目标机器验收。重点检查权限提示、配置错误、关闭与重开、断网后已有词法索引和原片可用、同库第二宿主与强退恢复。出现时间越界、旧版本证据误播、发布包加载失败或额外进程时，先修复再进入发布。发布签名凭据和干净 Mac 环境在对应环节使用。

# 6. 结果验收与闭环

首轮 SwiftUI 安装候选已构建并通过 DMG 挂载、复制、重开资料库和连续播放验证。Apple Silicon 架构和 macOS 15 部署目标已检查，实际运行环境是 macOS 26.5.1。SwiftUI 界面保留青瓷配色、资料库和任务入口、带时间码的结果卡片，以及点击定位原片的操作。包在观察路径中没有额外进程。首轮验收发现，左栏重复了网页导航，窗口缺少 Web 版的动效；Swift 窗口也不能直接供 Windows 使用。正式分发仍需实际模型、签名公证、目标 Mac、长片体验与跨版本升级验证。 [安装候选报告](../../report/desktop/native/2026-11-23-acceptance.md) · [工作台](../../dev/workbench.html)


0.2.0 用相同宣传片对照 Web 和 Mac 首页，又测试了窄窗口、资料树收放、搜索建议、原片跳转、播放器闲置隐去和减少动态效果。App 和 Windows ZIP 已构建，Windows 仅完成静态核对；用户对视觉与交互的验收仍在进行。 [窗口对照、录屏和安装包实测](../../report/desktop/native/2026-11-23-acceptance.md#020-的窗口动效和安装)
