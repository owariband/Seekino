# 1. 问题与现状

2026-11-24，Seekino 0.2.11 的原生播放器用“全屏 / 退出”文字表示全屏，观看时没有可以点开的 Kino。[桌面首版](macos-desktop-app-trd.md)将 Chat 留给了后续版本。[Web 观看页](watch-kino-entry-trd.md)已经能在播放位置打开陪看窗。此次将本地原片与提问接进同一播放器，分支为 `feat/desktop-watch-kino`（[PR #185](https://github.com/owariband/Seekino/pull/185)），依赖 [桌面 PR #184](https://github.com/owariband/Seekino/pull/184) 的原生宿主和资料库，先集成上游。

# 2. 影响因素、假设与评价指标

| 场景 | 0.2.11 | 本次验收条件 |
| --- | --- | --- |
| 切换全屏 | 按钮显示文字，已有 F 和 Esc | 用图标区分进入与退出，键盘与读屏提示保留 |
| 边看边问 | 视频上没有 Kino | 点 Kino 就能输入；悬浮模式下画幅宽度保持不变；窄窗也能看到输入区 |
| 提问位置 | 桌面未传递播放上下文 | 请求关联当前视频和发送时的整数毫秒位置；换片后旧结果不能出现在新片下 |
| 模型未配置 | 示范库中已有原片及暂停的任务 | 能为观看问答配置模型，既有向量合同和解析任务保持一致；错误须可见 |

# 3. 改造方案与建模

Qt Quick 负责播放器和 Kino 的焦点、窗口布局、全屏状态。Python 从受管原片取得当前时间附近的证据，调用桌面支持的模型协议，在工作线程完成请求。观看问答优先复用可用的模型连接，也允许为问答单独指定视觉模型。钥匙串与 Windows 凭据库继续保管密钥。应用只在用户发送问题时向所选服务提交问题和相应证据。

# 4. 对照实验与结果分析

在同一台 Mac、同一段样片上测试点击、键盘全屏、提问和切换视频。用可控模型回复追踪媒体输入、时间戳、历史与回答的归属。独立检查未配置、失败、全屏层级和小窗输入。外部模型效果与固定回复协议测试分别记录。

# 5. 试点验证与方案取舍

先在示例资料库的副本中测试，再以打包应用打开本机已有示例资料库。观察原片播放、问答、设置和正常退出。Windows 产物另做归档核对，真机窗口按实测范围报告。

# 6. 结果验收与闭环

0.2.12 在 macOS 上用 MyGO 原片验收。浮窗展开时保持 1080 点画幅，手动停靠时画幅缩窄。640 × 440 点窗口改用底部抽屉。播放器、模型地址录入、提交和切片隔离的实测见[安装候选记录](../../report/desktop/native/2026-11-23-acceptance.md)。真实模型输出质量、Windows 窗口和签名公证后的干净系统仍待验收。
