[PR #189](https://github.com/owariband/Seekino/pull/189) 的分支 `fix/desktop-provider-panel-settings` 基于 [PR #188](https://github.com/owariband/Seekino/pull/188)，先合并上游。此次目标是让用户在正在使用的窗口完成这些设置，并验证保存后实际生效。

# 3. 改造方案与建模

对照 Seekino Web 的连接列表、协议选择、用途和保存行为，参考 CC Switch 在同一个新增窗口复用服务表单和选择器的交互。[CC Switch 新增窗口](https://github.com/farion1231/cc-switch/blob/main/src/components/providers/AddProviderDialog.tsx) · [CC Switch 统一表单](https://github.com/farion1231/cc-switch/blob/main/src/components/providers/forms/ProviderForm.tsx)

桌面在「模型服务」中新建具名连接，在「模型用途」为视频理解、转录、嵌入和可选重排选择连接与模型。观看问答支持自己的视觉模型，也可沿用资料库。保存连接和应用模型用途是两个独立动作。更换已绑定连接的地址时，显示该用途实际仍在用的地址，应用后再换。凭据仍由系统保管，资料库只保存非密钥配置。

# 4. 对照实验与结果分析

在同一份隔离资料库中回看命中于 3.3 秒的原片。960 × 680 窗口展开左树后，播放器可用宽度为 778 点。0.2.16 以 778 判定为窄屏，右栏按钮消失，对话占满底部且不会淡化。0.2.17 改按窗口宽度判定。选择悬浮时播放器宽 778 点，对话宽 320 点；选择右栏时两者分别宽 420 和 358 点。实际拖动标题栏后，对话移动了 120 点和 16 点。将淡化等待设为 1.5 秒后实测不透明度降至 0.12，移入标题栏恢复至 1。720 点宽窗仍显示底部对话。

# 5. 试点验证与方案取舍

回归用同一非空 SQLite 资料库、两条 OpenAI 兼容连接和一条 Ark 连接。用 Ark 做视觉和转录，兼容服务做嵌入和独立问答，再单独切换视觉。核对 Gateway 实际解析出的服务凭据和冻结的编码合同。换地址未重新应用时，旧用途继续使用旧地址，单独应用问答后解析仍走旧地址。打开旧配置不会创建新的连接目录文件，已有部署管理的 YAML 保留原有控制权。

# 6. 结果验收与闭环

2026-11-24，macOS arm64。用同一隔离资料库跨三个独立进程复测。先保存右侧栏和 1.5 秒等待，重开后两项仍在；切为悬浮后拖动标题栏，本次关开对话保留坐标。重新启动应用恢复浮窗和 1.5 秒，坐标回到默认位置，与 Web 的会话行为相同。关闭自动淡化后移开鼠标仍为 100%。全局与播放器设置双向同步。

全屏验收发现舞台占用了 Qt 的弹层，导致「观看设置」虽已打开却被画面遮挡。改将全屏视频、证据条和陪看面板放在窗口内容层。实测全屏中打开观看设置、点击自动淡化、进入问答模型、返回输入框，以及选择倍速和打开历史删除确认。已将全屏点击加入回归。

在同一个设置窗口用鼠标和键盘创建 Ark 和 OpenAI 兼容连接，再按用途分配模型，关闭后重开核对。兼容接口返回的模型列表原先以 Python 对象传给 Qt，界面无法列出结果。改用 QVariantList 后，经离线 HTTP 返回的模型可以点选并写进真实输入框。已有配置缺凭据的库从导入流程进入设置，补齐并应用后继续原导入，只生成一次任务。

桌面与本地宿主定向测试共 83 项通过。在打包应用的固定响应测试中，导入、V2 解析、关键词和语义检索、原片取帧、播放和问答通过。另在 macOS Cocoa 窗口中从搜索命中进入原片，打开观看设置和统一模型选择器。Windows x64 归档进行了完整性和源文件校验，Windows 真机交互、Developer ID 公证分发和用户真实模型服务仍待验收。
