# 1. 问题与现状

2026-11-24，Seekino 0.2.16。在 Web 观看页，用户可以在陪看的工具栏切换布局，打开设置就能改淡化等待时间。桌面把秒数放到了应用设置里，陪看工具栏的设置按钮打开的却是另一套模型表单。右侧停靠和拖动标题栏已有代码，此前未从这些设置入口整条验收。

Web 把服务连接、协议和模型用途分开。桌面的解析配置和观看配置各有一份 Ark/OpenAI 表单，使用同一服务时还要理解两套入口。[Web 连接编辑器](../../../web/src/features/settings/PersonalConnectionForm.tsx) · [Web 观看页](../../../web/src/features/player/WatchPage.tsx)

分支 `fix/desktop-provider-panel-settings` 基于 [PR #188](https://github.com/owariband/Seekino/pull/188)，先合并上游。此次目标是让用户在正在使用的窗口完成这些设置，并验证保存后实际生效。

# 2. 影响因素、假设与评价指标

| 操作 | 验收 |
| --- | --- |
| 打开观看设置再改秒数 | 输入有效值、移出浮窗后计时淡化、移回恢复；与全局设置一致，重开后仍在。 |
| 切换右栏或悬浮 | 右栏给原片让出空间，悬浮覆盖原片，可拖动浮窗标题栏。检验宽窗、窄窗、拖动边界和记忆。 |
| 配置模型服务 | 从解析和观看入口进入同一设置窗口。在同一表单内选择服务协议、填写凭据和模型，按用途选用。保留已有模型、凭据和已有资料库。 |

# 3. 改造方案与建模

对照 Seekino Web 的连接列表、协议选择、用途和保存行为。参考 CC Switch 的列表及编辑器入口。桌面使用原生控件，业务动作接入既有桌面宿主。持久化测试用隔离目录和测试凭据；接收人可从表单辨别保存连接与应用到哪种用途。

# 4. 对照实验与结果分析

旧包和候选包在同一台 Mac 的隔离资料库中操作，记录入口、秒数、实际透明度、浮窗及播放器坐标。通过窗口添加两类连接并重新打开，核对不同用途的实际配置。结果待测。

# 5. 试点验证与方案取舍

使用现有版本的资料库与模型配置样例检查兼容。应用包从归档解出后再测试，确认签名、媒体检索与原片回看。Windows 在具备相应环境时进行交互验收。
