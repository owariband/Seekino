# 1. 问题与现状

需求：让剪辑参考素材的模型观察直接进入既有解析链路，移除把检测建议、描述形式和完整性偏好当成失败条件的过度校验。日期：2026-11-12。工作分支：`fix/reference-model-judgment`；集成目标：`dev`；PR：首个 TRD 提交后创建并回填。

上游为 [剪辑参考解析主设计](edit-reference-profile-trd.md) 与 [双召回 #50](https://github.com/owariband/Seekino/pull/50)。本次只改变 `edit_reference` 的模型输出接纳与归属整合，不另建任务系统；与普通 content/clip 解析、鉴权、版本及租约保持原有职责分工。当前需求状态统一维护在[工作台](../../dev/workbench.html)，本文件保存设计、取舍与验收依据。

本机正式上传的“剪辑素材库”包含 P3 Reload、P4、P5R 和五支 Bilibili 素材，使用 DeepSeek Flash high。首轮 8 项中 4 项完成、4 项失败。P4、《人是猫》《快使用恋爱笔记》因 `TechniqueObservation.source_steps` 强制动作步骤使用检测切点并铺满整个片段而失败；P5R 因 PickNote JSON 少最后一个外层右括号而失败。失败视频保留了原片与已提交的 Chunk，未因本轮调查触发重试。

已复现的具体矛盾：

- P4 的 [3517, 4724) ms 片段：Prompt 提供 4379 ms 闪光候选，后两次响应使用该时刻分段；校验器仅允许 4034、4069、4552 和片尾，因此拒绝 4379。三次响应全部被拒绝。
- 《恋爱笔记》的 [171104, 171972) ms 片段：检测切点为空，校验器只允许一整步；模型按可见人物动作拆分多步，三次响应全部被拒绝。
- 《人是猫》的 [97067, 98333) ms 片段：内部检测切点只有 97900 ms，模型描述其他原生帧时刻的动作，同样被拒绝。
- P5R 三次失败响应都能由既有 JSON 补尾函数恢复为合法 PickNote；该函数目前只用于 Refine，逐段观察没有接入。

原始本机证据在 `assets/library/sources/bilibili/p5-additions-20261112/` 的 `tracking-final-summary.json`、`p4-boundary-offline-replay.json`、`remaining-boundaries-offline-replay.json` 与 `p5r-json-offline-replay.json`。这些是本机忽略资产，不把仅存在本机的路径当作 PR 读者已经取得的证据；本次会将必要的脱离媒体、凭据和无关日志的回归样本纳入测试或报告。

源码还存在同类限制：风格卡锚点只允许片段起点或检测切点；有观察就强制要求存在风格信号；Refine 必须返回每个观察且恰好一次。描述枚举、文本长度和列表数量的额外限制将按真实消费方审计，不能把所有 Schema、来源和执行合同一概删除。

# 2. 影响因素、假设与评价指标

问题归属在 Engine 的观察合同及 Agent 的模型响应处理。检测器负责测量和提供候选，模型负责描述画面；检测没有发现切点，不代表没有动作或只有一个动作步骤。Server 继续拥有实际源视频、Chunk、Interval、事务、租约和版本。

| 因素或假设 | 当前证据 | 改造与验证方向 |
| --- | --- | --- |
| 动作边界被错误等同于检测切点 | 三支视频、九次原始响应全部触发同类拒绝 | 移除候选成员、相邻拼接及铺满整段要求；保留正向、源范围内的时间区间 |
| 风格例证可能位于任意原片时刻 | 当前代码只允许检测时刻；本轮尚未出现该阶段失败 | 改为自己片段内的毫秒范围，不强制落在检测候选集合 |
| Refine 输出是对既有观察的补充，漏写不应删除原始观察 | 当前按所有段号恰好一次拒绝整批 | 宿主保留源观察，只应用实际返回的更新，来源之外的引用仍不能进入结果；具体消费点先核对 |
| 其他描述偏好被硬编码为校验 | 审计中，尚未形成实测失败率 | 只去除无调用方依赖的描述性限制，保留结构与真正的资源边界 |
| 完整字段的 JSON 少一个外层括号可恢复 | P5R 三次原响应由既有函数恢复后通过 PickNote Schema | 将同一处理接到 PickNote，不接受任意损坏的 JSON |

| 指标 | 口径与基线 | 目标 | 验证方法 |
| --- | --- | --- | --- |
| 原失败动作响应的接纳率 | 三支素材各三次，0/9 | 9/9，原有文字和动作时间保持原值 | 同一冻结输出和测量事实的修改前后回放 |
| 原 P5R JSON 的接纳率 | 三次逐段响应，0/3 | 3/3 通过 PickNote 结构校验 | 原始响应回放；继续执行来源时间校验 |
| 同类语义限制 | 锚点、信号存在性、Refine 精确覆盖等，新增用例基线待测 | 合法描述、部分更新不触发整片失败 | Engine/Agent/Server 相关回归 |
| 来源及版本约束 | 既有归属、范围、租约和版本检查 | 跨视频、越界、过期版本仍拒绝 | 聚焦的反例测试及已有事务回归 |
| 真实素材任务完成率 | 首轮 4/8 | 修改后试点再测，不能由离线回放推定 | 正式 Seekino 上传/重解析入口、任务与索引状态；保持模型 high |
| 调用、耗时与费用 | 离线回放不产生模型请求；首轮任务记录部分不完整 | 如实记录试点新增调用与耗时，费用缺口标明 | 现有任务、模型用量与日志记录 |

# 3. 改造方案与建模

方向是删除错误的拒绝条件，让模型描述保留其原意；不把描述投影到最近检测切点，不自动改写中文内容或动作时间，不另加“宽松模式”配置，也不包裹通用异常来伪造解析成功。

执行流继续为 Prepare 提供可信测量 → Understanding 接纳模型观察 → 全片 Refine 整合 → 当前版本索引。变化只发生在观察的语义接纳、Refine 对既有来源的更新和同一 JSON 补尾处理。

拟移除或放宽：

1. 动作步骤必须属于检测候选、连续相接、覆盖整段。
2. 风格卡锚点必须等于起点/检测切点，以及有观察就必须有风格信号。
3. Refine 必须把所有原始段完整复述且只能出现一次；改为基于宿主已有来源应用更新，未修改的观察继续保留。
4. 经审计没有实际消费方依赖的描述性白名单、长度或数量门槛。审计结果和最终清单将在实现前后补充，不扩大为整个项目的校验删除。

保留可信来源的 segment ID、原片整数毫秒及左闭右开范围、Chunk/Video 归属、测量事实一致性、存储合同、任务租约/版本、鉴权与索引发布条件。片段之外或不属于本来源的引用仍不能被发布。全局 Consumer 的终止、恢复和并发策略不在本次改造范围；此次减少错误地触发失败的来源。

复用现有 JSON 补尾函数处理只缺一个外层括号的完整响应，随后正常验证必填结构。其他不完整数据仍走既有有限重试和真实失败记录。

不需要数据库迁移；保留既有 JSON 字段和旧成果读取。模型配置与媒体资产不随本次代码 PR 混入。localhost 已单独设为 Flash high、输出上限 50000；既有 8 项仍保存原来的 30000 快照，新上限通过后续新任务生效。

| 对照 | 修改前 | 修改后 | 验收边界 |
| --- | --- | --- | --- |

# 5. 试点验证与方案取舍

离线和相关集成验证通过后，通过 Seekino 的正式任务入口验证本批失败素材，不手工替代产品解析、不改写旧任务结果，不删除成功的四支视频。试点使用本机 development MySQL/ES 与既有素材；明确记录新版本、模型、输出上限和实测结果。部署采用项目已有授权与分支流程，不把本文计划当作额外外部操作授权。

接受标准为合法观察通过、源范围/归属约束有效、任务能提交成果并完成既有索引。若真实运行仍出现其他失败，保留错误并更新本 TRD，不把复现样本接纳率等同于长期稳定性。是否扩展到普通 content/clip 链路需独立证据，不在本次顺带重构。
