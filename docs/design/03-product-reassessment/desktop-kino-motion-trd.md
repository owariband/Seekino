# 1. 问题与现状

2026-11-24，桌面 0.2.15 的观看页可以移动 Kino 入口，却在拖动期间继续播放待机动画。Web 根据指针移动方向切换跑姿，松手后跳起并停靠。桌面此前的验收覆盖了打开问答和引用回看，遗漏了按下到松开的中间帧。

需求分支为 `fix/desktop-kino-motion`，基于[桌面交互延迟 PR #187](https://github.com/owariband/Seekino/pull/187)，合并顺序为上游先行。此次检查观看页、播放进度和聊天中与 Kino 有关的可见交互。原片时间仍按毫秒传递。

# 2. 影响因素、假设与评价指标

以同一版本 Web 的 [播放器入口](../../../web/src/features/player/WatchPage.tsx)、[动作引擎](../../../web/src/shared/kino/engine.ts)和进度控件为对照，分别检查人物的实际像素、手势判定和最终业务动作。仅改变控件的位置无法证明动画正确。

| 场景 | 0.2.15 基线与验收方法 |
| --- | --- |
| 观看页拖动 | 入口移动时仍待机。分别向左、向右、微抖、取消、松手，比较朝向、边缘和落地反应。短按须能打开问答。 |
| 播放器和问答 | 对照指针与时间轴、问答进行和结束时 Web 实际使用的形象，核对取帧、跳转及消息状态。 |
| 动画开销 | 检查隐藏、减少动态效果、键盘操作。沿用现有播放、检索和进程内校验。 |

# 3. 改造方案与建模

共用 Web 的像素动作数据，Qt 承担输入和渲染。播放器和聊天分别向 Kino 提供本地可观测的状态。释放后通过现有偏好保存停靠位置。平台打包继续共用原生组件。

# 4. 对照实验与结果分析

用真实指针事件记录拖动前、转向、松开及落地的状态与图像，同步检查点击和拖动触发的业务动作。结果待测。

# 5. 试点验证与方案取舍

先使用隔离资料库验证 macOS 包的实际交互，然后更新本机安装。Windows 包比对发布内容，实机结论单列。保留升级前的应用用于回退。

# 6. 结果验收与闭环

交付依据包括安装包版本、原生输入结果、直接覆盖修复的测试，以及尚未覆盖的环境。
