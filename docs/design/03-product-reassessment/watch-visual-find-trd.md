# 1. 问题与现状

观看页片内查找当前只返回台词与画面文字。[文字查找设计](watch-text-find-trd.md)与 [文字接口](../../../server/service/media.py) 已有当前视频的访问控制和毫秒跳转。MyGO 第 2 集的原片在 12:56.500 显示千早爱音坐在沙发上看手机，14:07.500 显示她背着吉他包在路上走。两个镜头均有出镜标注，字幕均未提及她。本需求允许用户找到这些画面，也可关闭画面结果。

分支为 `feat/watch-visual-find`，向 `dev` 提交，PR 建立后回填。沿用 [#105](https://github.com/owariband/Seekino/pull/105) 的查找组件和本地已验收的紧凑样式。独立人物工具 [#35](https://github.com/owariband/Seekino/pull/35) 面向跨素材的角色枚举；本次从当前视频的正式事件读取浏览器所需的小范围数据。

# 2. 影响因素、假设与评价指标

| 场景 | 原行为 | 通过条件 |
| --- | --- | --- |
| 只搜出镜人物 | 只查文字原文 | 繁简、姓名短写可命中已标记的镜头；画外提及只落入文字结果 |
| 人物加动作或自然语言 | 当前面板没有画面描述 | 查找已标注动作，语义候选受到当前视频范围和出镜条件约束 |
| 开关与连续输入 | 无此选择 | 默认开启，浏览器记住选择；关闭立即撤销画面结果与在途查询；文字可独立使用 |
| 权限与版本 | 文字读取已发布解析 | 私有视频、其他集及失效数据不得混入；索引缺失仍可搜索已有文字和画面标注 |

# 3. 改造方案与建模

作用对象为已获准观看的单个 `tenantId + videoId`。前端沿用一个输入框与上一处、下一处。打开时独立获取文字；开启画面时读取一次本集视觉事件。输入姓名在已缓存的 `visiblePersons` 上做繁简和空白归一。只有可见人物能支持出镜。连续重复事件在展示时合并。

`GET /api/videos/visual-timeline?tenantId=…&videoId=…` 返回 `{ready,cues:[{startMs,endMs,kind,description,visiblePersons}]}`。数据来自最新已发布的 Timeline。画面描述优先在本集匹配；非纯人名输入暂停后调用 `POST /api/videos/visual-search`，正文为 `{tenantId,videoId,query}`，应答采用同一格式。复用既有事件检索与回源核验，在 SQL 范围选择阶段限制 Video，网络查询沿用访问校验和模型额度。没有独立查询改写步骤。关闭期间不读取画面接口。切集、关闭、改词应中止过期请求。

# 4. 对照实验与结果分析

用同一查询切换开关，比较文字时间戳和新增画面时间戳。构造只有别人说出姓名的反例。检查网络记录、乱序返回、权限变化和索引不可用时的反馈。结果待测。

# 5. 试点验证与方案取舍

在隔离 localhost 上使用 MyGO 第 2 集及浏览器验收，记录实际跳转位置、保留选择、无结果和两种全屏下的可用性。服务端语义调用另以可控检索输入验证范围和真实事件回源；报告实际环境是否具备完整事件索引。两段原片不能推导整库人物召回率。
