# 1. 问题与现状

分支 `feat/settings-workspace`，基线 [#68](https://github.com/owariband/Seekino/pull/68) 的会话模型选择，合并顺序为 #67、#68、本需求。[设置工作区 PR #72](https://github.com/owariband/Seekino/pull/72)。工作台编号 SETTINGS-UI-01。

`web/src/features/settings/SettingsPage.tsx` 把外观、语言、连接和管理员表单排在一页。聊天输入是组件内的草稿，从聊天跳转到设置可能丢失输入。Kino 偏好分散在播放页。希望结合 Chatbox 的分类导航、字段行和场景内设置，让同一个选择仍然写到正确的设备、会话或全局配置中。保留居中 Kino、延迟创建、播放器浮窗、已有权限与保存合同。此轮调整前端，模型连接与密钥仍由当前服务端配置管理。

# 3. 改造方案与建模

借鉴 [Chatbox 设置导航](https://github.com/chatboxai/chatbox/blob/d17455c5ca8fd3ff44385c6d4d2118599e4c970f/src/renderer/modals/settings-navigation.ts) 和[设置行](https://github.com/chatboxai/chatbox/blob/d17455c5ca8fd3ff44385c6d4d2118599e4c970f/src/renderer/components/settings/SettingsLayout.tsx)。沿用 Seekino 的 React Router、CSS Modules、色彩变量与 HTTP 客户端。分类覆盖外观与语言、观看与 Kino、回答模型、连接、管理员运行参数。触屏先显示目录，宽屏并排。聊天中打开设置保留背景路由和草稿，直接访问设置仍可用。模型列表取自服务端，当前聊天通过已有会话 Hook 更改。已有解析快照仍在上传流程中编辑。

# 5. 试点验证与方案取舍

用真实挂载的 React 路由检查设置进出、语言、手机返回、设备偏好和会话选择。用隔离响应测试身份、失败、重试和全局 revision 保存。对照本地 Kino 联合工作树，保留原有未提交改动。供应商模型比较使用脱敏素材。
