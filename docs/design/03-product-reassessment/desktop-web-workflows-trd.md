# 1. 问题与现状

2026-11-24，0.2.12 已经能播放原片和点开 Kino，但观看工作流中断。在同一系列切换两集，第一集的 12 秒被第二集的 32 秒覆盖；片内查找会离开播放器。检索命中无法引用到问答，重开应用也找不回对话。首次导入被解析模型设置拦住，已存在的重解析和删除接口没有桌面入口。分支为 `fix/desktop-web-workflows`，基于[观看问答 PR #185](https://github.com/owariband/Seekino/pull/185)，先集成上游。Web 对照采用 main 的用户操作和 dev 的对应实现。

# 2. 影响因素、假设与评价指标

| 操作 | 0.2.12 实测 | 本次验收 |
| --- | --- | --- |
| 两集各停在不同位置，重开第一集 | 第一集从头开始 | 保留两处播放位置，首页显示最后观看且仍可播放的素材 |
| 本集查找、播放与问答 | 系统查找跳全库；无倍速；关闭陪看仍暂停 | 在原片内定位已发布的文字与画面，可调速，可按发送前状态继续播放 |
| 引用命中并回看对话 | 结果与问答分离，重启会话消失 | 引用有来源和时间，重启可找回；结果与回答按资料库隔离 |
| 导入与管理 | 无模型导入 0 个视频；重新解析及删除仅有业务方法 | 无模型可入库回看；修改、重解析、清理与导出从窗口触达对应服务 |

# 3. 改造方案与建模

保持现有桌面宿主和进程内媒体链路。窗口复用已有角色、任务、检索、媒体和库管理合同，在原生入口适配集号、范围、版本、来源和整数毫秒。观看记录按视频保存，旧格式能保留下来的位置在首次读取时转换。导入、持续的后台解析和问答同步分别呈现进度；重试只在当前任务或连接上下文内生效。删除始终展示实际影响对象并在确认后执行。

# 4. 对照实验与结果分析

用同一批临时素材跑 0.2.12 的复现步骤：保存两集进度，查找本集，点击时间码，从全库结果提问，重开对话。用独立库重复未配置模型的首次导入、管理解析版本与导出。包内模型协议测试用固定响应，另记录真实服务和 Windows 真机的验收范围。

# 5. 试点验证与方案取舍

先用 Qt、SQLite 与原片夹具验收，再在安装包中复查。用户 Mac 安装前检查正在运行的任务，保留现有资料库和可回退的旧应用。两平台使用相同的前端资源与业务源码。

# 6. 结果验收与闭环

初稿。按按钮、快捷键、重开后状态和导出文件逐项检验；用户验收以实际安装包为准。
