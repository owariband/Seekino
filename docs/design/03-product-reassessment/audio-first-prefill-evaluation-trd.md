# 3. 改造方案与建模

当前方案恢复既有B0：只以原非空speaker ID对应的有效音频作为匿名参考，null仅作查询；旧长句编码和评分入口不变，全部166条cue均评分或保留明确未评分原因。ACCEPT／CONFLICT沿用既有预填，证据不足保留原ID，禁止聚合丢弃原非空ID。2/3冻结的有效具名表达直接作为同一B0的参考，对已完成与晚到表达统一评分。下面重新聚类的设计为历史偏离方案，不再作为当前实现。

第一轮：按ASR已知范围建立有界音频窗口，用既有CAM++编码、现有匿名聚类方法生成分组；保留原WhisperX ID作为原始证据，不把它作为真实人物标签。输出匿名分组和逐cue预填，混合范围保留未知及细分声音区间。

第二轮：按原实际提交顺序取16/24份首次理解，给预计算窗口绑定具名表达参考。可复用同模型、同PCM、同精确区间的向量；不同区间不能冒充同向量。复用现有B0评分、目标／同cue／重叠排除和分档，再用真实Canvas构造器验证预填。剩余1/3提交后补齐锚点，完整重评分，区分16块时结果和最终全池结果。

匿名分组与人名评分分别评估；不能用一轮中的人物标签反过来改善另一轮的声学分组，并将其算作ASR后能力。当前先验证决定方向的假设，不修改生产调度、租约、来源快照或ready提交合同。

追加A/B的A组仅将第一轮匿名speaker ID交给新的Understanding，再按原始证据进行新的Refine，不执行具名声纹更新。B组使用同一匿名输入重新运行Understanding；第16个实际成功提交同步冻结当时16块的原始理解内容，随后绑定预计算音频窗的人名参考，对已提交和晚到表达准备具名预填，再让新的Refine消费。后续8块只提供查询，不扩充冻结参考。查询自身、同ASR cue、重叠锚点在绑定前排除，继续沿用原B0评分、分档与实际Canvas。原型不将匿名组ID直接认定为人物。

两组共享同一份抽帧和ASR；模型调用与首次理解答案相互独立，禁止把旧理解或另一组答案导入本组。实验宿主在重叠Refine成员上加本机互斥，使用最新快照提交，避免伪造Server并发／租约验收；分别保存24份首次理解、22个区间提交、实际请求与返回、B组16块来源收据和最终结果。它验证真实模型消费效果，不宣称生产调度接入、数据库恢复、索引完成或端到端产品发布。
