# 3. 改造方案与建模

复用已有 `WhisperXRuntime` 和 `PyannoteDiarizationModel`，以及已授权下载的固定 revision community-1 本地权重。GPU 新部署脚本纳入 `deploy/gpu/`，替换当前未跟踪的 HTTP wrapper；按现有 Gateway 分层实现通用声音证据处理，不在 Server 复制分组算法。

流程：音频 → WhisperX 转写与对齐 → CUDA pyannote 分组 → WhisperX 字词声源分配 → 在有完整证据时按声源切换拆段 → OpenAI 兼容 JSON。GPU 不认人物姓名。接口默认分组，配置/模型失败直接报错；保留显式不分组的基线途径。单请求内串行调度，避免模型并发占用。

优先让 GPU 返回 CPU 已接受的 `speaker_id`，并保留 WhisperX 原生声源字段和字词证据；CPU 是否增加原生 `speaker` 的兼容回退，以真实响应验证决定。Chunk 请求的编号只属于该音频输入，不宣称跨片段一致。跨整集一致性仍按主设计的视频级合同处理。

部署前保存 GPU wrapper 原版与校验摘要，采用本地权重、原环境和 loopback 18844，保留回退路径；不扰动 embedding。先测试纯函数和受控接口，再运行原片样本。CPU 调整先做离线兼容复现，正式服务部署按本轮验证结果记录。
