# 1. 问题与现状

2026-11-25，0.2.19 的「向量嵌入」只能选服务连接。虽然已用 Qwen3 完成一次真实视频验收，用户仍须在应用外启动推理服务。分支 `feat/desktop-local-embedding` 依赖 [PR #190](https://github.com/owariband/Seekino/pull/190)，先合入上游。本次实现见 [PR #191](https://github.com/owariband/Seekino/pull/191)。

# 2. 影响因素、假设与评价指标

首次下载约 639 MB，取消、断网或校验失败时要能重新下载。权重、分词、池化、查询指令和维度共同决定索引兼容性。验证同一文本的编码结果、现有资料库的切换保护，以及应用运行时是否启动推理子进程。

# 3. 改造方案与建模

「向量嵌入」并列提供 API 和本机模型。应用负责在用户数据目录安装并校验固定版本 GGUF，多座资料库可以共享权重。直接加载随包发布的 llama.cpp 库。下载完成后用户保存模型用途，只有选用本机模型的资料库在编码时加载权重；已有 API 配置沿用原绑定。

# 4. 对照实验与结果分析

沿用云端 Qwen3-Embedding-0.6B Q8_0、1024 维与 b12283。将同一问题分别与相关、不相关的段落配对，应用内余弦相似度分别为 0.6459767381 与 0.1590764147，两项和独立 llama.cpp 服务的差都小于 0.000000002。相同编码合同下，约 1000 与 3500 token 的文档均获得 1024 维单位向量。8192 token 上限之外会给出错误。

在 macOS 设置页实际下载、取消并重新下载，最终写入 639,150,592 字节，SHA-256 为 `06507c7b42688469c4e7298b0a1e16deff06caf291cf0a5b278c308249c3e439`。写临时文件、校验长度与 SHA-256、原子替换均在后台线程执行。回归覆盖校验失败重试、设置回显、切回 API，以及权重在开库期间下载完成后恢复消费。

# 5. 试点验证与方案取舍

使用 8 秒的 Seekino 自有宣传片，在隔离资料库通过桌面包内的正式业务入口导入。视频理解使用 `deepseek-flash`，转写调用临时的本机 Whisper tiny.en，向量由同一进程里的 Qwen3 计算。该轮 27.9 秒进入 COMPLETE。SQLite 中有 6 条 4096 字节的语义向量，每条包含 1024 个 float32。关键词「Kino」返回 5 条，首条从 1166 毫秒开始；用中文描述小动物和对话框返回 6 条，首条从 5500 毫秒开始。两种回看均匹配受管原片的摘要和对应首帧。

用重新解压的 `Seekino.app` 再打开该库，原生播放器从 1166 毫秒开始播放音频和画面，通过暂停、跳转、画面抽样与恢复播放校验。系统观察器从宿主第一条指令监测至退出，未出现 fork 或 exec。另一次对照试验能捕获主动生成的子进程。

在第二座隔离库内预置一条待解析任务，启动最终包内的原生 GUI。它自行领取任务，在启动后 26.91 秒进入 COMPLETE，生成 6 个事件和 6 条 1024 维向量。用量记录包括 DeepSeek 3 次、Whisper 1 次、进程内 Qwen3 7 次。内核观察到 0 次 fork/exec，宿主峰值 RSS 为 2,337,603,584 字节（2.18 GiB）。计量范围为原生 GUI 进程，转写使用测试工具独立启动的本机服务。两种查询各命中 6 条。解析完成后验收工具结束测试窗口，另起同一可执行文件核对原片中 [1166, 3166) 毫秒的音画播放、暂停及恢复。

# 6. 结果验收与闭环

0.2.20 macOS arm64 安装包通过解压往返、逐文件核对和 ad-hoc 深度签名验证。实点最终包的设置，两种入口可往返切换，已下载权重可复用。Windows x64 包通过 ZIP 校验、PE 架构与动态库依赖检查，Windows 真机推理与播放待验收。包内均不含模型权重或 llama-server。此次发行候选复用 0.2.19 已验证的运行时，两个平台都保留原有文件。
