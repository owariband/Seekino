# 1. 问题与现状

编辑想问“有没有人物登场时从面部特写逐级硬切拉远的例子”，然后自己查看每个切点。目前普通 clip 只有事件描述；八段 P5R 笔记和整片风格卡由实验脚本产生，上传或重解析无法复现。旧卡还曾将整个候选的起点当作切到脸的时刻，编辑拿到文字仍得从头找。

分支 `feat/edit-reference-profile`，承接[Claude 与 Codex 共同维护的双召回设计 #50](https://github.com/owariband/Seekino/pull/50)。上游 `refactor/parse-profile` 冻结任务用途，合入顺序为档案、解析、只读 MCP。普通上传路由见 [#82](https://github.com/owariband/Seekino/pull/82)，编辑自选正片区间沿用 [#81](https://github.com/owariband/Seekino/pull/81)。

实施 [PR #84](https://github.com/owariband/Seekino/pull/84)，上游[解析用途 #83](https://github.com/owariband/Seekino/pull/83)。

# 2. 影响因素、假设与评价指标

普通稀疏抽帧会漏掉 2–3 帧的亮相动作。代表片段应涵盖不同构图，片内密集变化还可能来自原画换姿。时间窗、切点候选和实际画面含义要分别核对。

| 指标 | 基线 | 试点验收 |
| --- | --- | --- |
| 代表片段和原片时间 | 独立脚本在 P5R 的 31 段中选择 8 段 | 从原片自动重扫、读取原生帧，对照既有记录 |
| 观察、回看与切点 | 手工接线，整片卡出现错误锚点 | 自然语言找到可播放片段，逐次核实景别及帧边界 |
| 版本、隔离和成本 | 正片采用自己的内容索引 | 一次全片 Refine；校验所有引用、成员及版本。记录调用、耗时，空片段不耗视觉调用 |

# 3. 改造方案与建模

沿现有 Prepare → Chunk Understanding → Interval Refine → Index 执行。Prepare 对原片测量画面变化并选择代表；Understanding 读取片内帧并记录可观察手法；Refine 归纳共同用法并引用段 ID。原片区间、所有者与测量由宿主给出。专用检索投影随当前版本发布；原始观察与卡留在既有 Chunk / Interval 成果，提交沿用租约、版本和事务检查。单窗口上限为 63 个块。模板库沿 #50 暂缓。

# 4. 对照实验与结果分析

同一支 P5R 对照预扫描与新 Prepare。比对被选段、实际解码帧、段内切换及来源。保留失败调用与漏判；模型产出的画面解释和程序能校验的时间分开计数。初稿结果待测。

# 5. 试点验证与方案取舍

本机使用独立 MySQL、ES 和媒体目录。先验一支 P5R，通过指定问题的真实回看后，再连接连续动作，最后扩库并交给新编辑。真实片主偏好由片主给出。旧盲选和已知时间只供验收者复核。

# 6. 结果验收与闭环

首次交付记录模型与配置、真实上传版本、代表片段、Refine、索引、检索和源画面。扩库和剪辑增效按真实完成的范围单列。当前为实施前计划。
