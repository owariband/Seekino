# 1. 问题与现状

普通上传 MyGO 需要在同一个 Parse V2 任务中自动选中剧情片策略。课程和已经剪好的 OP、MAD 也要得到各自的解析策略。分支 `feat/parse-pre-hook-router` 承接 [#77 动画召回](https://github.com/owariband/Seekino/pull/77)，以 [#50 双召回设计](https://github.com/owariband/Seekino/pull/50) 和[工作台 COST-01](../../dev/workbench.html) 为依据。两条分支按依赖顺序合入 dev。本 PR 创建后回填链接。

2026-11-09，CPU 的普通上传在完成时即创建解析任务，线上使用 DeepSeek Flash、720p、3 fps，GPU WhisperX 的兼容接口配置为按块转写。#77 只在显式传入 anime 时照顾正片角色表演。把分类仅挂在整片 ASR 回调会漏掉现有 CPU 配置。使用已剪好的视频作为参考还需要 #50 的代表片段和全片参考卡，该设计有单独的验收。

# 2. 影响因素、假设与评价指标

| 指标 | 基线 | 初次验收 |
| --- | --- | --- |
| 默认上传能主动选择类型和策略 | 三类均无自动决策 | 剧情正片、课程、剪辑成片分别得到 script、course、clip，检查真实样本和最终任务快照 |
| 决策能影响实际解析 | 手动配置才能改变提示 | 课程使用 0.5 fps，剧情与剪辑成片使用 3 fps。抽帧、Understanding、Refine 使用同一份持久配置 |
| 显式设置和恢复 | 已接受任务依赖冻结配置 | 显式类型和帧率优先，历史任务保持可读。重试复用已经提交的判断，过期租约不能写入 |
| 决策输入和失败可解释 | 无 | 记录判定来源。限制传给分类模型的文字，对无台词和分类服务失败分别验证 |

片名、系列背景与跨全片抽样的 ASR 是不同证据。动画中的台词不能单独证明原片是正剧，角色剪辑和课程式二创需要结合该文件的用途判断。

# 3. 改造方案与建模

普通上传标记等待判型。Prepare 在已有整片 ASR 可用时使用它，按块转写和无转写配置也有可执行的判型入口。路由读取受限的素材和系列信息，复用 Gateway 已配置的分类能力。分类输入是待分析的数据。Server 在当前租约内原子保存结果、来源和有效帧率，然后把同一配置交给素材准备和解析子任务。

三种内容策略复用既有时间线。剧本或叙事节目重视人物反应和表演边界，课程重视知识点、板书和画面操作，剪辑成片重视原片中实际可见的镜头切换、字卡及构图变化。正式的 edit_reference 结果合同、代表片段索引、全片风格卡仍按 #50 独立交付。显式 anime 档案继续支持。保留现有分块、索引合同和任务版本，无表迁移。

# 4. 对照实验与结果分析

使用相同源片信息和部署配置比较无自动策略、显式策略和默认上传。覆盖有整片转写、CPU 按块转写、无对白，以及历史配置和显式覆盖。检查任务提交、子任务领取和过期租约。真实分类与替代模型的流水线测试分开记录。当前自动分流结果待测。

# 5. 试点验证与方案取舍

用 MyGO EP04、课程与 Persona/爱音参考片对照，记录输入、决策、模型来源和使用范围。复用 #77 的 EP04 原片与语义召回作为已知的显式策略基线。发布试点验收点是用户无需提供类型的新任务。CPU 模型连通、dev 合并与实际生产部署分别记录。

# 6. 结果验收与闭环

合入 dev 前核对普通上传路径到实际的准备、Understanding 和 Refine，确认三个路由、显式优先和恢复保护。模型效果、失败样本与生产发布状态在试验后回填。
