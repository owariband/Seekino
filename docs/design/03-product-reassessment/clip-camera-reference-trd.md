# 1. 问题与现状

剪辑师希望在 Seekino 中找到一段“沿海岸丝滑向右移，小船从右侧入画”的素材，并让创作 Agent 把同一种运镜用在另一幅画上。分支 `feat/clip-camera-reference`，目标 `dev`。PR 创建后回填。依赖已合入的 [上传路由 #82](https://github.com/owariband/Seekino/pull/82) 与 [事件检索 #77](https://github.com/owariband/Seekino/pull/77)，承接 [剪辑参考主设计 #50](https://github.com/owariband/Seekino/pull/50)。

在基线 `2139cbaf`，自动或显式选为 `clip` 的素材会收到记录切镜、构图、字卡与时间范围的提示。普通事件只有自然语言描述和来源时间，显式提交 `camera_ref` 会被 Schema 拒绝。实验中的 `PAN` 标签和灯塔片可执行的 `cameraAt` 尚未连接到正式素材。只追主体容易看反方向，复制角色停帧会把平滑的镜头做成卡顿。

# 2. 影响因素、假设与评价指标

| 指标 | 基线 | 目标与验证条件 |
| --- | --- | --- |
| 可描述和召回 | 构图文字可记录，方向、速度、起终取景随模型发挥 | 对同一段视觉证据，要求说出镜头方向、起终可见内容、运动节奏和判断依据。用静止背景上运动的主体、硬切和证据不足做反例 |
| 可复现 | MCP 返回事件与原片，没有可用代码 | 从一次正式证据读取拿到版本化轨迹模板、该事件的毫秒时长、方向与速度策略，运行代码能复现左右取景及中间位置 |
| 数据、权限与成本 | 历史事件有固定指纹，检索按租户及当前发布版本回源 | 原有载荷序列化和文本索引逐字兼容。失效引用不泄露代码所关联的素材。沿用同一次视觉 Understanding |

# 3. 改造方案与建模

沿用已生效的 `clip` 路由。Understanding 在同一镜头内观察相对固定的背景、画面边缘与主体，写中文运镜描述，给有证据的 SCENE 附上结构化观测。短暂换景、遮罩、独立运动和无法判定的相机运动要区分。Refine 沿用原片时间与证据，可纠正误判。人的可读描述、方向、起止构图和速度进入既有文本检索投影。

创作 Agent 由 `retrieve` 或 `browse_events` 选中事件，`read_evidence` 回到当前有效的原始记录，再返回有版本的、可直接运行的二维镜头代码及参数。观察到的画面事实与由新作品决定的画幅、移动量、默认缓动分别标明。跟随、环绕或混合运动可以留下描述，缺少适用模板时不伪造数值轨迹。代码版本由宿主提供。#50 中跨手法的任意用户代码写入、默认版本管理与评价库另有独立的生命周期，本次交付以素材的运镜描述和代码读取贯通为界。

# 4. 对照实验与结果分析

计划用支持平滑右移的原创建模素材和有地面真值的控制样例检查实际画面。用相同事件走改动前后的模型合同、搜索投影、当前事件回读和 JavaScript 运行入口。分别记录方向、边界、镜头与主体混淆、识别误差以及哪些量来自创作默认值。真实识别和程序合同独立计数。基线与新增代码的结果待实测。

# 5. 试点验证与方案取舍

先在隔离工作树运行领域、提示词、索引与 MCP 测试，再用真实帧检查提示词能否让模型描述镜头并生成正式结果。新数据随正常解析或显式重解析产生，老素材按原版本读取。生产历史库不批量重写。检查现有发布版本及租约校验、代码模板输出稳定性、不同素材方向和模型采样限制。

# 6. 结果验收与闭环

验收对象是“从剪辑素材到下一次编辑可以使用的运镜参考”。需验证真实画面描述、同一事件的检索和来源、代码回放、非镜头运动反例与历史合同。实施期间在同一文档记录命令、失败和剩余的模型质量边界。部署及用户作品的主观效果另行记录。
