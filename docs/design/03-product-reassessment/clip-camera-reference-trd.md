# 1. 问题与现状

剪辑师希望在 Seekino 中找到一段“沿海岸丝滑向右移，小船从右侧入画”的素材，并让创作 Agent 把同一种运镜用在另一幅画上。分支 `feat/clip-camera-reference`，目标 `dev`。PR 创建后回填。依赖已合入的 [上传路由 #82](https://github.com/owariband/Seekino/pull/82) 与 [事件检索 #77](https://github.com/owariband/Seekino/pull/77)，承接 [剪辑参考主设计 #50](https://github.com/owariband/Seekino/pull/50)。

在基线 `2139cbaf`，自动或显式选为 `clip` 的素材会收到记录切镜、构图、字卡与时间范围的提示。普通事件只有自然语言描述和来源时间，显式提交 `camera_ref` 会被 Schema 拒绝。实验中的 `PAN` 标签和灯塔片可执行的 `cameraAt` 尚未连接到正式素材。只追主体容易看反方向，复制角色停帧会把平滑的镜头做成卡顿。

# 2. 影响因素、假设与评价指标

| 指标 | 基线 | 目标与验证条件 |
| --- | --- | --- |
| 可描述和召回 | 构图文字可记录，方向、速度、起终取景随模型发挥 | 对同一段视觉证据，要求说出镜头方向、起终可见内容、运动节奏和判断依据。用静止背景上运动的主体、硬切和证据不足做反例 |
| 可复现 | MCP 返回事件与原片，没有可用代码 | 从一次正式证据读取拿到版本化轨迹模板、该事件的毫秒时长、方向与速度策略，运行代码能复现左右取景及中间位置 |
| 数据、权限与成本 | 历史事件有固定指纹，检索按租户及当前发布版本回源 | 原有载荷序列化和文本索引逐字兼容。失效引用不泄露代码所关联的素材。沿用同一次视觉 Understanding |

# 3. 改造方案与建模

沿用已生效的 `clip` 路由。Understanding 在同一镜头内观察相对固定的背景、画面边缘与主体，写中文运镜描述，给有证据的 SCENE 附上结构化观测。短暂换景、遮罩、独立运动和无法判定的相机运动要区分。Refine 沿用原片时间与证据，可纠正误判。人的可读描述、方向、起止构图和速度进入既有文本检索投影。

创作 Agent 由 `retrieve` 或 `browse_events` 选中事件，`read_evidence` 回到当前有效的原始记录，再返回有版本的、可直接运行的二维镜头代码及参数。观察到的画面事实与由新作品决定的画幅、移动量、默认缓动分别标明。跟随、环绕或混合运动可以留下描述，缺少适用模板时不伪造数值轨迹。代码版本由宿主提供。#50 中跨手法的任意用户代码写入、默认版本管理与评价库另有独立的生命周期，本次交付以素材的运镜描述和代码读取贯通为界。

2026-11-10 实现。宿主在已有采样帧上对齐分布在不同行、列的背景纹理，记录毫秒及以画宽为单位的有符号位移。一次无中断的测量覆盖事件至少八成，且模型也认出横移时，校正左右和可辨别的快慢。若模型把一次横移按画面内容拆成两段以上，各段必须方向相符、首尾相接且覆盖至少一半测量时长，区间内也须没有竞争的运镜观测。此时保留各段的内容描述，把回放绑定到一条覆盖连续测量的 SCENE。证据不足时仅保留已有观测。

已发布片段按同一任务和内容版本读取采样。回放使用 `canvas2d/viewport@1`，将采样位置按原片相对时间插值为连续速度的单调曲线，最多交付 96 个节点。事件边界在同一测量段内时插值，在测量之外时保持最近姿态。静止、垂直移和推拉有二维模板，未测得的横移量、缩放倍率、构图锚点或缓动在回执中标记依据。环绕、跟随、复合、阶梯式或无法判明的运镜可按观察检索，其可执行参考留空。

普通视觉解析也要求把显著的镜头变化直接写进中文场景描述，并在 Refine 保留。自动或显式选为剪辑素材时还有结构化观察。Web 搜索与片段读取 API 的 `allTimeEvents[].cameraDescription` 使用这条观察生成完整的中文运镜描述。普通片段详情按当前播放范围显示相应条目，可同时看到来源时间、起幅、落幅与运动节奏。

# 4. 对照实验与结果分析

四个原创控制样例使用同一 3 fps 采样和 DeepSeek Flash。模型独立答对向右移、固定机位小船和硬切，把向左移说反。多处背景位移纠正了左移，两条横移的行程测得 0.994 个画幅，绘图真值均为 1。模型描述、采样证据和执行结果分别保存在[试点记录](../../report/agent/video_parse_v2/clip-camera-reference-20261110.json)。

对另一条有推入、横移和停留的 10 秒动画，仅输入 30 张帧和正式采样提示。首次 Understanding 把一次横移描述为两个一秒事件。合并后的 3.667–7.667 秒通过同一模型的真实 Refine，绘图真值为 3.800–7.600 秒。在该真值区间的 229 个 60 fps 帧位置上，回放相对原 MP4 解码测量的均方根误差为 3.80 像素，最大误差为 8.96 像素，画宽 1080 像素。该曲线由稀疏观测插值。

# 5. 试点验证与方案取舍

保留同一次视觉 Understanding，方向纠正和回放不增加模型调用。仅靠提示的方向误判，以及把两段画面描述各自套上缓动的问题，均在灯塔或左右对照中观测到。处理每段采样时保留原片时间。将首末观测强行拉伸到整段时，同一灯塔样例的已知区间回放均方根误差为 41.59 像素，保留原时间后为 4.70 像素。自动定位试验单独计数。

同库 SQLite 任务发布、当前版本回源与 MCP 工具读取经过隔离验证。生产的 MySQL、ES 和模型质量需要在各自环境单独验收。普通类型沿用基线模型协议。历史素材在按剪辑策略重新解析后才会新增参考。[验收方法与边界](../../report/agent/video_parse_v2/clip-camera-reference-20261110.md)

# 6. 结果验收与闭环

剪辑 Agent 可以先检索“平滑向右横移”或按源时间浏览，再从命中事件取得画面描述、来源范围与可运行的镜头。灯塔试点验证了“先只看左半幅，再跟随镜头看到右侧小船”，也验证了观察中的画面事件可保留各自时间而由同一条曲线回放。量化验收仅涵盖纹理充分的二维横移。实拍视差、遮挡、飞速甩镜和低采样率仍需真实素材验证。当前交付位于独立功能分支，发布和库内重解析待进行。[工作台 EDIT-CAMERA-01](../../dev/workbench.html)
