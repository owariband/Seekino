# 1. 问题与现状

观看页搜「红温」，MyGO 第 2 集的台词、画面文字和画面描述都没有这个原词。初版普通搜索按相关度排出五处候选，前两处分别描述紫红色眼睛和红色吉他。智能搜索初版纠正了词义，却仍把 18:04 的「茫然不安」列为第 5 处，下一处还倒跳至 11:13。观众需要用梗定位有词义依据的片段，并按播放顺序回看。

本需求作用于有权播放的单个视频，由观看页查找面板发起。开发分支为 `feat/watch-smart-find`，依赖[片内画面查找 PR #120](https://github.com/owariband/Seekino/pull/120) 的文字、画面与定位能力。[开发 PR #125](https://github.com/owariband/Seekino/pull/125) 以上游分支为基线。站点全局搜索、Kino 对话、视频解析、索引及模型配置均沿用各自的现有合同。

# 2. 影响因素、假设与评价指标

| 观察项 | 本地基线 | 验收条件 |
| --- | --- | --- |
| 普通搜索 | 「红温」五处相关画面 | 默认仍显示现有候选，聊天模型调用零次 |
| 智能搜索 | 面板没有扩词 | 界面保留原词并显示纠正词；成功纠正后，台词、画面文字和已开启的画面标注至少匹配一种写法 |
| 导航顺序 | 文字、直接画面和相关画面分组，相关候选按相关度排列 | 所有来源统一按实际跳转毫秒升序，列表、上一处、下一处使用同一顺序 |
| 误解与成本 | 颜色相似能排在情绪前面 | 在同一集记录实际释义与首批结果，区分文字证据与相似候选；普通语句、人物与字面上下文能保持原意 |
| 异常与状态切换 | 现有结果可跳转 | 快速改词、关开关和换集时剔除迟到响应，模型不可用时普通查询可用 |

# 3. 改造方案与建模

面板增加独立的「智能搜索」，每次打开面板默认关闭。打开后，原文先匹配，输入稳定后调用 `POST /api/videos/find-query`，传入 `{tenantId, videoId, query}`。服务复用当前可访问视频的鉴权、模型额度和已配置的默认聊天模型，返回 `{query, synonyms}`。模型将俚语翻成适合检索的短语，保留人名、动作、对象、限定词和否定。普通查询沿用原文。外部模型的输入仅含查找词和解释指令。

浏览器用原词、主释义、少量同义表达查本集时间线。同一条证据只计一次。成功纠正后，只保留这些词在文字或本集画面标注中的匹配，并沿用出镜人物限制。普通搜索、模型未改词以及模型失败时，继续使用现有普通查找规则。当普通查询允许查相关画面时，按相关度选取最多五个互不重叠的候选。

列表合并所有来源后，按显示和跳转使用的毫秒值升序排列。台词和画面文字使用起点，画面使用区间中点。后到候选插入对应时间位置，保留当前选中项。下一处和上一处都沿列表导航，到边界才循环。

# 4. 对照实验与结果分析

本地 Chrome 在 MyGO 第 2 集输入「红温」，等普通结果出现后切换智能搜索。两次使用同一视频和事件索引。

| 该次查询 | 修订后普通搜索 | 智能搜索初版 | 修订后智能搜索 |
| --- | --- | --- | --- |
| 聊天模型调用 | 0 | 1 | 1 |
| 画面语义查询 | 1 次「红温」 | 1 次「生气」 | 0 次 |
| 画面描述直接匹配数 | 0 | 2 | 2，均含「不满」 |
| 补入的相似候选数 | 5 | 5 | 0 |
| 首次实际跳转 | 00:13.600 | 11:02.150 | 11:02.150 |

初版用 DeepSeek Flash 从打开开关至收到释义为 1.38 秒，包含 400 毫秒输入等待。这个数字仅代表初次试点。修订后在同一集输入「红温」，Chrome 逐条读取播放器的实际位置。普通搜索依次为 00:13.600、01:40.000、11:09.120、12:50.540、21:02.499。智能搜索只有 11:02.150、15:41.000 两处。两种模式都验证了向后跳转和首尾循环，关闭智能模式会恢复五个普通候选。[浏览器与查询实测](../../report/server/evidence/watch-smart-find-local-20261112.json)

# 5. 试点验证与方案取舍

默认 Kimi 在首轮请求返回 429。验收在隔离配置中把新对话的默认模型切到 DeepSeek Flash。第一版会保留孤立的梗，也曾将普通描述「显卡温度过高」改写成「显卡过热」。最终版要求模型指出输入中的梗，服务验证该词来自输入，再采用释义。汉字间的空白对模型隐藏，拉丁文单词边界保留。

复验中，「红色吉他」「显卡温度过高」保持原样。「爱音没红温」返回「爱音没生气」，替代表达也保留人名和否定。「社死」解释为「当众出丑」，「紅 溫」解释为「生氣」。普通模式保留弱相关的场景供探索。纠正后的模式依赖现有标注和返回的近义词，可能遗漏使用其他措辞的镜头。

# 6. 结果验收与闭环

前端全量 665 项通过，构建通过。后端和既有 Chrome 观看页测试共 15 项通过。本地 Chrome 已用同一集逐条核对列表与播放器的实际时间，验证前后跳转、首尾循环、由智能切回普通，以及原词输入、画面开关、字幕查找和重新打开面板。生产环境的模型质量、延迟分布及其他剧集仍待验。开发集成依赖片内画面查找先合入 dev。[上游 PR #120](https://github.com/owariband/Seekino/pull/120) · [工作台](../../dev/workbench.html)
