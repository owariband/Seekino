# 1. 问题与现状

观看页搜「红温」，MyGO 第 2 集的台词、画面文字和画面描述都没有这个原词。普通画面搜索仍给出五处语义候选，前两处分别描述紫红色眼睛和红色吉他。希望表达人物生气的观众需要一种能解释网络用语的查找方式，同时仍能选择现有的直接查找。

本需求作用于有权播放的单个视频，由观看页查找面板发起。开发分支为 `feat/watch-smart-find`，依赖[片内画面查找 PR #120](https://github.com/owariband/Seekino/pull/120) 的文字、画面与定位能力。[开发 PR #125](https://github.com/owariband/Seekino/pull/125) 以上游分支为基线。站点全局搜索、Kino 对话、视频解析、索引及模型配置均沿用各自的现有合同。

# 2. 影响因素、假设与评价指标

| 观察项 | 本地基线 | 验收条件 |
| --- | --- | --- |
| 普通搜索 | 「红温」五处相关画面 | 默认仍显示现有候选，聊天模型调用零次 |
| 智能搜索 | 面板没有扩词 | 界面保留原词并显示解释；近义词查台词、画面文字及开启的画面，单次语义查询使用主释义 |
| 误解与成本 | 颜色相似能排在情绪前面 | 在同一集记录实际释义与首批结果，区分文字证据与相似候选；普通语句、人物与字面上下文能保持原意 |
| 异常与状态切换 | 现有结果可跳转 | 快速改词、关开关和换集时剔除迟到响应，模型不可用时普通查询可用 |

# 3. 改造方案与建模

面板增加独立的「智能搜索」，每次打开面板默认关闭。打开后，原文先匹配，输入稳定后调用 `POST /api/videos/find-query`，传入 `{tenantId, videoId, query}`。服务复用当前可访问视频的鉴权、模型额度和已配置的默认聊天模型，返回 `{query, synonyms}`。模型将俚语翻成适合检索的短语，保留人名、动作、对象、限定词和否定。普通查询沿用原文。外部模型的输入仅含查找词和解释指令。

浏览器用原词、主释义、少量同义表达查本集时间线。同一条证据只计一次。「画面」开启时只用主释义发一次语义检索，原有来源标签、时间戳和跳转规则继续适用。模型失败回到普通查找。无需重建索引、更新模型设置或迁移数据。

# 4. 对照实验与结果分析

本地 Chrome 在 MyGO 第 2 集输入「红温」，等普通结果出现后切换智能搜索。两次使用同一视频和事件索引。

| 该次查询 | 普通 | 智能 |
| --- | --- | --- |
| 聊天模型调用 | 0 | 1 |
| 发给画面检索的主词 | 红温 | 生气 |
| 本集画面描述中匹配的结果 | 0 | 2，两处都写到「不满」 |
| 额外的相关画面 | 5 | 5 |
| 首条定位 | 21:02，紫红色眼睛 | 11:02.150，爱音转身。原帧字幕为「態度好差」 |

这次使用 DeepSeek Flash，打开智能开关至收到释义为 1.38 秒，包含 400 毫秒输入等待。原词可立即查找，四个近义词共用一次主词语义查询。时间仅代表本次试点。[浏览器与查询实测](../../report/server/evidence/watch-smart-find-local-20261112.json)

# 5. 试点验证与方案取舍

默认 Kimi 在首轮请求返回 429。验收在隔离配置中把新对话的默认模型切到 DeepSeek Flash。第一版会保留孤立的梗，也曾将普通描述「显卡温度过高」改写成「显卡过热」。最终版要求模型指出输入中的梗，服务验证该词来自输入，再采用释义。汉字间的空白对模型隐藏，拉丁文单词边界保留。

复验中，「红色吉他」「显卡温度过高」保持原样。「爱音没红温」返回「爱音没生气」，替代表达也保留人名和否定。「社死」解释为「当众出丑」，「紅 溫」解释为「生氣」。远端相关画面仍可能只有情绪上的弱关联，面板保留其来源标签。
