# 1. 问题与现状

2026-11-09，分支 `feat/mcp-source-clips`。本改动接在[原片召回 #77](https://github.com/owariband/Seekino/pull/77) 之后，服务于[双召回与剪片主设计 #50](https://github.com/owariband/Seekino/pull/50)。先合 #77，再合本分支。官方 Cloud MCP 的接入与部署由另一需求负责。

编辑能通过 `read_evidence` 回看有来源和时间的命中，但得到的是整集视频地址。《Weekend》试剪要求“挑一张带背景的爱音原帧”；EP04 咬牙特写前的抬手、收拳因此没有进入成片。需求是让编辑自己找到并取得完整表演；人物名可帮助检索，取片无需人物名或分割参数。

# 2. 影响因素与指标

| 观察 | 对照与验收标准 |
| --- | --- |
| 提示与取用的单位 | 基线只有事件、整集 URL 和静帧指令。编辑应能按证据自选原片毫秒区间，跨过事件边界，下载独立 MP4。 |
| 画面与声音 | 按源时间左闭右开。核对首尾、帧数、画面顺序和有声/无声源；局部时间从片头开始。 |
| 服务边界 | Cloud 每次允许正时长且不超过 60,000 ms；60,001 ms 在转码前拒绝。自托管本地不套用该上限。下载时重新检查权限、发布版本与原片时长。 |

# 3. 改造方案

给现有 MCP `read_evidence` 增加可选的 `start_ms`、`end_ms`（成对传入）；返回来源、原片区间和可下载的 `media.clip_url`。不传时间维持已有合同。下载 URL 交付视频字节；MCP JSON 不携带视频本体。引用锁定原视频和证据版本，时间可跨同一视频内的事件。调用方不能传外部视频 URL 或服务器路径。

MCP 指引提醒：肢体或表情变化承载剧情时，先看命中前后，取完整动作；直接用原片、在本地做动态抠像或为了强调一拍而定格，均由编辑判断。Cloud 保留原有媒体阅读权限，限时由服务器执行。本次不改解析、索引和权重，不新增抠像工具。

# 4. 对照验证

使用同一份 EP04 真实源和已留存的命中引用；比较旧调用和指定区间调用，实取 MP4，与原片逐帧核对。隔离测试覆盖时间边界、失效引用、撤销访问以及旧客户端。初稿均待测。

# 5. 试点与取舍

先验收单次取用；按需转码会占用服务端 CPU，临时文件随请求清理。试点不据此推断 Cloud 负载能力或剪片偏好。之后只给新编辑剧本、MCP 与其本地工具，记录它是否自主采用连续动作。

# 6. 结果与闭环

初稿：实现、真实取片和独立剪片验收分别记录；不把 Cloud 模式的本地测试写成公网可用。
