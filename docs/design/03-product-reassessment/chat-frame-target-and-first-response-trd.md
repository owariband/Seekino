# 1. 问题与现状

完整 checkpoint 的 25 次工具尝试有 6 次失败：5 次 UNKNOWN_ITEM、1 次首次检索条件参数校验失败；业务工具完成日志仅记录其中 24 次／5 次错误。T02 两个首次调用同批发出，不能写成看到首次报错后再次犯错。历史和实时工具可见的 Chunk ID 不一定在本轮检索注册表；实时工具的 query 未用于选择时间。T03 明确要求 17:36，实时工具却按播放位置 17:36.558 取帧，视觉摘要还生成了“与用户相符”的对齐判断。区间抽帧取得 17:36.187 等附近位置，最终却声称精确核验。参数失败在 Gateway 中被替换为 `{}` 占位，不能由 checkpoint 认定模型原始参数为空。

本次目标：保留 JEV-only、关闭独立改写器，以最小工具直接解决简单问题；复杂任务才按需计划和委派；对需要取证的请求先给简短目标确认，再继续真实工具及答案；已知视频和时间点时直接取一帧。保持授权、来源版本、媒体毫秒、模型配置、流式持久化、既有工具预算与取消契约。Query 循环有界化、预算放大、推理档位调整、生产部署不在本次实现范围。

# 3. 改造方案与建模

正式流程保持 `JEV分类 → 当前轮模板 → Supervisor最小取证工具 → 按需Query → 接续答案`。简单问答直接回应；单点画面直接取帧；具体线索先细搜、缺上下文才扩搜；多独立或存在明确证据缺口时再委派 Query，不安排固定多 Agent 流水线。已给当前轮处理说明时不重复分类或输出完整计划。独立 rewriter 继续关闭。

短确认由同一次 Supervisor 生成自然输出，例如“我先看第10集17:36这一帧”。它是待执行目标说明，不声称已看过或预告未经核验的结果；之后必须继续调用工具、交付结论或实际失败。已有正文在工具后保留，不重复整篇回答。直接聊天、要求先解释的 mixed 请求和用户长度限制仍须遵守。

单点工具复用 Server 的可信授权和媒体来源校验、Engine 取帧与现有 ToolImageArtifact，不让模型拼路径或选择任意文件。已知当前视频或本次允许范围内的视频与绝对毫秒时刻即可调用，不要求为了注册历史 Chunk ID 先做语义检索。不触发无关 Parse、Refine、索引或持久数据迁移。区间 inspect 保留给候选概览，文案明确均匀中点不保证包含指定点。若未取得实际解码 PTS，返回未知，不把请求时间伪装成实测时间。具体宿主 seam 以窄范围源码核查后补齐。

统一历史证据、实时证据和检索证据的可用范围说明；已有 ID 不能跳过当前授权和版本复核。条件检索 schema 与运行时规则一致；原生通用 task 按既有设计关闭，业务 query_video 保留。删除和本次工具实际参数不符的旧 section／end／overview 指示。改动归属 Agent 的策略、Server 的授权与帧来源、Gateway 的通用 schema／harness 控制，不复制业务策略到 Gateway。

# 5. 试点验证与方案取舍

试点限上述三条原历史，不向生产数据库发回放，不部署。确认必须在真实工具之前且之后继续产生有效结果；单点调用须对准用户时间和授权视频，已知时间不能因旧ID失效转成无关语义检索。若时间／权限／来源护栏失败，保留失败证据并修正；若仅确认FTT变短而有据正文或TT无收益，分别报告，不扩大结论。
