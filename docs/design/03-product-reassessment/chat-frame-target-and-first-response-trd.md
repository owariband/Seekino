# 3. 改造方案与建模

正式流程保持 `JEV分类 → 当前轮模板 → Supervisor最小取证工具 → 按需Query → 接续答案`。简单问答直接回应；单点画面直接取帧；具体线索先细搜、缺上下文才扩搜；多独立或存在明确证据缺口时再委派 Query，不安排固定多 Agent 流水线。已给当前轮处理说明时不重复分类或输出完整计划。独立 rewriter 继续关闭。

短确认由同一次 Supervisor 生成自然输出，例如“我先看第10集17:36这一帧”。它是待执行目标说明，不声称已看过或预告未经核验的结果；之后必须继续调用工具、交付结论或实际失败。已有正文在工具后保留，不重复整篇回答。直接聊天、要求先解释的 mixed 请求和用户长度限制仍须遵守。

单点工具复用 Server 的可信授权和媒体来源校验、Engine 取帧与现有 ToolImageArtifact，不让模型拼路径或选择任意文件。已知当前视频或本次允许范围内的视频与绝对毫秒时刻即可调用，不要求为了注册历史 Chunk ID 先做语义检索。不触发无关 Parse、Refine、索引或持久数据迁移。区间 inspect 保留给候选概览，文案明确均匀中点不保证包含指定点。若未取得实际解码 PTS，返回未知，不把请求时间伪装成实测时间。实际由Server的VideoFrameReader.read_point完成原片授权、来源和Artifact交付，通过bootstrap注入同一reader；AgentRuntime注册get_video_frame，观看单帧路径不加载检索上下文。

统一历史证据、实时证据和检索证据的可用范围说明；已有 ID 不能跳过当前授权和版本复核。条件检索 schema 与运行时规则一致；原生通用 task 按既有设计关闭，业务 query_video 保留。删除和本次工具实际参数不符的旧 section／end／overview 指示。改动归属 Agent 的策略、Server 的授权与帧来源、Gateway 的通用 schema／harness 控制，不复制业务策略到 Gateway。

# 5. 试点验证与方案取舍

单点指定时间已在两组候选中按1056000ms真实取图，原片预检确认1图、跨范围拒绝、Parse任务数不变。收紧提示消除了这组工具错误，但T02仍挑了历史时点且未提前确认，核心通过只有2/3，不能作为业务质量全通过。

最终修正将本轮可信video_id和timestamp_ms就近附在当前用户消息，显式时间仍优先；不做改写或新增调用。原文和RunInputs保持不变。该修正通过完整回归，因模型402未有真实效果结论。采用既有架构和已验证工具修复，任务保留待真实模型验收，不部署生产。Query有界收敛、近满窗和并发另行验证。
