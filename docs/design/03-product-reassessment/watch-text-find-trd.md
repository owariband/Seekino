# 1. 问题与现状

需求是观看页的片内文字查找。分支 `feat/watch-text-find`，目标 `dev`，PR 创建后回填。基于已集成的 [观看页](../../../web/src/features/player/WatchPage.tsx) 和 [Event 时间线](../02-agent-harness/sub-chunk-trd.md)，无待合并的前置需求。

MyGO 第 1 集 05:06.4 的双语字幕出现“高松灯”，22:07.5 的演职员表写作“高松 燈”。两帧已在本地原片核过。播放器已有毫秒跳转，用户却不能在当前一集输入文字并依次跳往每处出现的位置。两帧可见不代表对应解析版本采集了两行文字。

## 2. 影响因素、假设与评价指标

对白的原文和已有译文、画面文字均有原片时间。繁简和字间空白影响字面匹配。当前混合检索的排名和数量限制不能表达“下一处”。验收要求混合写法在查询和材料两侧均能匹配，命中按时间排列，原文保留，跳转误差在播放器允许范围内。仅出现在描述、角色名中的字不算。分清解析未就绪、读取失败和零命中。

## 3. 改造方案与建模

首次打开查找栏时，读取有权观看的本集最新已发布时间线，仅交付对白文本、画面文字及毫秒范围。浏览器用同一套繁转简和空白处理规则生成文本与查询的匹配键，保留原文。一个事件的不同语言可共同命中同一时间点。打开时支持快捷键和播放器按钮，选中、上一处、下一处直接定位当前播放器。复用现有鉴权、播放和正式解析数据，无数据库迁移。假名、别名、对话改写与语义匹配留待后续需求。

## 4. 对照实验与结果分析

| 指标 | 基线 | 验收目标 | 计划 |
| --- | --- | --- | --- |
| 同集对白与画面文字的繁简及空白匹配 | 无片内入口 | 两种来源均命中，反例零条 | 固定时间线与 Web 测试 |
| 选中结果跳转 | 有独立播放器 seek | 实际媒体时间等于命中起点 | 测试播放组件与浏览器 |
| 未授权与陈旧成果 | 现有观看权限与发布版本合同 | 不交付正文 | 定向接口和仓储验证 |

## 5. 试点验证与方案取舍

先在隔离数据上验证两个时间点、双语重复、相邻匹配和其他视频隔离，再用观看页验证键盘导航。对公开站用实际已经存在的文字做冒烟，单独记录素材覆盖缺口。保护原有单键全屏、播放器快退和快进。发现访问范围、时间或部署异常时回退本次代码。
