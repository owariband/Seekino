# 艺术参考与角色素材驱动 SVG／Three.js 动画：论文线索与验证边界

调研日期：2026-10-29。本文是研究笔记，不是已采用的接口设计或实施验收报告。

## 用户要完成的作品

用户原始目标：

> 我在 assetes 里面提供了一堆素材 + mygo 视频，我希望 agent 能够自行融合里面的风格用 svg + threejs 围绕千早爱音做一个 1min 左右的，宣传 anon 特质“象征着爱与勇气”的女孩的特质。这个围绕着分镜、特效、剧本三重的理解。

这里包含两种来源、三类理解和一个制作出口：MyGO 提供角色与剧情依据；艺术、特效、音 MAD／PV 素材提供表现手法；Agent 形成新的分镜、运动和时间安排，最后制作可编辑的 SVG／Three.js 动画。“爱与勇气”是用户指定的创作主题；本轮未核验具体 MyGO 情节，不能把它写成已经从原片确认的角色事实。

**本轮未找到一篇已经验证上述完整闭环的论文，但找到了分别覆盖剪辑手法理解、叙事组织、视频到动画代码，以及动画代码验证的直接相关工作。** 阅读应围绕这些连接处，不必先把生成模型论文通读一遍。

## 六篇核心阅读

| 阅读 | 实际输入与输出 | 对这次作品最有用的部分 | 边界 |
| --- | --- | --- | --- |

| [VEU-Bench](https://arxiv.org/html/2504.17828) | 编辑后视频与问题 → 识别、推理、判断 | 建立分镜与剪辑语言理解的检查项 | Benchmark／专家模型，不生成 SVG 或 Three.js |

| [Motion Vectorization（2023）](https://arxiv.org/html/2309.14642v1) | Motion graphics 栅格视频 → 对象外观、运动和遮挡关系的 SVG 程序，外观可为栅格图 | 参考动画的中间表示应包含对象、运动和遮挡 | 不能视为恢复全部可编辑矢量路径；简化图形适用性不能外推到任意实拍特效 |
| [Animation2Code](https://arxiv.org/html/2606.28593) | Web 动画视频 → 可执行 HTML／CSS／JavaScript | 用实际重渲染检验“理解是否足以指导代码” | 短 Web 动画重建基准，不是成熟的参考风格融合系统 |
| [MoVer](https://arxiv.org/html/2502.13372v1) | 静态 SVG 与运动要求 → 动画程序、时空验证程序和纠错反馈 | 把运动、相对位置和先后关系变成可检查约束 | 不能自动验证艺术感染力、角色主题或复杂 PV 美感 |

### 1. Edit3K：检索应该识别“怎么做”，不只识别“画面有什么”

论文研究六类编辑组件：video effects、animation、transition、filter、sticker、text。数据覆盖 3,094 个组件、618,800 段视频，每段由一种组件施加在不同素材上生成。其学习目标是减轻原始素材外观的干扰，保留组件特征，用于识别、检索和推荐。[论文](https://arxiv.org/abs/2403.16048)

建议读 Fig.1／2、§3.1–3.2，尤其关注相同手法应用于不同内容的样例。对 Seekino 的迁移建议是：即使两个视频中的人物、背景完全不同，也应有机会按相似转场或图形运动被召回。这是候选检索目标，不能直接宣称现有 Event 向量已经做到。

官方提供[代码与数据入口](https://github.com/GX77/Edit3K)。本轮未下载训练或复跑。单组件数据不能证明它能把《Escapism》这类复杂合成自动拆成原始插件、图层和精确参数。

### 2. VEU-Bench：把分镜与剪辑理解变成可以验收的问题

论文提供 10 个编辑维度、19 项任务，区分 recognition、reasoning、judging；涵盖镜头内部属性与跨镜头关系。其目标包含识别景别、运动和转场，以及理解剪辑安排。论文评测 11 个视频模型并训练 Oscars 专家模型，表明通用视频问答能力不能直接替代剪辑理解。[论文 Fig.1、§3.2–3.3、§4.2](https://arxiv.org/html/2504.17828)

对项目的价值主要是验收问题与术语体系：例如同一视觉形状怎样连接前后镜头、运动或速度怎样影响节奏。不能把论文中的分类正确率等同于能还原特效工程，或能为爱音短片生成好看的动画。

建议读 Fig.1／4 和失败样例，先选与现有 assets 有关的维度，不要求每个片段填满所有字段。官方项目与代码入口可从[论文](https://arxiv.org/html/2504.17828)进入；本轮没有部署专家模型。

### 3. CineAgents：角色依据与新作品脚本之间要有组织过程

论文正式题名为 *A Benchmark and Multi-Agent System for Instruction-driven Cinematic Video Compilation*（2026）。CineAgents 通过 script reverse-engineering 构建 shot、event、story、character 的层级记忆，再将创作意图逐步形成 creative blueprint 和 compiled script。[论文 Fig.3、§4.2–4.3](https://arxiv.org/html/2604.10456v1)

我们可借它把“宣传爱与勇气”拆成有素材依据的表达段落，再安排开场、推进和收束。角色说了什么、做了什么属于来源事实；用某种颜色、构图或运动来象征勇气属于目标作品的创作选择，两者需要区分。

这篇验证的是原素材重组与叙事连贯性，不是 SVG／Three.js 生成。论文 Event 是叙事层组织单位，也不能直接等同于项目当前对白、动作等事实 Event。

### 4. Motion Vectorization：参考视频可以还原成对象与运动表示

论文 *Editing Motion Graphics Video via Motion Vectorization and Transformation*（2023）研究从栅格 motion graphics 中恢复对象外观、随时间变化的变换及遮挡关系，再构造可编辑运动的 SVG 程序。对象外观可由 canonical raster images 表达，不能将其概括为恢复了完整的可编辑矢量路径。[论文](https://arxiv.org/html/2309.14642v1)

建议先看方法总图与编辑样例，关注对象对应、运动参数和层级如何保存。[官方仓库](https://github.com/sxzhang25/MotionVectorization-ProgramTransformation)公开了 motion vectorization 与 SVG 导出脚本，Program Transformation 部分仍标为 “Coming soon”；README 提示复杂视频处理可能耗时数小时。本轮未安装复跑。对 Seekino 的启发是提供可供新作品借用的运动结构；本轮没有证明这套方法可以直接拆解 assets 中的实景、粒子、复杂遮挡或多层后期特效。

### 5. Animation2Code：代码跑通和运动做对，是两件事

该工作将参考动画反解为可执行 Web 代码，包含 1,069 个动画与 HTML／CSS／JavaScript 配对样本，时长为 2–8 秒，并把外观相似与时间动态相似分开评测。其结果显示，代码成功执行和静态外观表现较好时，运动重建仍可能很弱。[论文 §2–4](https://arxiv.org/html/2606.28593)

对本项目最有用的是评测方法：必须看重渲染后的运动和顺序，不能只看一张截图或代码是否无报错。它的任务是短 Web 动画重建，用户目标则是多参考风格迁移和约一分钟的新作品，不能直接照搬像素相似作为总目标。

论文还比较了直接视觉反馈、describe-first、caption bridge 和视觉／代码双 critic 的迭代方式，报告双 critic 在两项指标上最好。该对照使用 Qwen3-VL-8B 和三轮修订；附录对各组初始程序是否完全一致的表述存在张力，不据此断言所有中间描述都无效。对项目的推论是：不能预设“先转文字”必然有增益，应保留原视频证据，防止早期描述错误被后续制作固化。[论文 Appendix E／I](https://arxiv.org/html/2606.28593#A5)

建议读 Fig.1、§3、§4.2–4.3、Appendix E／I。[项目页](https://anya-ji.github.io/animation2code-website/)提供数据链接，代码入口本轮仍标为 “Code soon”；不能报告为已完成代码复跑。

### 6. MoVer：把关键动作和时序变成程序可检验的要求

MoVer（SIGGRAPH 2025）用一阶逻辑描述运动的类型、方向、幅度、相对位置和时间关系。系统生成 SVG 动画及验证程序，执行检查后将失败的谓词反馈给 LLM 修正。在其 5,600 个合成提示的评测中，正确动画比例从不迭代的 58.8% 提高至最多 50 次纠错后的 93.6%。这是限定任务的约束满足结果，不是艺术视频质量分数。[论文 §3–4、§6](https://arxiv.org/html/2502.13372v1)

我们可借它检查“主体出现后文字再展开”“装饰元素与主动作同时结束”等要求。规则本身也要核对：论文讨论了错误生成的验证程序可能误报成功，不能让模型自己写验收规则后只看全绿。

建议读 Table 1、Fig.1、§3–4、§7 和 Appendix A。[官方代码](https://github.com/jama1017/MoVer)含 SVG／GSAP 动画生成、数据导出、渲染及验证入口，采用 Apache-2.0；本轮未安装执行。

## Three.js 的直接工程参考：Code Video Model

[Code Video Model 项目页](https://code-video-model.github.io/)与[官方仓库](https://github.com/code-video-model/CodeVideoModel)展示了文本到 Three.js 场景、对象运动、相机与程序化预演的路径。仓库包含视觉 review、时间线／逐帧查看及渲染相关流程。这比把 SVG 研究直接假定可扩展为 Three.js 更接近目标技术栈。

但其完整目标是让代码生成 proxy video，再用 proxy 和 reference image 条件化视频模型，最终得到像素视频。**在 Three.js 渲染处结束、保留可编辑工程，是我们提出的迁移用法，不是论文已验证的完整目标。** CodeVideoBench 只有 22 个案例、8 类应用；本轮核验了主页与仓库，没有读完体积较大的技术报告 PDF，也没有复跑。按技术报告／预印本看待，不标为已确认会议论文。

## 对 Seekino 的候选启发：理解应能支撑下一步制作

以下是结合上述研究提出的设计推导，不是论文共同实现的系统，也不是本项目当前已具备的能力。

```text
MyGO 原片 → 带来源的角色事实与叙事上下文 ─┐
                                         ├→ 目标剧本／分镜／运动与时序计划
艺术参考 → 带来源的画面、图层、运动与衔接 ─┘             ↓
                                                SVG／Three.js 工程
                                                       ↓
                                             渲染 → 视觉与时序核验 → 修改
```

三类信息需要在制作时相互关联：

| 信息 | 需要保留什么 | 对 Agent 的用途 |
| --- | --- | --- |
| 来源事实 | 视频、时间范围、人物／动作／原句、证据与不确定项 | 防止为主题编造爱音经历或台词 |
| 参考手法 | 前后状态、对象与图层关系、轨迹、相机、时序、重复／衔接、可确认的音画关系 | 支持按制作手法检索，并说明借哪段的什么特点 |
| 目标制作计划 | 新作品时间、分镜意图、对象 ID、动作参数、镜头／转场关系、素材映射与检查条件 | 让代码生成和修改有明确对象；不把推测的实现参数冒充原片参数 |

例如，可以设想“爱音主体作为视觉焦点，次要图形围绕她汇聚，随后文字展开”的目标镜头。但这只是示意创作选择；是否采用、参考哪个片段、运动的具体时间和几何参数，都需要后续原片观察与制作实验决定。

一个参考片段可以同时出现文字、图形、相机、转场和声音，不宜被迫塞进唯一类别。先用真实查询和可执行镜头样例验证信息需求，再决定现有 Event 之外需要哪些结构。MCP 负责将来源与这些观察交给制作 Agent；协议连通本身不证明理解质量。

## 最小验证建议

首先从现有短素材中选一个约 5–10 秒的制作片段，固定同一参考集合、输出目标、生成 Agent 和总推理／修改预算；原片访问作为实验变量按组控制，对照三种输入：

1. 原参考视频直接交给 Agent 制作。
2. 只给解析描述，让 Agent 制作。
3. 原视频加带来源的结构化观察与少量关键约束，让 Agent 制作。

分别验收外观／层级、运动／时序、制作意图、局部修改成本及耗时，并单列解析耗时、调用成本及复用次数，避免把预处理代价藏在生成计时之外。若输入 3 没有优于 1，则“增加解析层有助于制作”的假设仍未成立；若输入 2 丢失信息，应保留多模态原片证据。约一分钟作品还要额外验收角色表达、分镜推进、跨镜头风格一致性与音画配合，不能用一个短动画成功代替。

本轮未运行论文模型、未调用付费生成、未制作爱音短片，亦未修改生产解析、检索或 MCP 合同。文中数字均为对应论文或作者项目披露，不是 Seekino 实测。

## 2026-10-29 补充：从旧产品愿景收敛到制作收益

用户补充的旧闭环包括解析、导出、问答、陪看、公共上传社区，以及面向角色 NPC 的小模型或 skill 蒸馏；新闭环聚焦从 MyGO 取得角色依据、从 assets 提炼表现手法，再用 SVG／Three.js 创作约一分钟的爱音宣传片。旧功能的完善不能直接证明新作品更好；这里记录目标区别，不据此宣称所有旧能力无价值，也不推定整个 Web 已获准删除。

本次复核 [CineAgents §4.1–4.3](https://arxiv.org/html/2604.10456v1#S4)：其输入是指令与源视频，借助 shot／event／story／character 记忆形成叙事蓝图与具体镜头脚本，再选取原片镜头并应用编辑工具。可借用“角色事实支持主题叙事”的组织方法；它没有验证从多份风格参考生成 SVG／Three.js 动画。

本次复核 [VEU-Bench §3.2](https://arxiv.org/html/2504.17828#S3.SS2)：它覆盖画面内、镜头内与镜头间的十个编辑维度，并区分识别、解释变化与判断叙事作用。可借用其问题来检查参考片的构图、运动、切镜和转场理解；其任务是理解评测，不输出制作代码，也不能保证美感。

建议首先固定一个 5–10 秒目标镜头，比较“原参考直接交给 Coding Agent”和“相同原参考加 Seekino 的结构化观察”，控制模型、素材、生成与修订预算，并计入解析成本。检查运动／层次／时序、参考手法是否迁移成功、角色表达与修改成本。**Seekino 的理解层能否比直接交给 Coding Agent 带来增益，仍是未验证假设。**短镜头成功后才扩到多镜头叙事与一分钟连续作品；本次没有执行该实验，不承诺完成时限。

同日后续用户明确：2026-10-30 面试需保留旧的解析、导出、问答与陪看演示，其他工作也依赖这些能力；面试前停止进一步裁剪，先前 NPC/ACP 小范围删除已恢复。新创作方向继续作为研究，不构成退役旧产品的指令。恢复范围与验证见 [devlog](../dev/devlog.md#devlog-interview-preserve-20261029)。
